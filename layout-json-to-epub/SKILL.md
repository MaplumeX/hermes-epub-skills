# layout.json → 干净 Markdown/EPUB

## 触发条件
用户发送 layout.json 文档（保存在 ~/.hermes/cache/documents/doc_*_layout.json），要求"提取全文并整理为干净的 Markdown/EPUB，整理好目录、脚注、引用"。

## 开工前读什么（固定顺序）

1. **本技能 SKILL.md** + 按书的形态挑 **一份** `references/*-case.md`（形态判定看各「变体」标题下的触发条件）。
2. **`web-to-epub` 技能的 `references/epub-internal-structure.md`** —— 跨管线通用的 EPUB 格式规范（拆章、双向脚注写法、content.opf/nav、EPUB2 vs EPUB3）。本技能只管内容抽取与排版，格式层疑问一律回查那份。
3. **`scripts/` 下现有的诊断/校验脚本**（align / check_* / validate_epub），不要重写。
4. **按需才加载**：要从原扫描页读上标 → `ocr-and-documents`、`pdf`（pdftoppm/qpdf）；书源不是 layout.json 而是网页 → 整体换成 `web-to-epub`。

**同一本书的新版本只读旧 case 的「差异清单」，不复用旧脚本的阈值**（如曼昆 11e vs 10e 的五处致命差异）。

**回答「你会读什么」这类元问题时**：先给结论（主技能一个 + 必读交叉引用一份），再列按需项；不要展开到 pages.json/book.md 等中间产物的细节——用户追问才展开。

## 数据格式（layout.json）
- 顶层 `pdf_info`：页列表（每页一个 dict）
- 每页 `preproc_blocks`：正文块（type: text/title）；块文本 = 各 line 的 span content 用空格 join
- 每页 `discarded_blocks`：噪声块（type: header 页眉 / page_number 页码 / footer 出版社页脚 / page_footnote 脚注文本）
- 脚注标记：正文内嵌 ①②③（圈码）、`*`、`**`；脚注文本块以同样标记开头
- 页码边注 `[11]` `[44]` 内嵌正文流 —— 用户明确要求去掉

## 变体：章末注释（prose 类书籍，无 § 结构）
- 触发：正文标记为 `inline_equation` span（`^{N}` 每章从 1 重新编号 / `^{*}` 译注），注释集中在书末"注释"区
- 注释块：ref_text 为主，**部分误分类为 text**——注释区页区间内 `re.match(r'^\d+\s', t)` 的 ref_text 和 text 都算注释
- 章节边界 = title 块（章名）；**每章注释起始页页首块是上一章注释续文**（title 之前，归上一章）
- 译注 `*` 对应 discarded_blocks 的 page_footnote（页脚译注），与章末注释是两套体系，分开处理
- **跨文件续章**：正文分多个 layout.json 时，续章页区间（如 P2 p0-14 → 第5章、P3 p0-6 → 第9章）须在 chapter_of() 特判，不能只靠页区间
- **译注配对（页脚 * ↔ 正文 * 标记）**：
  - 页脚续行合并：无 `*` 开头的条目并入前一条；正则用 `^\*+` 而非 `^\*+\s`（`**奥尼尔` 星号后无空格案例）
  - 优先按星号数精确匹配（OCR 漏识别个别标记会错位，如 `^{**}` 漏识别导致圣餐注释错配）
  - 标题带 `*`（如 `从无规定的思想到有规定的思想*`）→ 该页页脚注释是标题译注，须先于 orphan 收集处理
  - **marks 元组必须携带来源页 (tag, pi)**：跨页段落拼接后块的 page 属性是前块页，译注配对会错页
- **诊断**：每章正文标记数 vs 注释条目数逐章比对（int 比较，勿 str vs int），找出 OCR 漏识别的标记——**先尝试修复，不要默认"忠实保留"**（用户明确要求用英文原文解决，见下节"OCR 标记缺陷修复"）
- 引用格式 `[^chN-M]`（章-序号），定义按章分组
- 案例：references/houlgate-introduction-case.md

## 变体：逐节讲解+注释（圈码脚注，每节重新编号）
- 触发：title 块为"第N节"（非 § 结构），每节 = 讲解正文（可跨页多段）+ "注释：" + 圈码①②③条目；圈码**每节从①重新编号**（书末附录除外，见下）
- 案例：张世英《黑格尔〈小逻辑〉绎注》（references/zhang-shiying-yizhu-case.md）
- **节标题可能是 text 类型**（第84节案例），判定不能只看 block type，须正则 + 行长校验（`^第\s*\d+节$` 且 len<24）
- **裸圈码 = 丢失上标**：正文里未包 `^{}` 的裸 ① 等字符是 OCR 没识别出上标包裹的注释标记（如 "……浪漫主义哲学家的哲学。⑤耶柯比主张……"），必须计入正文标记数——只数 `^{X}` 会严重低估（诊断脚本 scripts/align_marks_notes.py）
- **注释两套体系混用**：节末注释区（preproc text）与页脚注释（discarded page_footnote）可能并存——第48节案例：注释①②③在页脚 discarded、注释区只有④；诊断时页脚注释也要归入当前节
- **附录页脚注释每页从①重新编号**（第二套文件 P2 p190 起 + P3 全篇实测：p190 ①-④、p191 ①-⑥、p192 ①-②、p193 ①-⑥、p194 ①-⑤、p195 ①-③、p196 ①-④、p197 ①-⑤、p198 ①-③、p199 ①-②、P3 p0 ①-②、p1 ①-③、p2 ①-⑧、p3 ①-②、p4 ①-④、p5 ①-④、p6 ①、p7 ①-②）。正文标记须带页码前缀 `[[MARK:page-N]]`（如 `[[MARK:371-1]]`）才能与注释唯一配对；注释条目按 (页码, 文本) 元组收集、输出加 `[页码]` 前缀。**不能按"每节从①开始"或"跨页连续"对齐**（第一套文件旧分析曾误判为连续编号，第二套文件证实是每页重编号）
- **OCR 圈码错读变体**：`^{42}` `^{[1]}` `^{j}` `^{(2)}` `^{30}` `^{33}` `^{14}` 等均为圈码 ①-⑱ 被错读；注释条目开头也会错读（①→"中"、③→"3"）
- 诊断：逐节"正文标记数（`^{}` 上标 + 裸圈码）vs 注释条目数"对比，缺口≈OCR 丢失的标记（本案例 243 节中 141 节不匹配、缺口约 300 处）
- 流构建注意：**页眉去重**——章名页眉会以 title 块重复出现（"第三篇\n概念论" 多行页眉、正文句以章名开头如"第一版序言接着谈到……"），需 seen_chapters 去重 + 精确匹配章名而非前缀
- **页眉/页脚噪声按 y 坐标过滤**（第二套文件实测）：text 类型 + y>640（页面高 796）+ 精确匹配章节名（可带页码后缀，如"第二版序言7"）即页眉噪声，须在 is_helper() 里按 `y>640 and HEADER_FOOTER_RE.match(t)` 过滤——**否则页眉会混入注释区成为伪注释条目**（"第一版序言"混进第一版序言注释①的续行）。注意：y>640 的短块不全是噪声（第113节标题 y=651、注释条目 y=641-712 都是正文），所以必须"精确匹配章节名"而非"y>640 即丢"
- **text 类型子标题识别需前瞻**：`B. 量(Die Quantität)`、`(b) 定量(Quantum)`、`(c) 程度(Grad)`、`(b) 实存(Die Existenz)` 等子标题是 text 类型（非 title）。判定：text + len<40 + 无正文标点 `[,，。;；:：]` + **下一块（按 y 排序）是节标题或 title 类型子标题**。extract.py 必须保留每块 y 坐标（index 字段在 extract 时丢失，前瞻只能按 y 比较）
- **注释区内的子标题**：`(b) 定量`、`(b) 实存` 出现在"注释："区之后（页末），会被注释续行逻辑吞并成上一条注释的尾巴。修复：in_notes 分支里先判子标题（text + len<40 + 无标点 + 下一块是节标题）→ flush 当前节、in_notes=False、按层级 start_chapter
- **章节级注释收集（无节结构的章）**：第一/二/三版序言等章节有独立"注释："区（正文标记 `^{①}` 等上标 + 注释条目）。需要 cur_chapter_notes 收集器：遇到"注释："且 cur_sec 为 None 时初始化，条目按圈码/数字开头分新条目、否则续行；**start_chapter() 切换章节前先 flush 上一章的注释区**（否则只输出最后一章的注释）
- **章节标题检查必须在 helper 过滤之前**：`导言`、`逻辑学概念的初步规定` 等章节名同时出现在 HELPER_RE 噪声模式里（`导言\s*$`），若先过 helper 过滤会误杀章节标题——顺序：章节标题匹配 → helper 过滤 → 其余
- **交叉引用不能转标记（第二套文件实测）**：正文里的"注①""节注⑤""上节注⑤"等交叉引用不是注释标记，norm_marks 必须排除——检查标记前 3 字符 `re.search(r'注$|节注$', pre)` 则跳过（第120节"可联系上节注⑤所引《大逻辑》的话"曾被误转成 `[[MARK:5]]`，导致该节多出 2 个假标记）。**注意 re.sub 回调里用原始文本 orig 取 pre，不能用已被替换的 text（位置偏移）**
- **注释续行判定：数字开头是续行不是新条目**：注释条目跨页续行常以数字开头（如"33、34、35页):"惟有当思想……"是注释①的续行），若把 `^\d` 当新条目会多计。正确规则：**只认圈码开头（含 OCR 错读"中"=①）为新条目，其余全部并入前一条**。旧技能"注释条目开头错读（①→"中"、③→"3"）"的表述要修正——"3"开头的行是续行而非错读的新条目
- **特殊子标题（title 类型短行无标点）**：`※ ※ ※`、`直接知识或直观知识` 是 title 类型但不匹配 A./B./C.、(a)(b)(c) 等标准模式。规则：title + len<20 + 无 `[。！？，、：]` + 非"注释"开头 + 不匹配标准子标题模式 + 不在简称表区域（P1 p5-7 的书名 title 块）→ 输出 `###`。**注意 `A. 思想对客观性的第一态度;形而上学` 只有 18 字符，若此规则不排除标准模式会被降级为 ###**
- **篇名德文副标题**：`(Die Lehre vom Sein/Wesen/Begriff)` 是 title 类型，直接 emit 为普通段落（不设标题层级），否则会污染 TOC
- **跨文件诊断脚本必须用 (file, pi) 定位**：P1/P2/P3 的 pi 是各自文件内索引，跨文件比较会冲突（第112节曾混入 P1 p10 第一版序言的注释）。sections 元组带 file，collect 时按 `(f, pi)` 元组比较区间
- **修复表 fixes.json 模式**：OCR 错读上标（`^{2}`→`^{②}`、`^{[1]}`→`^{②}`、`^{(1)}`→`^{①}`、`^{®}`→`^{⑧}`、`^{③}`→`^{④}`、`^{5}`→`^{⑥}`）写入 fixes.json（`{节名: [{old, new}]}`），build.py 的 apply_fixes 在 norm_marks 之前应用——防重建回归，且修复可审计
- **fixes.json 键与目标形式（第二套实测）**：正文修复键 `"第N节"`，注释区修复键 `"第N节注释"`（build.py 两处分别 apply：正文在 norm_marks 前、注释在 flush 时）。
- **apply_fixes 覆盖范围易漏（第三套实测）**：章节级正文分支（cur_sec 为 None 的 `# 章节` 正文）与附录正文分支都必须 apply_fixes——键分别用**章节标题**（如 `"第二版序言"`、`"第三版序言"`）和 `"附录"`。漏加则序言/附录的 fix 静默失效（第二版序言 ⑦⑫⑬ 落点最初全没生效；附录 p370 注释②落点 `[[MARK:370-2]]` 靠 `附录` 键注入）。
- **fix 的 old 必须是该文本流 apply_fixes 执行点上的实际形式**：正文分支在 norm_marks 之前 → old 用原始 `^{①}`/裸文本；个别路径（第121节）在 norm 后 → old 用 `[[MARK:N]]`。fix 不命中时 showsec.py 查证并用另一形式重试；被漏过的错号最终由严格递增序列校验 + 重编号兜底。**fix 目标可能是已归一化的 `[[MARK:N]]` 形式**：部分块先过 norm_marks 后过 apply_fixes（build.py 存在两条路径），此时 `^{[1]}` 等原始形式已不存在，fix 不命中（第121节案例：`"…客观标准”  ^{[1]}"` 无效，`"…客观标准”  [[MARK:2]]"` 才生效）。**锚点必须匹配 book.md 实际文本**（OCR 变体如"也不同于脱离特殊性和个体性的抽象普遍性"与印象中的"…和抽象普遍性"不同）——fix 应用后用 showsec.py 查证，不能只看 exit code
- **批量写 fixes.json 用 Python json dump**（execute_code 内 load→改→dump，原子且避免 patch 模糊匹配静默失败）；改后 `json.dumps(f['第N节'])` 打印确认实际落盘内容
- **逐节语义配对修复流程（收尾阶段，本案例 213→0 不匹配）**：
  1. 诊断：align.py 输出不匹配节；`showsec.py 第N节`（book.md 正文标记序列+上下文 vs 注释条目）或 `showraw.py 第N节`（layout 原始上标+注释）
  2. diff=-1 节（注释多一条）＝某注释无落点：按注释内容语义（人名引用：费舍/莱布尼茨/康德/斯宾诺莎；主题关键词："充足理由律"、"形式的真理"、"内在目的"）在正文找对应句插 `^{N}`
  3. **OCR 错读序列整体重排**（第24节案例：⑤⑩⑪⑫⑬⑭⑮⑯⑱ 全被读成 ①-③）：不要逐条修，按注释内容 ↔ 正文短语语义批量重写整个序列（每条 fix 用带引号的独特短语作锚点）
  4. 注释条目被并入前一条（第50节案例：⑤"耶柯比《关于斯宾诺莎学说的书信》"被并入④）→ 在 `"第N节注释"` 键里用 `\n⑤ ` 插入拆分
  5. 重复标记＝OCR 重复错读（第81节"割裂开来。^{①}"与第1段重复）→ 直接删除而非改号
  6. 最终指标：`align.py` 输出 `mismatch: 0 / 243`
  7. **count 对齐 ≠ 编号正确——严格递增序列校验（第三套实测）**：锚点生成时发现 id 冲突才暴露"数量对但编号错"（正文序列 `1,2,3,1,5`、`8,3,10`、`1,3,3,4` 等 37 处"缺 N 补 1"型 OCR 错读，注释编号同步错）。校验：逐区域（节/章/附录每页）收集正文标记序列与注释圈码序列，检查 `marks == list(range(1, len+1))` 且 `marks == notes`。**修复：按出现顺序统一重编号**（正文第 k 个标记→k、注释第 k 条→k，计数器独立；附录按页重置且保留页码前缀 `[[MARK:pg-N]]`；章节/节正文与注释各用一个计数器）——一次清 37 处，比逐节写 fix 高效得多。例外：语义配对验证过的顺序颠倒（第146节 `5,6,4` 对应"萌芽⑤→潜在⑥→实在④"）必须 SKIP 保留，重排会破坏语义锚点。重编号后 mdlinks 的 id 唯一性检查（`Counter` 查重复 id + href 无目标）是最终把关
- **跨页注释区无"注释："标题（第二套实测）**：注释区跨页续页时，续页首块可能直接是注释条目（第155节案例：p77 首块 `①《小逻辑》，第319页。` 被当正文输出为 `[[MARK:1]]《小逻辑》…` 行）。修复规则：**正文块以圈码开头且 len<80（未在注释区）→ 归入当前节 notes**；cur_sec 为 None 时归 cur_chapter_notes（注意判空顺序防 NoneType 报错）
- **跨页/跨文件断行必须合并（第三套实测，全书 100+ 处）**：layout.json 每页块独立，句子在页末截断、下一页续接是常态（"写成的。由于"+"作者水平有限"；P2 尾"Die setzende"+P3 首"Reflexion), 是指"跨文件；P3 p0 尾"规"+p1 首"定，达到"）。build.py 流构建默认不合并。**必须在 pages.json 层面合并**（页边界已知），**不能在 book.md 层面做后处理**——book.md 无法区分"页边界断行"与"页内正常分段"会误合并，且单遍遍历不做链式合并（前一行被合并后仍以非终止标点结尾，下一行被跳过，如"…纯粹的反思和规定的"+"反思的统一"）。合并规则：页末块以非终止标点结尾（TERMINAL 正则，先剥 `[[MARK:...]]`/圈码再判）+ 下一页首块是纯续文（单行、非结构元素）→ 合并；结构元素（章节/节标题、子标题、注释条目、圈码开头、`[页码]` 条目、※ ※ ※、注释：、德文副标题、页眉噪声）绝不合并。跨文件边界同样处理。脚本：scripts/merge_page_breaks.py。**合并 5 大陷阱（第三套实测，逐一踩过）**：
  - **① 合并后保留下一页首块的原始 y**：`first_b['y'] = last_b['y']` 会把正文块 y 改成上一页底部 y，破坏该页按 y 排序——正文被排到注释区之后，`in_notes` 状态机错乱，整节注释区崩溃（第25节 113 条注释被吞，align 报 `body marks=0, note entries=113`）。合并只改 text，y 不动。
  - **② TERMINAL 正则必须含全角括号**：字符类只写半角 `)` 时，以全角"页）"结尾的注释条目被误判为"未结束"，与下一页错误合并（第三版序言注④+目录页）；正则写 `[。！？….!?]["」』”’）)\]]*$`。
  - **③ 拆行页脚噪声**："导\n言\n23"被 OCR 拆成三行，逐行匹配章节名失败 → 被当正文块与下一页首块合并（第17节注③被"导言23"污染）。修复：y≥600 的块先去空白拼接（`re.sub(r'\s','',t)`）再匹配 HEADER_FOOTER_RE，整块命中即删。
  - **④ pass1 页脚噪声清理只限 y≥600**：对全页清理会误删真正的章节标题（y<600 的"导言"等 title 块、目录页内容，曾误删 246 块）。y<600 的块一律不动。
  - **⑤ 附录区（P2 pi≥190、P3）页末块含上标/圈码则跳过合并**：附录页脚注释每页独立编号，跨页合并会把上一页正文（含其注释上标）并入下一页块，标记页归属错乱（check_appendix 报 375/376/377 错位，marks 6 vs notes 4）。**合并后必须重跑全部校验**：align.py（节级）+ check_appendix（附录每页）+ check_chapters（章节级）——只跑 align 就进 EPUB 会漏掉附录错位。
  - 另外：P1 封面/目录页（pi≤1、27-29）不参与合并（与 build.py 的跳过规则一致）。
- **块内嵌页脚噪声（第三套实测）**：OCR 可能把页脚噪声合并进正文块内部（P1 p166 y=689 块内嵌"存在论"行，is_helper 只匹配整块所以漏网；P1 p100 y=608 孤立"逻辑学概念的初步规定71"）。修复：y>635 的块按 `\n` 拆行，删除匹配 HEADER_FOOTER_RE 的行；**HEADER_FOOTER_RE 须含 存在论/本质论/概念论**（不只第X篇），否则"存在论"孤立行混入正文。build.py 输出后加 post-process 删孤立页眉行（`HEADER_FOOTER_RE.match(s) and not s.startswith('#')`）
- **诊断脚本从 book.md 统计（align.py v3）**：build 归一化标记后，从 book.md 逐节统计 `[[MARK:...]]` 数 vs 注释条目数（`^[圈码]` 开头），比从 pages.json 统计更准（已含全部归一化）。批量报告脚本（batch_report.py 模式）：输出每节正文标记序列（含上下文）+ 注释条目开头，快速定位 OCR 错读——正文标记序列与注释编号序列对照，错位处即错读处（如第48节 `^{③}` 重复出现、第50节序列 1,3,4,6,7,8,3 明显错位）
- **用户重新上传的文件 md5 可能全变**：第二套文件（doc_756a5d6126cc / doc_342945bdff38 / doc_e9818afeca4e）与旧案例文件 md5 全不同、P3 页数也不同（10→8 页）——必须重新探索、重新 extract，不能复用旧 pages.json；旧参考文件里的源文件名已过时

## OCR 标记缺陷修复（对照英文原文，用户要求）
- **用户偏好**：缺失注释标记/星号数错误**必须尝试用英文原文修复**，不要默认"源数据缺陷，忠实保留"（本会话用户主动问"你有办法根据英文原文来解决吗"）
- **第一步：扫描"被 OCR 识别成普通文本"的上标**——很多"缺失"标记其实就在正文里，只是没被识别为上标：
  - 正则 `([。！？”’）\]》])(\d{1,3})(?=[\u4e00-\u9fffA-Za-z])` 全书扫描（如 "27因此"、"5因此"、"9这样的"）
  - 变体：`^{[41]}` 是标记 141 被方括号包裹（`^{[N]}` → `[[MARK:N]]`）
  - 变体：**Unicode 上标字符** `¹²³⁴⁵⁶⁷⁸⁹⁰` 也是 OCR 变体（第8章 1-3 案例：`¹`→`[[MARK:1]]`）——全书扫描 `[¹²³⁴⁵⁶⁷⁸⁹⁰]`
  - 变体：**纯文本星号串**（如 "修拉 *****"、"比亚兹利 *****" 星号未转成标记）——扫描 `[\u4e00-\u9fff]\s*\*{2,}` 上下文核对
  - **扫描技巧：先屏蔽标记再找残留**——`re.sub(r'\[\[MARK:[^\]]+\]\]', '', t)` 把已转标记的文本挖掉，再正则扫 `\*{1,6}` 和 `\^\{\w+\}`，剩下的都是真残留（第9章"马奈 **""杜乔 ***""乔托 ****"案例、第10章 `^{*86}` 案例）；`^\{...\}` 数学公式（m/s²、t²）不是注释标记，保留
- **第二步：获取英文原文**（archive.org 需登录 401，用 libgen）：
  - libgen.li 搜索 → edition.php?id=... → 页面含 IPFS 链接和 `get.php?md5=...`（需先访问 get.php 拿 `&key=...` 再下载）
  - **DJVU 版文本层可能保留上标**（本案例第1-4章有、第5-10章无）：`apt-get install djvulibre-bin` 后 `djvutxt en.djvu en.txt`
  - PDF 版（pymupdf 提取）上标通常丢失，仅作语义参考
  - PEP 668 环境：`python3 -m venv .venv && .venv/bin/pip install pymupdf`
- **第三步：英文标记定位**：DJVU 文本中上标模式 `([.!?\"'\)\]])(\d{1,3})(?=[\sA-Za-z])` 或 `([a-z])(\d{1,3})(?=[\sA-Za-z])`（如 `relationship.1`、`vocabulary*.14`）→ 提取标记前 ~250 字符英文上下文
- **第四步：中文定位插入**：英文上下文 → 找中文译文对应句子（人名/引文/关键词，如 "commensurating vocabulary"→"通约的词汇表"）→ 在句末插入 `[[MARK:N]]` 并追加到 marks 列表
- **插入后必须验证标记顺序**：批量插入后重扫每块 `[[MARK:...]]` 出现顺序，确认与编号递增一致——本会话第10章 6/7 曾插到标记5 前面、第7章 3/4 曾插进引文内部（锚点字符串在文本中出现多次或锚点本身含引号时易错位）。修正方法：先 `replace` 撤销错误插入，再按正确锚点重插
- **最终验证（两套体系分别核对）**：
  - 数字注释：`正文标记集合 == 注释条目编号集合`（逐章，int 比较）
  - 星号译注：正文 `[[MARK:*+]]` 集合 == 译注文本开头 `^\*+` 集合（按星号数）
  - 全部对齐才算修复完成；残留的纯文本星号（如 "比亚兹利 *****"）也要转成标记
- **星号配对必须按数量核对，不能只比集合**（第7章案例：正文只有 1 个 `*` 标记、译注有 2 条 `*`——集合相等但数量不符，差 1 条译注无对应正文）。核对脚本统计每种星号数的出现次数：`正文计数[k] == 译注计数[k]`，逐 k 比较
- **`^{*N}` 是合体标记**：OCR 把星号译注和数字注释合成一个 span（`^{*86}` = 好撒玛利亚人星号译注 + 数字注释86）。修复时拆成 `[[MARK:*]][[MARK:86]]` 两个标记，**不能只转数字丢星号**（本会话曾把 `^{*86}` 只转成 `[[MARK:86]]` 导致第10章星号又缺 1 个）
- **discarded_blocks 的 header/footer 类型也可能含正文**（两案例）：
  - 第10章：正文引文在"以色"处截断，续句"列人双足未湿就过了红海…加农炮差不多"被误分类为 discarded header
  - 第7章：正文首句"黑格尔的生命概念是先天的。*"整句在 discarded footer（`discarded_blocks footer` 类型）——footer 通常被当出版社页脚丢弃，但**页脚内容可以是正文引文或译文首句**
  - 正文引文突然截断（如 "...以色"）时，用英文原文关键词（Red Sea / Israel / trumpets / Jericho）搜索**全部块类型**（para/preproc/discarded）确认内容去向，再从丢弃块中补回正文
- **EPUB 生成后核对"正文星号链接数 vs 译注条数"**：渲染后统计每章 `href="#chN-tr"` 链接数 == 该章译注条数（本会话 70 条译注 vs 66 链接即漏链接信号）；链接数少于译注数的章节就是正文星号缺失/错位所在
- **DJVU 文本层只覆盖部分章节时的替代方案**（本会话：DJVU 仅前 4 章有文本层，第5-10章 PDF 上标丢失）：
  - 方法：**相邻已知标记夹逼**——先列出缺失标记的相邻标记 N-1/N+1 在中文中的位置（上下文），再从 PDF 文本流中取两标记之间的英文段落，缺失标记必在该区间内
  - 批量表驱动：`(章, 标记, 英文锚点词, 中文锚点词)` 列表逐个定位；英文锚点选引文原文（如 "ex opera operato"、"abstractions from the true life"）或人名（Winfield/Derrida），中文锚点选对应译文片段
  - 页码区域切分：`text.find('Chapter Title', body_start)` 定位章节边界（第 8 章标题用 "Freedom, Rights and Civility" 而非 "From Hegel to Hitler"——后者是第一节标题）
  - 上标缺失但正文里可能残留 `¹²³` Unicode 上标字符或 `*` 串——第 8 章 1-3 就是 `¹ ² ³` 被 OCR 成 Unicode 上标字符的案例
- **章节边界**：英文章节标题在正文中首次出现（`text.find(kw, body_start)`，body_start 是目录后第一个标题位置；勿从 0 找会命中目录）
- **星号数错误**（修拉 6 星、圣餐 `**`）：从页脚注释顺序 + 星号数精确匹配推断，无需英文原文
- 修复后重新跑 build.py 验证：缺失标记数应大幅下降

## 变体：教科书（MathML 公式 + HTML 表格 + 页面圈码脚注 + 缺失插图）
- 触发：`interline_equation` 数量大（数百），表格的 span 里有 `html`，正文有圈码①脚注（每页重编号），image/chart 块只有 `image_path` 文件名
- 要点：`\tag{}` 用 `\qquad\text{(X)}` 保公式号；`\begin{array}{r l}` 列格式的空格必须去掉（texmath 报 `unexpected "l"`）；表格是 raw HTML 所以单元格内公式要预转 MathML；脚注用 markdown `[^id]` 让 pandoc 生成双向跳转；插图无数据→`〔图〕`占位；双栏页显式页区间而不要自动判定；**图题/图释必须从 image/chart 块的 `image_caption`/`image_footnote` 子块取（正文块里通常没有），不能只扫正文短行；`chart` 块的子块类型是 `chart_caption`/`chart_footnote`——只收 `image_*` 会静默丢掉全部图表题（曼昆11e 实测丢 132 条，症状就是「有些图没有标题」）**；图题一律排在**图后**、全书统一为 `**图X-Y 标题**`（`**bold**`/`*italic*`/纯文本三种格式并存、图题在图前、整段正文被当图题加粗，是同一类投诉的四种表现）；**图题↔图片的配对比位置/格式更容易错，而且用户看得出来**：
  - 「往前找 N 块内的图」会把图题搬过界（相邻两图只隔一段图注时，上图图题会落到下图后面）→ 只允许「图题紧跟图」或「中间只夹**本图号**的图注」（中间文字提到别的图号就停）；
  - 删空白误识图后，它的图题必须**挂起**贴到下一张真图后面（就地输出会跑到图前）；输出顺序固定：图 → 面板标签 → 本图图题 → 挂起图题 → 本图图注 → 挂起图注；
  - 面板标签归属靠**坐标**（自带标签优先；数量相符但分配可疑时按字母序配 `(y, x0)` 序），不靠字符串排序——加粗后 `t[2]` 恒为 `(`，按下标排序静默失效；
  - 验收不要数「图后紧跟不是图题」的图片数（多面板图组天然如此，会出假异常）；改数**图组**，并逐章校验图号 `1..N` 无缺口、单调递增，再**抽样把图交给视觉模型读内容与图题比对**（这是唯一能抓出「面板标签张冠李戴」的办法）。
- **插图补齐路径**：layout.json 只给哈希文件名，图在**OCR 产出目录**里（本体不在这台机器上）；先把全部 image/chart 块的 `(tag,pi,bbox,src,path)` 导出成 `figures.json` + 把唯一文件名列成清单发给用户，用户把 jpg 放进 `images/` 后 build 自动把 `〔图〕` 换成真图（`os.path.exists` 判定：存在→`![](images/<hash>.jpg)` + 斜体图题，缺失→占位）。**图题挂靠**（`^图\s*[A-Za-z]?\d+`、短、无句末标点）先归到同页最近的 fig 块再渲染
- **用户发大 zip 必先过 20 MB 上传上限**：分卷 `zip -s 19m -r 1.zip <目录>` / 给 http 直链 / 先压小——不要默默等文件到达
- **分卷 zip 用 `7z x`，不要 `cat` 合并后 unzip**（曼昆图片包实测）：用户常发 `images.z01..z04 + images.zip`。`cat *.z0* images.zip > all.zip` 后 `unzip` 报 `20971520 extra bytes at beginning`、`bad zipfile offset`、`invalid zip file with overlapped components (possible zip bomb)`——分卷的中央目录偏移按卷内位置算，拼接后全部错位。正确做法：把分卷放同一目录、**保留原卷名**，`7z x -y -o<out> images.zip`（7z 自动按 `images.z01..z04` 补齐卷，实测 5 卷 634 图全解，`Everything is Ok`）
- **压图用 ffmpeg（mogrify 不一定有，PIL 也可能没装）**：逐张 `ffmpeg -loglevel error -y -i f -vf "scale='min(900,iw)':-2" -q:v 6 out`。两个坑：① **输出文件名必须带 `.jpg` 后缀**（写 `f + '.tmp'` 会报 `Unable to find a suitable output format`，改成 `f + '.tmp.jpg'` 再 `os.replace`）；② 只压「book.md 里实际引用到的图」（正则 `!\[\]\(images/([^)]+)\)` 取集合），未引用的封面/装饰条不必进 EPUB。实测 575 张、900 px 宽、q:v 6 → 25 MB 降到 9.9 MB，成品 EPUB 10.1 MB（Telegram 20 MB 内）
- 校验：scripts/validate_epub.py（XML、链接、文件内锚点、重复 id、脚注双向计数、MathML/表格统计、封面、nav）+ `java -jar epubcheck.jar`
- **行内公式 span 必须转 `$...$`（曼昆案例教训）**：text 块里的 `inline_equation` span 直接取 content 会留下裸 LaTeX（`\times`、`\alpha`、`P_{基年}`）。extract 阶段就要转：`^{①}` 形式的 inline_equation 是**脚注标记**（还原成裸圈码）、`^{N}` 是上标（`<sup>N</sup>`）、其余一律 `$...$`。漏掉这一步后面只能靠正则补救，极易切错
- **正文散落 LaTeX 自动包 $（wrap_math）**：`\alpha`、`72\%`、`P \times Y`、`Y = K^{\alpha}[(1-u)L]^{1-\alpha}` 混在中文里。做法：先按 `(\$[^$]*\$)` 切段，只处理非公式段；命中 `\\[a-zA-Z]+` 后左右扩展到数学字符集；**向左扩必须允许 `{`/`}`**，否则 `P_{基年} \times Q` 被切成 `P_{基年$} \times Q$`（实测踩过）；`\%` 先还原成 `%` 再包
- **写含反斜杠的正则不要经 patch/heredoc 拼**：`BS = chr(92)` 后 `BS + 'begin{array}'` 拼；字符集里字母范围用字面量 `'A-Za-z0-9'`，**不能** `re.escape("A-Za-z0-9")`（变成 `A\-Z` 破坏范围）。症状是「正则看起来对但 match 返回 None」，本会话为此耗了多轮
- **`clean_tex` 必须在所有公式输出路径都调用**：独立公式走 `interline_equation` 分支、行内走 text 分支，只给其中一个加 `array` 列格式修正，另一个仍报 `unexpected "l"`——pandoc 只给 WARNING 并把公式退化成 TeX 源码，很容易漏看
- **段落合并只能在页边界做**：`mergeable=first_in_page`，只让每页**第一块**与上一页末尾尝试拼接；页内各块本就是独立段落，按「前块无终止标点」合并会把相邻两段粘成一段（本会话第一版 3750 段 vs 修正后 4072 段，差的全是被粘掉的段落）
- **双栏判定：只用「左右块数」，不要用间距/中线判**（曼昆案例两种错法都踩过）。可用规则：`tl = [text 块 x1<=310]`、`tr = [text 块 x0>=300]`，`two_col = len(tl)>=3 and len(tr)>=3`。**不要**用「左栏 max(x1) 与右栏 min(x0) 的空隙 > 4pt」——双栏页里夹着跨栏块时 `max(x1)` 会取到跨栏块的值，空隙变负，整页被误判单栏（p450 术语表左栏块 x1≈302、右栏 x0≈316，但同页有跨栏块 → 误判；随后整页按 y 排，左右栏句子交替串栏）。也不要单纯按「块跨中线」判（单栏页正文块天然跨中线）
- **双栏页串栏碎片直接丢，不要试图接回上文**：双栏页 OCR 会把某栏的半句识别成独立块（如孤立的 `稳定性？`、`附录。)`），它原本接在上栏某句末尾。想「找最近一个以汉字结尾的段落追加」会**接错位置**——`prev_para_idx` 在 heading/block 重置后可能指向完全不同的段落（本会话把它接进了另一题的选项里）。判定：`len<8` + 纯中文/括号 + 无独立语义 → 丢弃
- **章名取众数 + 归一化比较**：同一章各页页脚章名空格/OCR 差异（`第11章 总需求I：…` vs `第 11 章 总需求 I：…`）会让 `(章号, 章名)` 元组判成两章、重复出 `# 标题`；改为按章号取章名众数，比较时 `re.sub(r'[\s：:·]', '', s)`
- **篇分隔页 = 全图页 + 页眉「第N篇」+ 竖排标题块**：只有 1–4 个块（竖排篇名 text + `第N篇` title），页眉可能只有 `第1篇`；不能只认页眉，也不能当正文输出
- **标题层级必须按原书结构：篇 → 章 → 节（用户会直接指出「章不是应该在篇下吗」）**：`#` = 篇 / 前置章节，`##` = 篇下的章，`###` = `x.y` 小节，`####` = 小节内的案例研究/参考资料/小标题。**不要把篇和章并列成同级 `#`**——即便每章独立拆 xhtml（`--epub-chapter-level=2`）也一样要降级；用户看的是导航树，不是文件切分。
  - 层级：`ch_level = 2 if (cur_part and isinstance(ch, int)) else 1`；无篇的 front matter 章（总序/序言/辅助材料和媒介/结束语/术语表/译后记）保持 `#`，其小节降到 `##`（`off = 2 if isinstance(cur_chapter, int) else 1`，`heading(ch_level + off, …)`）。
  - **陷阱：`ch` 取自本页页脚，页脚漏识别时 `chapter_no is None` → `ch_level` 退回 1，同一章里 h1/h2 混排**（本会话改完第一次仍不对，症状是 `1.3 本书的安排` 变成 `##` 而 `1.1` 是 `###`）。必须用 `eff_ch = ch if ch is not None else cur_chapter` 算层级。
  - 特殊小节：结束语里的「启示 2/3」降到 h3（挂在「四个启示」下）；「宏观经济学的八个重要变量」是独立附录级内容 → `#`。
  - pandoc：三层导航用 `--toc-depth=3 --epub-chapter-level=2`（篇→章→节）；`--toc-depth=2` 只出两层。生成后 **`grep '^#\{1,2\} '` 打印层级树自查**，别只看 TOC 条数（条数对但嵌套错是常态）。
- **页脚噪声正则族（教科书）**：`宏观经济学（第十版）`、`\d{1,3}\. 宏观经济学（第十版）`、`第\s*\d+\s*章[^，。；：？！]{0,32}`、`目录 3`、`《经济科学译丛》总序 1`；**页眉里混入的正文续句**（`于国外产品变得较便宜了。`、`方面提供了见解。`）要按「含句读 + len>8」救回正文，不能一律丢
- **脚注区定位**：候选 = discarded `page_footnote` + **discarded `footer` 里以圈码开头的块**（数学注释常落在 footer）+ preproc 里 y>380 且以圈码开头的 text/公式块；`zone = min(y)`，y ≥ zone 的块全归本页脚注；按 y 排序后「圈码开头 = 新条目，其余并入上一条」，**行间公式块并入上一条脚注**（否则数学注释被拆成正文段落）
- **未配对圈码 = 列表符号**：正文里以圈码开头、但本页脚注没有该圈码的块 → `- `。关键概念框按空白切列表**仅当条目无句号且 len<220**，否则会把整段正文拆成一堆列表项（本会话序言被拆坏）
- **图题判定要看句读，且必须加「引用动词」黑名单**：正文里 `^图\s?\d+-\d+` 且**无句号**、len<80 才**可能**是题注；带句号的是图释正文，保持普通段落。**但只靠「短+无句号」会把正文吃掉**——OCR 常把「图 6-1 也可以表明劳动的边际收益递减规律。假定土地和其他投入保持不变……」截成 70 字无句号块，被误挂成图题、正文凭空消失（本会话实测踩过，保真度没掉是因为字仍在、只是位置错）。所以还要判「图号后是否紧接引用动词」：`描述|表明|显示|说明|是|将|表示|所|中|到|和|与|及|（|(|给出|描绘|呈现|列出|用|可以|还|也|概括|总结` → 是正文的交叉引用，不是题注。原书大多数图没有独立题注 → 直接 `〔图〕` 占位
- **图题挂靠顺序：先上后下**：题注几乎总在图**下方**，但同页可能有两张图 + 两个题注，按「|Δy| 最小」会把上图配到下题的题注。规则：先找 `0 <= cap.y - fig.y < 330`（图在上、题在下）里最近的一张；没有才退到 `0 < fig.y - cap.y < 180`（题在图上）。配对用「已占用 fig 索引」防重复
- **公式：裁切图 vs MathML 是用户选择项，不是默认值**（曼昆案例，质量差距极大）：`interline_equation` 的 span 同时带 `content`（OCR 转的 LaTeX）和 `image_path`（原公式裁图）。OCR 版会把数字拆成 `2 0 1 7`、把 α 读成 `a`、把 `L` 读成 `I _ {L}`、`72\%` 读成 `72\\%`——这些错在 MathML 里会原样显示给读者。**有 `image_path` 就输出 `![](images/<hash>.jpg)`**（`extract.py` 的 interline_equation 分支要记得把 `figs` 一起带出来，否则 build 阶段拿不到），没有才退回 `$$...$$`。代价是公式不可复制/不可重排，需向用户说明；本书 358 个公式全部走裁图。**但用户明确要「可复制的公式」时就改走 MathML**（第十一版案例）：`$$...$$` + `pandoc --mathml`，并用「剥掉 `<math>` 后搜裸 `\\[a-zA-Z]{2,}` 必须为 0」做验收；两套都要能切，先问或按上次同一本书的选择
- **章节归属兜底：小节号优先于页脚**：页脚偶尔漏识别会把下一章首节算进上一章（曼昆 14.1 被算进第13章、13 章因此多出 9 个二级标题）。规则：见到 `^\d+\.\d+` 的 `##` 小节标题时，若小节号整数部分 ≠ 当前章、且该章号在章名表里，就**先补发 `# 第N章 章名`** 再输出小节标题（配 `emitted` 集合防重复）
- **页脚章名的特殊章**：`总序/序言/辅助材料和媒介/术语表/译后记/结束语` 也常只在页脚出现（如 `《经济科学译丛》总序 1`、`术语表`、`卢远瞩`）。按 `startswith` 逐个匹配（总序用 `in`，因为前面带书名号），匹配到就把该章名当 chapter 键；否则整段会挂在上一章末尾
- **表格题注在 HTML 首列且跨行重复 → 删该列**：OCR 常把「表3-1 …」和「资料来源：…」塞进第一列并 `rowspan=N` 覆盖全表，展开后每行首格都相同。判定：`all(row[0] == grid[0][0]) and CAP_RE.match(grid[0][0])` → 整列删掉，题注另用 `**表3-1 …**` 输出。跨页续表（页眉 `续前表`）自然变成同页第二张表，不必合并
- **保真度自检（几秒出结论）**：`源 layout 所有 span 的非空白字符数` vs `book.md 去标记后的非空白字符数`，比值应 ≈1（本案例 0.998）。低于 0.97 就查是不是某类块被静默丢弃
- **pandoc 默认 EPUB CSS 没有 `img` 规则**：900px 宽的插图在手机上溢出 → 注入 `img { max-width:100%; height:auto; }` + `p > img { display:block; margin:.8em auto; }`
- 详见 references/varian-microeconomics-case.md、references/mankiw-macroeconomics-case.md、references/marx-math-econ-case.md
- **同一本书的新版本要重新探索，不要复用旧脚本的阈值**：曼昆第十一版（references/mankiw-macroeconomics-11e-case.md）与第十版同社同版式，却有五处致命差异——①**页脚不再带章名**，章边界要从页首 title 块 `re.search(r'第\s*(\d+)\s*章')` 取（标题语序是乱的：`国民收入：源自何处？第3章 去向何方？`，startswith 必失败），且只能看**首块 + y<180**（序言里有个小节就叫「术语表」，扫全页 title 会把章判错）；②**篇分隔页页眉会 OCR 错**（实为第二篇却写「第一篇」）→ 篇号用出现顺序计数器，篇名查常量表；③**双栏阈值按页宽换算**（第十版 310/300 在第十一版漏掉整个右栏 `x0≈239`，症状是左右栏句子交替串栏）；④正文裸 `*` 译注与数学 `$r^{*}$` 撞车 → 用私有区占位符 `\ue000` 在 extract 阶段区分，不要 build 阶段全局替换 `*`；⑤`^{[^id]}` 是**行内公式里嵌了脚注引用**，必须还原成 `[^id]`（pandoc 报 `Note with key ... defined but not used` 就是它）

## 变体：中译本学术专著·双注释体系（页脚圈码 + 章末「译注」数字）
- **触发**：4 个 layout.json 按页连续切分（200/200/200/135 页）、`interline_equation` 只有数十条**且带 `image_path`**（走裁图或 MathML 二选一）、`table` 块带 html、`image` 块只有个位数（肖像插页 + 资本循环图）、**页脚 `discarded page_footnote` 圈码注（每页从①重编）+ 每章末「译注」区数字注（每章从 1 重编）两套并存**、书末有「参考书目 / 人名索引 / 主题索引」
- 案例：references/harvey-limits-to-capital-case.md（大卫·哈维《资本的限度》张寅译，中信 2017，735 页：页脚圈码注 271 条 + 章末译注 555 条、23 公式、4 表、30 图）
- **两套体系的识别顺序**：先跑一遍 `diag_two_note_systems.py`（scripts/），它同时打印「章级：正文 `^{N}` 数字标记 vs 译注条目」和「页级：正文圈码 vs 页脚注条目」。**别先写 build 再诊断**——两套体系混在一起时，缺口报错会互相掩盖
- **`ref_text` 是独立块类型**（本书 702 块）：参考书目、译注条目、索引条目都可能是 `ref_text` 而不是 `text`。extract 阶段漏掉 `ref_text` 会让参考书目/译注**整章变空**（症状：章标题在、正文 0 块）
- **译注区可能整个落在 `table` 块里**（本书 B p188 一章 41 条、C p51 一章 16 条）：OCR 把单列条目识别成单列表格，`<table><tr><td>12.《全集》…</td></tr>…`。译注解析必须先把 `table` 的 html 走 `html_table_to_grid()` 拆成行，否则**该章译注全部静默丢失**（本书第8章 73 条、第9章 81 条就是这样被救回来的）
- **译注区内混着页脚注块**：`译注` 标题之后仍可能出现 `discarded page_footnote` 的圈码块（本书 C p50 的①、C p160 的①、B p69 的①，都是长段页底注）。若整块丢进译注区，页脚注丢失且正文圈码无落点（`unresolved_circ`）。规则：**译注模式下一律判断——`fn` 块且以 `{{MARK:圈码}}` 开头 → 归回 `items` 作 `fn`；其余才进译注文本**
- **译注条目序号会被 OCR 读成正文**：`…译文根据本书的表述做了调整48.《全集》第46卷…`（序号前无任何标点）。所以分条正则**不能要求前文是标点**；改用「严格连续」判据：`n == last + 1` 直接收；`n > last+1 and n-last <= 30 and 前文 in '。！？；：）】”’…'` 才允许跳号（并记 gaps）；其余一律当正文忽略。本书靠这条修好 4 处 gap（第2章48、第4章31、第10章21、第11章93）。**gap 容差不能写 6**：第3章译注 64→74 之间整段缺 10 条（源数据 A p190 只录了注64 与注74 两行），容差 6 会把 65–73 全部当正文吞掉、译注区少 10 条且不报错；改 30 后能正确识别缺口
- **页眉会夹进译注条目中间**：`…第230页脚注。资本的限度31.《全集》…`（书名页眉被 OCR 拼进条目）。解析前先 `txt.replace('资本的限度','')`；条目尾部残留 1–3 字页眉碎片用 `re.sub(r'(?<=。)[^。]{1,3}$','',t)` 清掉
- **`\prime` 不是注释标记**：`^{\prime}`（数学撇号，`C^\prime`、`M^\prime`）在 inline_equation 里出现时**必须转 `{{MATH:…}}`**，不能当 `^{*}`/`^{N}` 一类标记处理——本书 4 处，误转会让整章标记序列错位
- **裸圈码归一只能在 `text` 类型 span 内做**（本书实测踩过）：第一版在 `block_text()` 末尾对整块 `re.sub` 圈码，而 `inline_equation` 早已把 `^{①}` 转成了 `{{MARK:①}}` → 得到 `{{MARK:{{MARK:①}}}}` 双重包裹（症状：标记数虚高、MathML 段被吞）。正确位置是 `span_text()` 的 `t=='text'` 分支，且必须在拼块**之前**
- **页边竖排噪声 vs 被误判的正文页眉**：本书 `aside_text` 是竖排书名/章名/英文页码（宽 <60），`header` 里既有窄条也有**整段正文**（宽 >60 且 len>20，是跨页续文被甩到页首）。判据：`bb[2]-bb[0] < 60` → 边注丢；宽块按「含句读 + len>8」救回正文；`page_number` 有两套（页边码 `xiii`/`010` 与印刷页码 `003`），只取三位数
- **章节标记必须在宽度/边注过滤之前判**：`译者说明`/`后记`/`参考书目`/`人名索引`/`主题索引` 会以窄 header 出现（宽 <60），先过滤就会丢章标题——本书实测「后记」「参考书目」「人名索引」「主题索引」四个 `#` 级标题全在窄 header 里
- **章名可能整块被丢**：`导言` 在本书 A p42 是 `header` 且窄（`aside_text` 里也有），过滤后整章消失。补一个 `FORCE_START = {('A',42):'导言'}` 按 `(file, pi)` 硬指定章节起点（同 `FORCE_START` 也用来把 A p9-10 的两张肖像插页归到 `# 插图` 下，否则它们会挂到「译者说明」末尾）
- **页脚注续行会跨页**：`page_footnotes()` 里 `curc` 必须存 **`(pagekey, circ)` 元组**而不是 `circ`——续行块来自下一页时 `res[(page, circ)]` 直接 `KeyError`（本书 A p86 实测）
- **双向链接直接用 HTML 锚点**（本书用 `--epub-chapter-level=1`，一章一文件，跨文件锚点由 `fix_epub_links.py` 修）：正文 `<a id="tnref{ch}-{n}" href="#tn{ch}-{n}"><sup>{n}</sup></a>`；译注条目 `<a id="tn{ch}-{n}"></a>{n}. 文本 <a href="#tnref{ch}-{n}">↩</a>`。**只给正文确有落点的条目加 ↩**，否则一次产生几十条死链；同一编号重复出现时只给第一个 `id`（后续只留 `href`）
- **收尾诚实边界（本书实测，可直接照抄口径）**：39 处「译注有条目、正文无标记」的缺口里，用「引文页码指纹」（段落末尾 `（《全集》第X卷，第N页）` 在相邻两个已知标记之间唯一命中）只能可靠补回 5 处，其余 34 处是 OCR 整处丢失上标（layout 里既无 span 也无残留数字）。**不要硬插**——交付时按章列出缺号清单，说明需要原扫描页才能补

### 收尾阶段实测（第二轮：断句合并 + 标记序列 + EPUB 注入）
- **跨页合并必须能跨越页底注块（本书最高频的假性丢字）**：OCR 输出顺序常是「页末半句 → 该页 page_footnote 块 → 下一页首块」。只判「相邻两块」的合并逻辑会在这里断开，全书 30 余处正文被切成两截（症状：保真度比值卡在 0.98、正文段数偏多，但逐块扫描报「0 丢失」——因为字都在，只是断成两段）。修法：合并时记住「最后一个正文段的下标」`last_p`，遇到 `fn` 块只计数不清零，下一个 `p` 块允许与 `last_p` 拼接；条件仍是「前段无终止标点 + 后段非题注」。
- **合并后圈码标记会挂到错误的页底注**：合并把后页文本并进前页段，该段 `page` 属性若取前页，后页那个 `①` 就去前页的脚注表里找 → `unresolved_circ` 从 1 飙到 31。修法：**extract 阶段就给每个圈码打来源页戳**（`{{MARK:①@A30}}`），build 的 `mrepl2` 拆 `@` 后按 (页戳, 圈码) 查 `fnmap`；`page_footnotes()` 与「译注区判 fn」的正则都要容忍 `(@[A-Z]\d+)?`。
- **页底注文本里的标记必须单独渲染，不能走正文渲染路径**：页底注里常夹 `①`（交叉引用「见第51页注①」）和裸数字（OCR 噪声）。若套用正文的 `render_text`，交叉引用会被当成本页脚注引用 → 产出 `[^fA30-①]: … {{MARK:12}}` 这种**未渲染的残留 token 混进脚注定义**（grep `{{` 能查出来）。正确做法写独立的 `render_fn()`：圈码保持纯文本、`*` 丢弃、数字**只在正文确实没有落点时**才建链接（顺便把这类「注释里才有标记」的条目救成有落点），其余丢弃。
- **正文标记序列修复（`^{11}` 被 OCR 读成 `^{1}`）**：表现为序列里出现重复或倒退编号（`1,2,3,1,5`、`8,3,10`）。修法写 `fix_mark_sequence()`：按文档顺序维护 `last`，遇 `n <= last` 且 `last+1` 存在于该章译注表 → 改成 `last+1`；`n == last` 且无对应 → 直接删掉这个重复标记。跑完 `dup_mark` 归零。
- **上标被读成普通数字的第三种形态**：句末引号后紧跟数字再接括注引证 —— `…才是生产力发展的界限”10（《资本论》第3卷，第484页）`、`…携手并进的。”39（《资本论》第1卷，第604页）`。扫描正则 `(\d{1,3})(（《[^）]*》第[\d、—]+页）)` 或 `([”’])(\d{1,3})(?=[（(《])`，命中后**逐处人眼核对编号与该章译注条目是否对应**，再写进 `TEXT_FIXES = [(old, new)]` 表（本书 4 处：第3章注10、第4章注39、第9章注15、第11章注81）。别用通用正则自动替换——`16、17世纪`、`第77、81页` 这类会被误伤。
- **源数据整页缺注释 → 插占位条目并建链，不要留裸上标**：正文有 `^{65}` 但该章译注区没有第 65 条（源页 OCR 只录了两行）。做法：算出 `ch['lost'] = 正文用到但译注表缺的编号`，按**连续区间合并**成占位条目 `〔源数据缺该条注释：注65—73（共 9 条）在源文件中未被 OCR 录入〕`（后续同区间的条目写「同上」），照样建 `id`/`↩`。这样正文上标可点、读者知道为什么没有内容，比裸 `<sup>` 和「整章少 10 条」都好。
- **表题注必须排在分隔线之内**：插入组顺序固定为 `---` → `**表N-M**` → 表格 → `---`。写成「题注 → `---` → 表格」会让题注跑到线上方、和正文粘成一段（本书表8.1 实测）。
- **`rowspan` 转 grid 会重复首列**：`html_table_to_grid` 展开 `rowspan=2` 后首列文字复制成两行（「物质形式/物质形式」）。原表其实是「左上角单元格 + 表头两列」，改写源 HTML 为 `<tr><td>物质形式</td><td colspan="2">生产内部的范畴</td></tr><tr><td></td><td>…</td><td>…</td></tr>`（空单元格 + colspan）才是对的；别去改 grid 渲染器。
- **索引的双栏缩进不可还原，如实交付**：主题索引/人名索引原书是双栏 + 子条目缩进，OCR 把双栏拉平后 `x0` 在交错行里不可靠（同一页 `x0` 在 36/59/68/73 之间跳），按 `x0` 分层会造出假层级。做法：统一输出 `- 条目` 不分层，并在交付说明里写明「文字一条不少，层级缩进无法还原」。
- **注入封面的三个 epubcheck 硬错（本会话一次踩齐）**：① `ERROR(RSC-005): @refines missing target id: "epub-creator-1"` —— pandoc 已生成 `<meta refines="#epub-creator-1" property="role">aut</meta>`，改写 `<dc:creator>` 时用 `re.sub(r'<dc:creator[^>]*>.*?</dc:creator>', …)` 会把 pandoc 给的 `id` 属性一起吃掉 → 替换时必须**保留原属性**（`<dc:creator%s>` 回填 `m.group(1)`）；② 见上条 nav mathml；③ `ERROR(RSC-007): Referenced resource "EPUB/text/cover.jpg" could not be found` —— `cover.xhtml` 放在 `EPUB/text/` 下，图片引用要写 `../cover.jpg`，写成 `cover.jpg` 就指到 text/ 目录里。

### 引文段落转引用格式（用户口径，第三轮实测）
- **用户原话**：「文段结尾有标注出处且独立成段，我刚刚没说清楚。有些正文里可能也用""引号引用且正好是在段落的最后，这些不要用引用格式，不要识别错了」。即：**只有「整段都是引文」的段落**才转 `>` blockquote；作者本人的分析段、以及正文里带引号引语而引语恰在段末的段落，一律保持普通段落。
- **绝对不能用「段末有出处」单条正则**：本书 77 个段末带出处的段落里只有 57 个是整段引文；另外 **100 个是作者分析段**（例：「《资本论》开篇的论述简单得异乎寻常。马克思把商品界定为……（《资本论》第1卷，第38页）」）、**20 个是段末引语**（例：「马克思接着补充了一个颇为隐秘的说法：“成为生产工人不是一种幸福，而是一种不幸。”……」）。按正则跑会误伤 120 处，比不做更糟。
- **可行流程**：`scripts/check_quote_paragraphs.py book.md` 先把「段末带出处」的段落全导出（含所属章、是否含引号、前一段末尾），**逐条读原文**分类 → 把判定为整段引文的**段首 15–20 字指纹**写成 `QUOTE_STARTS` 常量（去空白去标记后 `startswith` 比对）→ build 时命中即输出 `> `。指纹比正则可审计、不会随改版漂移；判错时改一行常量即可。
- **读原文时的三条判据**：① 前一段以冒号 / 「写道」「认为」「总结说」「如下」结尾 → 后段大概率是整段引文；② 整段引文通常**不带引号**（原书用缩排表示引文，OCR 后引号消失），段内出现成对 `“”` 的往往是作者转述；③ 引文段常以「——」开头（接排的分条引文）。
- **一段引文可能跨多个段落（用户第三轮补充：「也有可能是多段的」）**：原书用整段缩排表示引文时，一段引文常被页边界/OCR 切成 2–4 个 `text` 块，**只有最后一段带出处**。做法：判定出引文段后**把相邻引文段合并成一个 blockquote**（段间 `>` 空行 `>` ），不要输出成 N 个独立 blockquote。本书 71 个引用块里 4 个是多段块（第1章 2 段、第2章 2 段、第3章 2 段、第7章 2 段）。
  - **合并的唯一合法条件是「前一段没说完」**：前段末去掉 `<a>`/`[^id]`/引号括号后**不带出处标注**（即以 `……` 或断句收尾）→ 与后段合成一块；**前段已经带出处 `（《…》第N页）` → 这条引文结束了，后段是新引文，必须分成两个引用块**。本书第2章「对任何种类劳动的同样看待」、第13章「在那里，资本主义制度……」都是靠这条正确分块的，早前一律合并会把两条独立引文粘成一块。
  - **绝对不要用「向前回溯把引文前未结句的段落并入」的启发式（本会话 v3 因此整版作废、用户直接说「v3 错了 撤回」）**：这条规则会把作者的话吞进引用块——实测吞进「所以，让我们回到马克思的论述。他说过，抽象劳动」（作者引导句）、「希法亭说（列宁也赞同这一点）：」（引导句）、并把残片「“这里」单独拆成一个引用块。**判据再细也不行**（加「引导动词收尾就停」仍拦不住「…他说过，抽象劳动」这类断在半句的引导句）。正确做法见下条。
  - **正确做法：逐条读原文 + 显式白名单**（用户原话：「你能不能读取一节一节的内容自己根据文本语义判断，而不是使用脚本」）。三步：① 脚本只负责**导出报告**（全部「段末带出处」候选段 + 前后各一段上下文，本书 163 条 ≈ 12 万字，`scripts/check_quote_paragraphs.py` 可扩展成这个用途）；② **逐条读**，判「整段都是马克思原文」还是「哈维自己的分析」；③ 把判定为引文的**段首 15–20 字指纹**写成 `QUOTE_PARAS` 常量，build 只按清单标记，**不做任何语义推断**。指纹比正则可审计、判错改一行；清单条目数 ≈ 引用块数 + 少量未命中（本书 78 条清单 → 71 块）。
  - **指纹匹配必须先把引号归一**：清单里写的是半角 `"`，正文是全角 `“”`/直角 `「」` → `norm_head()` 里统一替换成半角并 `lstrip('"')`，否则以引号开头的段落（`“社会需求”，也就是说…`）永远匹配不上（本书 5 条静默漏判，靠「未命中清单」才发现）。**build 后要打印「清单里哪几条 0 命中」**，命中数对不上就是漏判。
  - **逐章盲读 + 并行 subagent（第四轮，89 段清单 → 84 块，最省力也最准）**：把 book.md 按章拆成独立文件、**剥掉全部 `> ` 标记**、段落顺序编号 `[001]…`，一个 subagent 读一章只回 `{"quote":[段号…]}`；回来用段号映射回段首指纹。脚本 `scripts/blind_read_quotes.py split book.md read/` + `merge answers.json read/`。三条硬规则：
    - **必须盲读（去掉已有 `>` 标记）**：带着标记去读，模型只会核对已有标记——第一批 8 章（含标记版）报出 0 处漏判、1 处误判，全是照抄旧结论；剥标记重派后同一批章补出 20 余段。**这是本环节最容易白跑的一步。**
    - 一个 subagent 只读一章（3–4 万字），16 章分两批各 10/6 个并行，单批 2–3 分钟。
    - 提示词里写死四条排除（作者分析段／句中夹引语／引导句收尾／编号列表属作者分点）和一条并入（一条引文被拆两段 → 两段都算），并要求只输出 JSON。
  - **判读清单落地后必须删掉「自动扩展」规则**：build 里若还留着「前一段是引文且未结句 → 后一段并入引用块」，它会覆盖人工清单、把作者段落吞进去（本轮第6章「资本积累的步伐与工资率仿佛是反向变动的……」就是这样被吞的；删掉这条后多段块从 14 降到 5）。**清单是唯一真相源，不要留任何语义启发式与它并存。**
  - **TAIL_MOVE 的匹配方向极易写反**：判定要查**引文段**（`items[i+1]`）的段首，不是前段（`items[i]`）的段首；写成前段时整张表静默失效（本轮 5 条规则一条没生效，靠「引用块前一段是否结句」检查才发现）。
  - **移动文字会让指纹失配**：TAIL_MOVE 把「但是」「抽象劳动」「我们不应该」移回引文开头后，段首已与清单不同 → `is_quote_para` 要先按 `LEAD_STRIP = ('但是','所以','因此',…,'“这里','金融资本')` 剥前缀再比对，否则这几段会从引用块里掉出去。
  - **两个必做的收尾校验**：① 把每个 blockquote 按 `>` 空行拆成逻辑段，逐段比对清单指纹，**清单项 0 命中就报出来**（本轮 89 条最终全命中；中途漏 1 条是「金融资本」被留在引导句末尾）；② 扫「引用块前一段是否以 `：`/`。` 结句」，非结句且不是标题/公式/`---` 的就是引文头残留（本轮 13 处里 9 处是标题公式、4 处是正常引导语）。多段块数要单独统计并与人工判读出的跨段引文数对上（本轮 5 个）。
  - **另有一类段级缺陷必须靠人读才发现，正则修不了**：① 一句话被 OCR 拆成相邻两段（`…劳动的特殊技巧越来越成为某种……` + `无差别的东西，而劳动…`）→ 拼回；② 一段里混着「引文 + 作者评论 + 下一条引文的引导句」（第13章「…细致微妙的差别。马克思说："这里"」）→ 在评论起点切开，并把「"这里」移回下一条引文开头；③ 引文开头被落在作者引导句末尾（第10章「…（列宁也赞同这一点）：金融资本」）→ 把「金融资本」移回引文首。三处都用 `JOIN_PAIRS` / `SPLIT_AT` / `TAIL_MOVE` 三张显式表实现，条目以 `(段首指纹, 目标)` 定位。
  - **极短首段（<20 字）不加段间空行**：`“这里”` 后面直接接正文的，加空行会渲染成两段，改为直接拼接。
- **竖排书名页眉会落进 `preproc text`**（本书 15 处，症状：正文里凭空出现一行「资本的限度」）：判据 `bb[2]-bb[0] < 45` 且去空白后恰等于书名 → 剔除。`aside_text`/`header` 里的同名噪声已过滤，但这一路是**正文块类型**，最容易漏（本书 grep `^资本的限度$` book.md 从 15 降到 0）。
- **blockquote 必须配 CSS**，否则多数阅读器只缩进一丁点：`blockquote { margin: 1em 1.8em; font-size: 0.95em; } blockquote p { text-indent: 0; }`。
- 交付说明里要写明「识别口径 + 排除了哪两类 + 各自多少处 + 引用块总数与其中多段块数」——用户会核这一条（他会追问「有没有识别错」「是不是多段的」）。

### 收尾两个「校验全绿但成品是错的」陷阱
- **`{{MATH:…}}` 的结束符正则必须 extract / build 两处同步改**：extract 改成私有区收尾（`'{{MATH:%s\ue000' % tex`）后，build 的 `MATH_RE` 仍是 `r'\{\{MATH:(.*?)\}\}'`，公式内容含 `}`（`C^{\prime}`、`\frac{s}{c+v}`）就截断——症状是 build 直接抛错或整段公式变残留 token。改一处必 `grep -n "MATH" extract.py build.py` 核对另一处。
- **`validate_epub.py` + epubcheck 全绿 ≠ 渲染正确**：本书表8.1 的 `rowspan` 被 `html_table_to_grid` 展开后首列重复（「物质形式」出现两次），两项校验都不报错；只有 `unzip -p out.epub EPUB/text/chNNN.xhtml` 读实际 `<table>` 才发现。**收尾必抽 2–3 处表格 / 公式 / 引用块解包读 xhtml**，别只看校验输出。

## 变体：尾注（附注）制 + 跨册合订（本册无注释文本）
- **触发**：正文的数字上标（`^{N}`、`¹²³`、或残留成普通数字）是**尾注**，注释文本在书末「附注」章，常位于**另一个 layout.json**（下册或专门的附注文件）；页底 discarded page_footnote 只有少量 `*` 译者注和 ① 编者注（两套体系，分开处理）。
- **附注解析**：条目标记 `^\d{1,3}[.、]` 开新条，无序号块归上一条；**块内可能粘着下一条**（`\n(?=\d{1,3}[.、])` 再分）；续册文件**首块常是上一册最后一章的注释续文** → parse 函数要能传 `initial_cur`。
- **OCR 用逗号顶替句点会把两条注释粘成一条**（`…I, 406. 18, Takaki,…`）：在**单条注释文本内**定向搜 `\s{prev+1},\s+(?!Vol\.)(?=[A-Z][a-z]+[, .])` 拆分。**不要**为此加通用的「逗号变体」分条正则——会把 `Ser. 1, Vol. 51` 误切成新条目并污染多章注释（实测踩过）。
- **跨册合订**：先按 `^\[\^id\]:` 把每册的**脚注定义区切开**，正文区再做「末段无终止标点 → 与下册首段拼接」；下册缺编名页则在 `## 第N章` 前补 `# 第二编 …`。**下册若丢了某个章节标题（OCR 只留副题行），必须按上册目录补齐**——不补则该章正文被算进上一章，整章尾注链接错位（症状：上一章链接数 > 附注数、该章 0 链接）。
- **尾注链接方案**（不用 pandoc 脚注）：正文 `<sup>K</sup>` → `<a id="enref-c{ch}-{K}" href="#en-c{ch}-{K}"><sup>K</sup></a>`；附注条目 `<a id="en-c{ch}-{K}"></a>{K}. 文本 … <a href="#enref-c{ch}-{K}">↩</a>`。两条硬规则：**只给正文确有落点的条目加 ↩**（否则一次产生 200+ 死链）；**同一编号的重复标记只给第一个 `id`**，后续只留 `href`（否则同文件重复 id）。拆章后务必跑 `scripts/fix_epub_links.py`。
- **自动补回被误识成普通数字的上标**：`scripts/repair_endnote_marks.py`。**关键正则细节**：数字后要**允许空格**（`(?=\s*[\u4e00-\u9fffA-Za-z“《（(])`）——写紧接中文会漏掉一大半（本案例 126/127 处靠这一处放宽才捞回）；数字后接 年/月/日/世纪/人/个/次/多/余/万… 的排除，否则日期被当标记。插入需过三关：**章内序号单调且落在前后已知标记之间 + 该取值只取第一个 + 该章附注确实存在该编号**。
- **每册的脚注/锚点 id 必须带册别 tag**：无页号的页用 `pi` 兜底会与另一册撞号（`build.py <pages> <out.md> [tag]`）；`FIXES`/`NOTE_MARK_OVERRIDE` 这类按印刷页码的修正表，**只在 `page['pageno']` 精确相等时应用**，否则退化到 pi 会跨册误命中。
- **英文原书对不上版本时，编号不可搬运**：用户给的「英文原文」可能是**另一版**（本例中译据 1982 年第 1 版，用户给的是 2010 年第 4 版，且改成了页底脚注）。实测编号偏移（中译第7章注10=英文注13、第13章注3=英文注14…）。可用做法：先做**中英附注对照表**（引证前缀在英文文本里的命中次数），再按「英文句子内容 → 中文同义句」逐条定位；**绝不能按编号直接搬**。
- **收尾的诚实边界（用户偏好）**：OCR 整处丢失的上标（layout.json 里既无 span、也无残留数字、丢弃块/ref_text/独立数字块全查过为 0）**无法机械还原**。此时不要用弱启发式硬插——本会话用「专名唯一匹配」探了 6 个候选，逐条核对后 4 个是错的，全部回退。正确交付：① 附注全文一条不少地收进书末；② 已建链接数 / 缺口逐章清单（编号列出）单独出一份 txt 给用户；③ 说明缺的外部数据（原扫描页 / 英文原版），并**算出真正需要的页**（用缺口区间文本反查页码 → `qpdf --pages …` 只导那几十页，绕开 Telegram 20 MB 上限）。
- **别指望用另一版/另一语的文本层自动做句级对齐**（本案例实测三种启发式，全部不可用）：① 用第4版带数字的 footnotes 做「年份+专名指纹」→ 84 条缺号 0 条可靠；② 用第1版扫描件 OCR 出的 `^`（该版把上标统一读成脱字符，共约 367 个，与 352 条注释量级相当）做指纹 → 仅 1 条可靠，候选被 1844/1861 这类年代反复撞车并列；③ 用已链接标记当锚点按序列插值 → 只能得到 8 个单调锚点，远不够。**结论：文本层对齐不可靠，别在这上面继续加码**；可靠路径只有两条——(a) 中文扫描页图像直接读上标（确定性，推荐），(b) 人工逐条双语比对（可用 `^` 句作辅助线索，但须人判断）。
- **拿到扫描页后怎么读上标（vision 路线）**：`pdftoppm -f <页> -l <页> -r 300 -png book.pdf p`（上标是小字号，≥200–300 dpi）→ `vision_analyze(image_url=<png>, question="这句话末尾引号后的上标数字是几？")`；整页定位后用 `region=[x1,y1,x2,y2]` **按原图像素裁剪（缩放前生效）** 放大只读那一处。机制：vision_analyze 是**转交**型工具——图片编码为 base64 data URL，交给 Hermes 辅助模型路由（`agent/auxiliary_client.py`）中的**多模态模型**，回给主模型的是文字，所以主模型是纯文本也能用。auto 解析顺序：主 provider（若本身是受支持的视觉后端）→ OpenRouter → Nous Portal → 原生 Anthropic → 自定义 endpoint（Qwen-VL/LLaVA/Pixtral）→ None；配置在 config.yaml `auxiliary.vision.{provider,model,base_url,api_key}`（另有 timeout 120s / download_timeout 30s / max_concurrency）。**上标读不准时不要换主模型**，单独给 vision 换更强的 VL 模型：`hermes config set auxiliary.vision.provider openrouter` + `hermes config set auxiliary.vision.model <id>`。SVG/BMP/TIFF 会先被栅格化。**读不清就报「读不清」，不许猜数字**（与上一条「宁缺勿错」同一原则）。
- **批量读中文扫描页补回上标（实测可行，本案例上册 40 缺号 → 补进 26 条，第6/7/8章达 100%）**：
  - **别一页一次 `vision_analyze` 工具调用**（84 页 = 84 次调用）。写脚本在 **Hermes venv** 里直接调辅助客户端，一次工具调用跑几十页：`/usr/local/lib/hermes-agent/venv/bin/python`（系统 python3 没有 openai 模块）→ `import agent.auxiliary_client as A` → `prov, client, model = A.resolve_vision_provider_client()` → `client.chat.completions.create(model=model, messages=[{type:text},{type:image_url,image_url:{url:'data:image/png;base64,...'}}])`。
  - **必须 `background=true` + 可续跑 JSON 检查点**（每页读完立即写盘），84 页约 30–40 分钟；中途重启自动跳过已完成页。
  - **视觉模型很可能是推理模型**：`max_tokens` 给小了会 `finish_reason=length` 且 `content=None`（实测 800/1200 全空），答案只存在于 `reasoning_content`。对策：temperature 0.1 + `max_tokens` 放宽到 4000，并 `resp = content or getattr(msg,'reasoning_content',None) or ''`——Hermes 自带 `tools/vision_tools.py` 就是 `extract_content_or_reasoning` + 空内容重试一次，照抄它的参数最稳。
  - **渲染**：`pdftoppm -f P -l P -r 250 -x ../-y ../-W ../-H ../-png`（-x/-y/-W/-H 是像素 = pt × dpi/72）切掉页眉页脚。文字页 **PNG 比 JPEG 小**（实测 148 KB vs 939 KB），不要费劲转 JPEG。pdftoppm **会在输出名后再拼一次页码**（`-png out/p023` → `out/p023-023.png`），脚本里用 glob 取实际路径，别硬拼文件名。
  - **prompt 用列表格式**：要求逐条输出 `上标数字 | 它前面紧邻的 6~12 个汉字（原样照抄）`，看不清写「看不清」，无上标不列、不解释。带表格/图版的页噪声大（会读出页眉数字），可单页重读或跳过。
  - **三道闸才允许写入**：① 号码必须在该章注释编号表内；② 前文必须在该页文本中**唯一**命中（并加「只比汉字」回退，因为模型常漏抄原文里的数字）；③ 插入位置必须落在**相邻两个已链接标记之间**（顺序单调）。任一不过 → 记拒绝日志，绝不硬塞。
  - **控制组＝免费准确率校验**：这些页上通常还有已链接的注号，模型读到的「号码+前文」若与正文已有位置一致即说明该页读得准（本案例 66 条控制读数全部对上）。把控制读数一并统计进报告，用户能直接判断这一批读数可不可信。
  - **页→章映射要用累计字符数**：把每章页文本按 `bounds.append((total,total+len(txt),pi,pageno)); total += len(txt)` 建偏移边界。**写成 `len(buf)` 会静默全错**——buf 是字符串列表，`len()` 返回元素个数而非字符数，反查永远落不进任何页（本会话在此卡了多轮）。
  - **不要在工具调用里写 `\uXXXX` 正则**：经 JSON/heredoc 传递会变成 `\\uXXXX`，在 raw string 里语义改变，规范化函数会**静默剥掉所有中文**（症状：报「前文在本页命中 0 次」，但手动 find 又能命中）。稳妥写法：`''.join(c for c in s if c.isalnum())`。
  - **双模型一致才采纳（收尾期主力手段）**：本机 axonhub 除 deepseek-v4-flash 外还有**原生多模态 `glm-5.3-flash`**（用户告知；另有 `glm-5.3`）。同一页切块用两个模型各读一遍，**号码相同且前文有 ≥6 字重叠**才算一致读数，再进三道闸。实测一致读数里仍含大量控制组可自检，且**抓出过一处错插**（见下一条）。
  - **有疑问就地做「紧裁终审」**：从 layout.json 取该块 `bbox`，`pdftoppm -r 500 -x/-y/-W/-H`（±6pt 边距）只裁这一段，问两个模型同一问题「这句句末标点后的上标数字是几」，两者一致才动手。比整页重读可靠得多——本案例第12章「……由一个有肠胃病的列兵所组成。”」早前单模型 250 dpi 读成 8 并已插入，紧裁+双模型一致读出 **3**，据此更正锚点（注8 退回待补）。
  - **插入前三道新守卫（本会话补，均实测拦下过错误）**：① 同一注号出现 ≥2 个**不同前文**落点 → 判歧义跳过（ch16 注30）；② 落点 ±80 字内**已有锚点** → 跳过（防重复插，也暴露前后两次读数矛盾）；③ 前文之后**必须紧跟句末标点**（走标点循环后 `j` 未前移即判「句中」跳过）——第1章注3 曾被插进引号内部（"任何东西都可以用机器³制造。”"），而该句三个模型都只读到 8，属误读。
  - **错插更正流程**：整段替换锚点编号（`enref-c12-8`→`enref-c12-3`）→ 扫附注区**删掉目标已不存在的 ↩**（否则留死链）→ 再跑一次补 ↩。
  - **每一步写回都要有护栏**：写 `book_full.md` 前 `assert len(body) > 100000`；每步跑完打印「正文长度 + 锚点数」并 `cp book_full.md book_full.stepN` 留档。本会话有一次生成的 apply 脚本引用了已删除变量，把中间文件写成 **1 字节**（症状：重建出的 EPUB 只有 1548 字符 / 目录 1 条）——靠「EPUB 正文总字符数 + 锚点数」异常发现，恢复办法是从上一份已验证副本逐步重跑并逐步核对锚点（268→294→298→326→330→332），不在坏文件上继续叠加。
  - 脚本：`scripts/read_marks_from_scan.py`（locate/read/apply 三段，可续跑）；实测数据与拒绝样例：`references/scan-superscript-reading.md`。读不清的页 → 放大重读，**不许猜**。
- **判定用户给的扫描件是上册还是下册**：把两个候选 PDF 同一页号渲染成左右拼接图（ffmpeg `hstack` + `drawtext` 标 LEFT/RIGHT），一次 vision 提问「左右分别是什么章节、页码」即可（本案例据此确认 部分1=上册 / 部分2=下册 / 部分3=附注）。比逐页 OCR 猜测快得多。

## 变体：学术专著（全书 MathML + HTML 表格 + 页脚圈码脚注 + 图目录/索引）
- 触发：两个 layout.json（正文分册）、`interline_equation` 数百且**无 `image_path`**（只能走 MathML）、`table` 块带 `html`、页脚只有 `discarded page_footnote` 的圈码注释、书末有「图目录/表目录/参考文献/索引」
- 案例：references/marx-math-econ-case.md（藤森赖明、李帮喜《马克思经济学与数理分析》，313 页合订，811 行间 + 1738 行内公式全 MathML，33 表，74 条页脚注）
- **源数据 LaTeX 是单反斜杠，别做 `replace('\\\\','\\')`**：JSON 里 Python repr 打印成 `\\begin{array}`，实际字符串只有**一个**反斜杠。误加「双→单」替换会把 `\\`（换行）压成 `\`，pandoc 报 `unexpected control sequence \0` / `\3`（`\begin{pmatrix}6000\\0\end{pmatrix}` → `\0`），**公式整块降级成 TeX 源码且不报错退出**。判定方法：`c.count('\\')` 与 `'\\\\\\\\' in c` 都数一遍，确认后再决定
- **pandoc 2.17 没有 `--epub-title-page`**（报 `Unknown option`，exit 2、EPUB 根本不生成）；要去掉自动标题页就 post-process 删 `title_page.xhtml`，或留着当扉页
- **页脚注释三件套（顺序固定）**：① 先把 `^{①}` 形式的 inline_equation span 与裸圈码都归一成 `[[MARK:①]]`（`text_span()` 逐字符转），注释区条目也走同一函数；② 条目切分：**以 `[[MARK:x]]` 开头的块 = 新条目**，其余并入上一条（判据要放在归一化之后，否则 `[[MARK:①]] 比如取部门1…` 会被当成续行）；③ **OCR 把页脚内联公式重复输出成独立 page_footnote 块**（本案例 39 个）：判定 `re.fullmatch(r'\$[^$]*\$', raw) and hay.count(norm_math(raw)) >= 2`（hay = 本页正文+注释拼接）→ 丢；再补一条 `len(norm) <= 8 and norm in norm_math(上一条)` → 丢（`ω`/`g`/`r=0` 这类碎片）。**不滤则注释数 66 ≠ 正文标记 76**
- **正文块以圈码开头 = 被误分类的页脚注释**：`text` 块 `startswith('[[MARK:')` 且该页注释条目数 < 正文标记数 → 从 blocks 里摘出补进 notes（本案例 p2 p93 的「① 此内容进行推广后…」）
- **章节层级（中译本三档）**：`第X章` → `#`；`第X节` → `##`；`一/二/三 + 空格 + 短标题` → `###`（**排除字符集里不要放全角冒号**，`四 均衡增长路径：数量体系` 含 `：` 会漏判）；附录 `B.N` → `##`（挂在 `# 附录B` 下）。**正文行首「第一章主要明确…」不是标题**——靠 `len<40` + 无 `。！？，、；` 挡住
- **页眉噪声两种形态**：① title 块重复书名（去空白后 == 书名，本案例 p11/p29/p57/p119 四处）→ 丢；② header 里 `......`、`• • • •` 装饰行 → 忽略。`[Unreadable]` 也要滤
- **`Ground Truth` 噪声出现在 preproc text（不只是 discarded）**：`The Ground Truth image displays a single, solid horizontal line…` 整段 650 字，混进正文会毁掉索引区。过滤判据：含 `Ground Truth image displays` 或 `quick brown fox`
- **图目录/表目录/索引 = 多行 text 块**：块内按 `\n` 拆成 `- ` 列表项；**索引跨 5 页**（本案例 p118-122），页区间必须扫到「条目消失」为止，只取首两页会丢掉大半索引（症状：索引里 `劳动过程` 等条目跑到正文段落里、单段长 1313 字符）
- **缺图处理**：只输出**带 caption 的 fig**，无题图的 image 块是出版社 logo/封面装饰，直接跳过（否则封面页会多出 `〔图〕`）；正文按位留 `〔图〕` + `**图X-Y 标题**`，并在交付说明里列全缺图编号
- **保真度检查对表格书要换方法**：grid table 的 padding/分隔线会让「字符数比值」虚高（本案例 1.10，看着像重复渲染其实全是表格横线）。改用**块级清单法**：对每个源块取归一化后前 40 字（去 `[[MARK:]]`/`[^id]`/空白/`$\\{}`），不在 book.md 里就报——本案例报出的 13 条全是目录/索引（已按 `- ` 渲染），属正常
- **双向脚注直接用 pandoc 原生**：正文 `[^p1-22-1]`（`file-pi-seq`），定义集中在文末；`validate_epub.py` 报 `noteref 74 / backlink 74 OK` 即通过。不需要手写 `<a id>` 锚点（那是尾注/拆章场景的方案）

## 变体：中译本学术专著（页脚圈码脚注 + MathML 公式 + HTML 表格 + 少量插图）
- 触发：多个 layout.json **按页连续切分**（每册 200 页上下，末页句子截断、下一册首页续接）；`discarded page_footnote` 圈码注释**每页从①重编号**；`interline_equation` 数十且**无 `image_path`**（只能 MathML）；有 `table` 块；`title` 块给出「第N章」「一、二、三、」「附录一」层级；书末有双栏「译名对照表」
- 案例：references/sweezy-capitalist-development-case.md（斯威齐《资本主义发展论》三册 477 页：472 条页脚注全对齐、65 公式 MathML、7 表、译名表 14 个画数、431 KB）
- **`table` 块的 HTML 在 `blocks[]` 的 `table_body` 子块里**，`table_caption`/`table_footnote` 同样是子块——只扫块自身的 `lines/spans` 会**静默得到 0 张表**（与曼昆 `chart` 块的 `chart_caption` 同一类坑）。extract 阶段必须遍历 `b['blocks']`；表题/表注也从子块取，别靠「同页最近短文本」猜（会把「续表」页错配给上一张表）
- **`html_table_to_grid()` 返回 `list[list[str]]`（rows），不是 markdown 字符串**：要 `grid_to_md(html_table_to_grid(html))`，否则 `TypeError: expected str instance, list found`
- **跨页续表**：用**归一化表头**（去空白/`$`/反斜杠）比较——两页表头 OCR 空格常不同（`不变资本c` vs `不变资本$c$`），严格相等比不中；合并时记下已输出行的 `start/end` 索引，`out[start:end] = grid_to_md(rows).split('\n')` **就地替换**，不要追加第二张表（旧技能「跨页续表自然变成同页第二张表，不必合并」只适用于教科书那种「续前表」独立表）
- **页脚注释排序按 `(y, x0)`**：同一 y 并排的 ①② 只按 y 排会得到 `notes [2,1]`——诊断信号就是「body `[1,2]` vs notes `[2,1]`」（本案例 3 页）
- **正文块以圈码开头且本页脚注缺该号 = 被误分类的页脚注释**：`Counter(body_marks) - Counter(note_nums)` 精确搬运（p146 的①正文续文），搬完重算两侧
- **OCR 把整行公式重复输出成多条 page_footnote**（p154 一次 9 个碎片 `p = s^{\prime}(1-q)`、`1-q`、`q^{\prime}`…）：判据 = 无中文 + len<60 + 归一化后是**另一条**的子串 → 丢
- **`interline_equation` 块里的圈码**也要转脚注引用（否则该注无落点）；`inline_equation` span 里夹圈码时（`p = s^{\prime}(1-q) ①`）拆成 `{{FN}}`+`{{MATH}}` 两段，不能整块当公式
- **标题去空格后归一化**：`第一章马克思的方法` → `第一章 马克思的方法`；`附录一关于再生产表式问题` → `附录一 关于…`（正则必须含 `附录[一二]`，只写 `第[一…]+[章篇]` 会漏）
- **译名对照表**：按 `x0` 分左右栏；块内 `\n` 拆成列表项；`Tugan-Baran-\nowsky` 连字符续行**不加空格**拼接；一行粘两条（`萨伊，J. B. Say，J. B. 康特，伊曼努尔 Kant，Immanuel`）用 `\s+(?=[汉字]…，)` 再拆；**画数小标题（三画/四画…）输出为加粗行，绝不能给 `##`**——否则导航树里冒出十几条「三画」（用户看的是 TOC，不是文件切分）
- **附录下的「一、二、三」降一级为 `##`**（附录本身是 `#`）；篇标题用汉字数字 `# 第一篇 …`（`'一二三四五六七八九十'[n-1]`），别输出 `# 第1篇`
- **半角括号必须成对转换**：逐字符转只换半边，得到 `(1946年）` 混搭。先扫 `(`…`)` 配对，括号内含汉字或左右邻汉字 → 整体换全角；再做逐字符转换（**跑两遍**，让 `）` 参与后续逗号/空格判断）
- **TERMINAL 必须含全角冒号 `：`**：以「如下面所示：」「……他说：」结尾的引导句是完整段落，不含冒号会把下一段引文粘上来（本案例 within-page 非终止对 361 → 48）
- **短前块（<20 字且不以 `，、：` 结尾）不参与跨页合并**：「一、引言」「还有：」「保罗·M. 斯威齐」这类结构/署名块不能被后段吞掉
- **诗行合并**：连续 ≥3 个 ≤18 字、以 `，`/`。` 结尾的 text 块 → `<br/>` 连成一段（p288「没先也没后，/统统在一道，/突然全爆开，/好像肥皂泡。」）
- 脚本：scripts/wrap_math.py（散落 LaTeX 包裹，含花括号配平）、scripts/check_loss_blocks.py（逐块丢失扫描，归一化含标点映射）

### 散落 LaTeX 包裹与占位符（三处硬坑，本轮全踩过）
- **花括号必须配平右扩**：`\frac{消费增长率}{生产资料增长率}` 花括号内是中文，按「数学字符集」右扩会停在第一个 `}` → `$\frac{消费增长率}${生产资料增长率}`，pandoc 报 `unexpected eof`。右扩后 `{` 多于 `}` 就继续扩到配平；右邻是 `^` 或 `{` 也继续吞
- **占位符结束符不能用 `}}`**：`{{MATH:…}}` 内容本身含 `}` 时 `[^}]*` 会截断。用私有区字符收尾（`{{MATH:<tex>` + U+E006），保护/还原/切分的正则要同步改
- **脚注引用落在 `$…$` 里的修补顺序**：先 `{{FN}}`→`[^pN-M]`，再在 MATH token 层面把 `[^pN-M]` 搬到公式外（`{{MATH:tex<U+E006>[^pN-M]`）。**不要在 `$` 层面正则搬运**——配对歧义会把整句吞进公式（症状：整段变成 `$…$`）
- **`Note with key 'pXXX' defined but not used` 是「标记没生成」的报警**（本案例正是 `$A[^p466-1]$` 落在公式里），按缺号回查该页原始 span，别当良性警告
- **`Could not load translations for zh-CN` / `The term Abstract has no translation defined` 是 pandoc 2.17 良性噪声**，可忽略
- **pandoc `--mathml` 对中文公式友好**：`\text{剩余价值率}` → `<mtext mathvariant="normal">`、`\boxed` → `<menclose notation="box">`、`\underbrace` → `<munder>`，可复制可缩放
- **交付前跑 epubcheck**（本机 `/root/epub_work/epubcheck-5.1.0/epubcheck.jar`，有就用）：`java -jar epubcheck.jar out.epub`，0 errors 0 warnings 才算过；比自写校验更权威
- **豆瓣 `subject_suggest` 可能只返回带书脊的立体展示图**（800×800）：仍可用，但交付时说明「不是平面书影」；先用 `vision_analyze` 确认是不是真封面
- **构建脚本改动用 write_file 写 patch 脚本再执行**：Hermes terminal 会把命令行里的 `&` 判成后台符并拒绝，`$` 会被 shell 展开，`sed … | python3` 触发安全审批——含正则/私有区字符的改动一律走 `.py` 文件

## 变体：中译本教科书·多分册（圈码页脚注按**章**连续编号 + 答案/术语表双栏 + 图组）
- 触发：4 个 layout.json（200/200/200/87 页）**按页连续切分**、`interline_equation` 数百且**带 `image_path`**（可裁图或 MathML 二选一）、`table` 块带 html、`chart`/`image` 块数百、页脚 `discarded page_footnote` 圈码注、书末有「请回答答案 / 奇数题答案 / 术语表 / 教学支持」
- 案例：斯奈德、尼科尔森《微观经济理论：基本原理与扩展》第 11 版（北大社），references/micro-theory-11e-case.md
- **圈码页脚注是「按章连续」而非「每页从①重编」**：与斯威齐案例相反。判定方法：逐页打印 `body marks` 序列 vs `notes` 序列，跨页看是否递增（本案例 第1章 ①-⑦ 跨 p19-31，第2章 ①-⑲ 跨 p35-70）。**先做这个判定再写 build**，判错会导致整章脚注全错位
- **脚注编号必须「懒分配」，不能预先按页编号**：不要「先把本页所有注释编号成 n..n+k，再按顺序配给正文标记」。正确做法是维护本页注释队列 `pnotes/pnote_i`，正文遇到标记时才 `next_ref()` 取一条、分配编号并压入 `notes_buf`；页末再把队列里剩下的注释补编号。**症状对照**：预先编号时 `refs 646 / defs 323`（同一 id 被多处引用 + 大量「无引用的定义」），改成懒分配后 323↔323 全对齐。**标题块里的标记也必须走同一条路径消费编号**（否则该条注释变成「无引用的定义」）
- **`^{N}` 是脚注标记还是数学上标，靠前文判**：OCR 把 ⑩→`^{10}`、⑳→`^{20}`、⑬→`^{13}`。规则：`re.fullmatch(r'\^\{?\s*(\d{1,2})\s*\}?$', span)` 且**前一个字符是汉字或中文标点** → 脚注标记；前文是 `=`/字母/数字/`^`/`_` → 数学上标（`x^{2}`、`e^{-r}` 不能动）。全书扫描这种纯数字上标只有 17 处，逐处人眼核一遍即可
- **裸圈码转 token 必须只处理 token 外的片段**：先 `re.split` 出已有 `\ue000…\ue001` token，只对非 token 片段做圈码替换。否则 `\ue000\ue000②\ue001\ue001`（二次包裹）——症状是标记数虚高、编号全部错位（本案例 A71/B76/C72/C134 四处）
- **以标记开头的长 text 块 = 被误分类的页脚注释**：`b['type']=='text'` 且 `txt.startswith(M0)` 且 `len>15` → 从 blocks 摘出、按 y 并入本页 notes（本案例 5 处，B p47/p76/p95）。注意阈值：`len<=15` 的是「圈码 + 短标签」正文，别一起搬
- **`discarded footer` 里的成句中文是正文引导句**：`含汉字 + len>15 + 以 。！？ 结尾` → 救回 blocks（本案例 B p135 页末「我们现在使用数学方法对这些概念做更精密准确的分析。」被整句丢在 footer）
- **双栏判定只用「左右块数」，且不要加「跨栏块数量」限制**：左 = `x1<=445 and x0<250`，右 = `x0>=340`，`len(left)>=2 and len(right)>=2` 即双栏。加 `len(full)<=2`（跨栏块少）会把「小结 / 推荐阅读材料」这类**双栏夹整段跨栏导语**的页判成单栏，整节内容按 y 交错串栏（症状：小结要点乱序、文献条目与中文说明错位）。**右栏阈值取大了会吃掉答案区右栏**：本案例先写 392，右栏题号 `x0=395` 被划进左栏，题号与解答错配（`2.2` 后面跟 `1.1` 的答案）；改 340 才对。判定后给每块打 `_col` 标记，供跨页续段用
- **双栏排序：跨栏块切段，段内左→右**，并给每块打 `_col` 栏位标记。跨页续段条件写成 `prev_open and (not first_prose_done or col_changed)`——只看「本页首块」会把右栏首块误接到左栏末段（症状：答案区题号与解答错配、`2.2` 后面跟着 `1.1` 的答案）
- **答案区（“请回答”简明答案 / 奇数题号答案）**：题号是独立 `title` 块（`^\d+\.\d+$`），正文是紧随的 text 块 → `pending_qno` 合并成 `**2.6** 解答…`；「第N章」title 转 `### 第N章`。**双栏答案页必须先按栏排序再合并**，否则题号与解答张冠李戴
- **术语表**：字母标题（`^[A-Z]$`）→ `**A**` 加粗行，绝不能给 `##`（否则导航树里冒出二十几个字母）
- **图块成组输出，组内有题注才收**：连续 `chart/image` 块（中间可夹 `(a)`/`(b)` 面板标签 text 块）算一组，组内至少一张有 caption 才输出，否则整组是装饰图标/分隔条（本案例滤掉 175 个装饰块，保留 196 张真图）。面板标签按「第 k 张图之后的标签」归属，输出为斜体行
- **图面积过滤不能一律 `area>300000` 丢弃**：单幅大图会被误杀（本案例 图 5.8 补偿性差异 area=350196 被丢，症状是图号连续性检查报「图5 缺 8」）。改用「**宽度>650 或 area>450000**」判整页/跨页宽图；`图 2.4` 整组在源数据里根本没有图块（正文仍在引用），只能插〔图〕占位并写进缺图清单
- **图号连续性校验是最快的「图被误杀」探针**：逐章收集 `**图N.M …**` 的 M，必须 == `1..N` 无缺口、单调递增（脚本几行，秒级出结论）
- **中文之间的 OCR 空格要归一**：`(?<=[汉字])\s+(?=[汉字])` → 删、`第 3 章`→`第3章`、`第 11 版`→`第11版`。不归一则 `^第\s*(\d+)\s*章` 之外的层级正则（`^\d+\.\d+\s`、`^[A-Z]$`）会静默失配，标题被降级成加粗段落
- **OCR 拆开的数字要清洗公式**：`2 0 0`→`200`、`0 . 5`→`0.5`、`7 9 \mathrm{e}`→`79\mathrm{e}`。三条正则：`(?<=[0-9])\s*\.\s*(?=[0-9])`→`.`、`(?<=[0-9])\s+(?=[0-9])`→``、`(?<=[0-9])\s+(?=\\mathrm\{[a-z]\})`→``（本案例 `x ^ {2} + 0. 2 5 y ^ {2} = 2 0 0` 全靠这三条才可读）
- **保真度块级扫描必须先有显式 SKIP 清单**：本案例 201 条「源块文本在 book.md 里找不到」，绝大多数是主动跳过的封面/版权页 CIP/OCR 目录/献词页/重复的教学支持页。把 `SKIP = {(tag, pi)…}`、`FRONT`、`DEDICATION` 写成常量并在扫描时扣除，否则真丢块会被噪声淹没（本案例人工过前 30 条才确认全部是跳过页）
- **遗留 OCR 未包 `$` 的行内公式用 TEXT_FIXES 表兜底**：`e^{x}dx`、`1.41[=8/(2×2^{0.5}×2)]` 这类正文里的裸上标，写进 `TEXT_FIXES = [(old, new)]` 在 `esc()` 里先替换，别指望通用正则（会误伤 `x^{2}` 之外的场景）
- **`discarded header` 里恰好等于标准小节名的块必须救回为 title**：OCR 常把章末小节标题判成页眉（`header` 块内容就是 `推荐阅读材料`、`小结`），按「header 一律丢」会静默丢掉整节标题——本案例 4 处（第2/4/16/19章的「小结」「推荐阅读材料」）直到数导航条目才发现。判据：`re.sub(r'\s','',text) in {'小结','本章小结','练习题','分析问题','推荐阅读材料','定义'}` → 按 y 插回 blocks 当 title。**成品验收信号**：`grep -c '^### 小结'` 应等于章数（本案例 19 章 → 19 个）
- **空页说明文字也是噪声**：`The OCR result should be empty, as the image contains only…`（与 `Ground Truth image displays`、`quick brown fox` 同类）会整段混进正文，加进 NOISE_RE
- **`interline_equation` 块内嵌条目编号要摘出来**：`7. \frac{\mathrm{d}[f(x)g(x)]}{\mathrm{d}x} = …` 是「编号+公式」同一 span，直接输出会让公式带上 `7.`。判据 `re.match(r'\s*(\d{1,2}|[a-h])\.\s+(?=\\)', tex)` → 编号存 `rec['num']`，build 时先输出 `7\.` 再加 `$$…$$`
- **交付文件名必须带版本号/时间戳**（`…-v4-10271511.epub`）：连续几轮都用同一个文件名时，用户在 Telegram 里点到的往往是更早那条消息的附件，会打开旧版并据此报「没修好 / 你是不是没检查公式」（本会话真实发生，白白争论一轮）。每次交付换新名 + 同时报 md5 与字节数；用户说「还是旧的」时先对 md5，不要先怀疑自己的构建。
- **多行公式的编号回挂与对齐**：一个编号多行 / 每行一个编号的处理（含 Chromium 忽略 `columnalign` 的实测结论，别再重复试）见 references/micro-theory-11e-case.md 的「多行公式」一节
- **pandoc 数学转换失败必须显式检查，不能只看 exit code**：`pandoc … 2>warn.txt; grep 'Could not convert TeX math' warn.txt`。pandoc 只给 WARNING、把公式退化成 TeX 源码，成品里就是裸 `\frac{…}`。本案例首轮 7 处，全是两类 OCR 缺陷：①行内公式里夹圈码导致 `$d^{}$`、`$e^{}$`、`^{\}` 残缺（extract 阶段先摘标记，再 `re.sub(r'[\^_]\{\s*\}','')` 清残留）；②公式被截断（`E_{ij}=…\bigg|_{U=$ 常量` 多出一个 `$`）。修法：把失败片段写成 `POSTFIX = [(old, new)]` 在 build 末尾替换，目标 **0 条**
- **epubcheck 报 `OPF-014: The property "mathml" should be declared in the OPF file` 时**：pandoc 只给 `text/*.xhtml` 加 `properties="mathml"`，导航标题含公式时 nav 也需要 → 把 `<item id="nav" … properties="nav"` 改成 `properties="nav mathml"`。**但这条按 epubcheck 版本分裂（本会话实测）**：epubcheck 5.1.0 / EPUB 3.3 下给 nav 加 mathml 反而报 `ERROR(OPF-015): The property "mathml" should not be declared in the OPF file`。所以注入脚本默认**不要**加；只有 epubcheck 明确报 OPF-014 指向 nav 时才加，且加完立刻重跑 epubcheck 确认不是反向报错
- **保真度比值必须两边用同一个归一化函数**：先算源、再算 md，两套归一化不一致会得到 0.66 / 0.89 这种假低值（白跑一轮）。把归一化写成**一个函数** `N(s)`（剥 `[[MARK]]`、`[^id]`、`<br/>`、`![..](..)`、`^#{1,4} `、`**`、LaTeX 反斜杠、`$ { } ^ _ * 反引号 | +`、行首 `- `）对两侧同时调用，比值才可信（本案例 1.0125，>1 的差额是 23 张表的 HTML 源字符未计入源端）
- **用 OCR 的原书目录反查小节完整性（最快的「整节丢失」探针）**：目录页里 `(\d+\.\d+(\.\d+)?)\s+标题\s+页码` 提取小节清单（本案例 160 条），去空白后与 book.md 的 `^#{3,4}` 集合比对。**两边都要去掉 `$`**——标题含行内公式（`4.3 $n$ 种商品的情形`），否则报 1 条假缺失
- **豆瓣取封面必须带版次关键词**：只搜书名会返回别的版次/别的书（本案例搜 `微观经济理论` → 2005 版 + 2024 版，都不对）；`subject_suggest?q=微观经济理论 第11版` 才命中正确条目。拿到 `pic` 把 `/s/` 换 `/l/`、带 `Referer` 下载，再 `vision_analyze` 确认是平面书影还是 3D 展示图（本案例是 3D 立体图，交付时要说明）

## 变体：中译本教科书·单册拆多文件（`title` 自带 level + 图题被拆散 + 书前 OCR 目录）
- 触发：5 个左右 layout.json **按页连续切分**（本例 200/200/200/200/64 页）、`title` 块**自带 `level` 字段**（1=编/章/前置章节，2=小节）、`chart`/`image` 块题注在子块 `chart_caption`/`image_caption`、`table` 块的 HTML 在 `table_body`、书前有**多页 OCR 目录**、书末有「专业术语表 / 索引 / 译后记」
- 案例：references/samuelson-economics-19e-case.md（萨缪尔森、诺德豪斯《经济学》第19版中文本典藏版，864 页，346 图 / 115 表 / 97 公式 / 95 页脚注，epubcheck 0 error 0 warning）
- **`title` 块有 `level` 就别自己猜层级**：level 1 → `#`（编、章、章附录、前置章节、术语表/索引/译后记），level 2 → `###`（小节），`####` 只留给章末区内部的小标题。**篇和章都是 level 1，但导航树要「编 → 章」两层** → 章降到 `##`，篇保持 `#`
- **页码偏移用众数**：`offset = mode(index - pageno)`（本例 758 页一致为 42），TOC 页码 + offset 直接得 pages.json 索引，比逐页找标题可靠得多
- **书前 OCR 目录解析（`text` 块内 `\n` 多行）**：条目两种形态——`条目名 页码` 同行，或 `条目名` + 下一行纯页码。**同一本书常印「简目 + 详目」两份**，用 `编号` / `(章号, 是否附录)` / 书末名做 key 去重，否则章数翻倍、编号重复（本例首版解析出 41 章，去重后 38）
- **图题被 OCR 拆成独立块（本变体最高频缺陷）**：`chart_caption` 常整段跑出 fig 块变成 `title`/`text` 块，且**图号与标题还可能再拆两块**（`图1A-4` + `坡度不等于斜率`）。挂回判据：
  - `title` 块以 `图N-M`/`表N-M` 开头 → 一定是题注
  - `text` 块以图号开头 + len<80 + 无句号 + **图号后不接引用动词**（黑名单见上节「图题判定」）→ 题注
  - 拆开的两块先拼接（`图1A-4` + `坡度不等于斜率`）再判
  - 宿主 = 同页**最近的无题** fig/table 块；同页没有则看下一页前 6 块
  - 脚本：scripts/attach_captions.py（跑在 build 之前；幂等）
- **小节标题对齐 TOC 的四招**（本例 876 条目录 vs 正文只识别 810 条 → 补到 876）：
  1. **精确匹配要在整个剩余区间里找**（`for j in range(i, len(secs))`），只扫 `i..i+8` 会漏掉被前面块跳过的节
  2. **前缀匹配**：正文只印 `补充读物`、目录写 `补充读物和互联网站` → `sn.startswith(tn) and len(sn)-len(tn)<=6`；匹配上后**输出目录的完整标题**，不要输出正文的残缺标题
  3. **章末兜底插入**：章内 TOC 有、块流里一个都没命中的小节，按 `page_start[页码+offset]` 在对应页开头插 `### 标题`（`page_start[pi] = len(out)` 在进入每页时记）。**插入位置必须落在同页已输出标题之后**：同一页常「既有命中的节、又有要补的节」（本例 `价格指数` 命中、`总结提要` 未命中），一律插页首会把「总结提要」排到「国民账户简评」前面 → 记 `page_heads[pi].append((sec_idx, out_idx))`，插入点取 `max(out_idx for h in page_heads[pi] if h[0] < sec_idx) + 3`
  4. 被拆成两块的标题要拼起来再比对：`tn+nxt`、`tn+'和'+nxt`、`tn+'与'+nxt`
- **章末区名字必须精确匹配，不能用模糊匹配**：`反托拉斯法与效率` 与 `反托拉斯法与经济学` 相似度 >0.82，模糊匹配会把真小节吞掉 → 进入章末区后 `match_section(..., exact_only=True)`
- **概念复习的块内多行是列表**：`text` 块内 `\n` 拆行，全部 <26 字且都不以 `。` 结尾 → `- ` 列表；否则按「汉字接汉字不加空格、其余加空格」拼回整段（OCR 把一句拆两行是常态，不拼就成两段碎句）
- **问题讨论的选项粘连**（`a. … b. … c. …` 挤成一段）：正则 `(?<=[汉字。？！；：、）)"])\s*([a-f])\s*[.、]\s*(?=[汉字A-Za-z])` 命中 ≥2 次即拆段，`split()` 交替取「字母 / 文本」。**字母类必须含到 `f`**——`e.` 后面还有 `f.`，只写 `[a-e]` 会漏最后一个选项
- **表格单元格里的 `<img src="hash.jpg">`** 要转 `![](images/hash.jpg)`，否则单元格里留裸标签
- **术语表词条不是都在 `title` 块**：`text` 块首行常是「英文词条 + 中文译名」整行 → 首行加粗、其余作释义。索引的子条目（小写开头，如 `balance sheet 资产负债表，158~161`）用全角空格缩进、**不加粗**；字母（`A`/`B`）只加粗、绝不能给 `##`
- **分卷图包解压会多一层目录**：`7z x -o images images.zip` 可能解出 `images/images/*.jpg`，要 `mv images/images/* images/` 摊平，否则 `![](images/xxx.jpg)` 全部 missing（build 前先跑一次「引用到的文件名 vs images/ 实有」集合差）
- **页脚注被 OCR 拆成公式碎片**：`Y = a + bX_{\circ}`、`X < 2`、`Y =` 这类「无中文 + len<40」的块并入前一条注；否则注释条数虚高（本例 125 个 footnote 块 → 合并成 95 条）
- **多阶段改 pages.json 必须有 raw 备份 + 固定重建链**：`cp pages_raw.json pages.json && python3 merge_pages.py && python3 attach_captions.py && python3 build.py`。每次调参都从 raw 重跑，否则上一轮的合并/挂靠会叠加，越修越乱
- **`dc:date` 只能有一个**：pandoc 已生成 `<dc:date id="epub-date">`，注入出版年要用 `re.sub` **替换**而不是再插一条，否则 epubcheck 报 `element "dc:date" not allowed here`
- **带表格的书保真度比值要把 grid table 的分隔线从 md 侧剥掉**：`^\+[-+|]+\+$` 这类行、`|`、`-` 全清掉再比，否则得到 1.12 的假高值（本例正确归一化后 0.998）
- **图号正则：字母在数字后面**：`图1A-4`、`图5A-1` 这类必须写 `图\s*\d+[A-Za-z]?[-—]\d+`。写成 `图\s*[A-Za-z]?\d+[-—]\d+` 时这些题注**全部不匹配**——题注被当普通段落渲染成斜体（别处是加粗）、图号连续性检查也数不到（症状：明明有题注却报缺号，且格式不统一）。本会话因这一处漏掉 图1A-1~1A-8、图5A-1~5A-6 整批
- **图题缺口的权威判定**：`正文提到的图号集合 − fig.cap 图号集合`，**不要**用「1..max 缺号」（章末无编号装饰图、编分隔页整图、跨章同号会造大量假缺口——本例按缺号法报 18 个，按集合差只有 8 个真缺）
- **报「源数据缺失」前必须穷举四类**（用户会直接要求「你能人工审查一下吗」；实测初次只查 `cap` 就误报「11 个粘连硬拆会切错」，穷举后 18 个可恢复）：① `chart_caption/chart_footnote/image_caption/image_footnote` 子块；② 同页 `preproc` 的 title/text（题注可能整段落成独立 text 块）；③ `discarded`（header/footer/page_footnote/**aside_text**——本例表题「表7-8」就藏在 aside_text）；④ 把图块交给 `vision_analyze` 确认图内是否印有图题。四类全空才允许下结论，并**给出印刷页码清单**。**不要用「OCR 粘连、硬拆会切错」当交付理由**——那正是用户会追问的地方
- 图题错位的**六种形态与恢复方法**（题注挂到 table 的 cap 上、藏进 fig.fnote、粘在 text 块里、丢了「图N-M」前缀、被当成 title 小标题、被粘进上一段正文中间）：references/figure-caption-recovery.md
- **题注/标题被判成「脚注」或「页眉」是独立的一类缺陷，必须专门扫一遍 `discarded_blocks`**（用户会主动点出来：「可能有些图题被当脚注了」）。本例实测：`page_footnote` 里藏着 图9-3/图9-4 的整条题注+面板说明+资料来源、**7 条表题**（表16-1/19-2/19A-1/26-2/27-4/28-2/30-2）、以及**下一页正文的开头**（第6章 p131「机技术的改进…」「我们要区分产品创新和工艺创新…」，本页正文正好断在句中）；`header` 里藏着 **15 条小节标题**（「当今的混合经济」「生产函数」「政府采购」「休谟的调整机制」…，去空白后精确等于 TOC 小节名）。四类判据 + 恢复代码见 references/figure-caption-recovery.md「七」
- **`extract.py` 合并页脚注时必须保留 `y`/`x0`**：合并后只留 `{'text': …}`，后面按 y 就近挂载题注时 `KeyError: 'y'`。写成 `{'text': t, 'y': n['y'], 'x0': n['x0']}`
- **`check_caps.py` 要 cap + fnote 两边都数**（`python3 check_caps.py pages.json table` 查表题）：题注可能整条落在 `fig.fnote`（本例图30-10），只数 `cap` 会把它报成缺号，然后去「修」一个本来没坏的东西
- **`table.cap` 里会混进正文**：`表 4-1 说明了如何计算价格弹性。价格上升 20%…`（以「表N-M」开头、很短）被当表题。拆分判据：**第一句到第一个句号 ≤70 字**才算「题注标题 + 说明」，否则整块是正文，不要挂
- **跨页合并加「本页底部有图就不合并下页首块」这条会误伤**（本会话实测：修好 图27-6/图30-9 的题注，同时把 图29-7 的题注和图29-9 的图释打散，最终没收敛）。要判就判「下页首块本身是不是题注/图释」（以图号或短标题开头），不要判本页有没有图；没把握就别加这条，改为对个别页白名单处理
- **多阶段修 pages.json 时每段必须容错**：`find_block()` 找不到要 `return None` 并 `continue`，不能 `raise`——上游规则一改（挂回顺序、合并策略）块就被消费掉了，一处失配整条链断在中间，前面所有修复白跑。固定顺序：`merge_pages → fix_captions（硬编码白名单）→ attach_captions（通用规则）→ rescue_discarded → normalize_caps → build`，每次都从 `pages_raw.json` 重跑
- **双栏提要框（章末「总结提要」）按视觉行交错**：第20章 1–10 条输出成「1 → 3 → 4 → 2 → 5」的乱序（x0 124/269 两栏交替）。修法：白名单页按 `x0<200` 分栏 → 栏内按 y 排 → 栏内未结束段落拼接 → 左栏末块与右栏首块跨栏拼接 → **重排后再整体扫一遍**（单遍合并会漏掉二次可拼的）；仅对人工核对过的页生效，不要全局启发式
- **署名/题词被拆成列表项**：`——弗兰克·奈特` / `(Frank Knight)` / `《风险、不确定性和利润》(1921年)` 三块被当 `- ` 列表（判据「全部 <26 字且都不以句号结尾」误命中）。规则：`segs` 里出现以 `——` 开头的行 → 合成一条斜体署名 `*——作者 书名(年份)*`；纯条目列表的判定门槛从 `len(segs) > 1` 提到 `>= 3`

### 图题/表题整条掉进 discarded 块（第二轮实测：同一本书的补救）
- **最大教训：图题/表题会整条掉进 `discarded_blocks`，而 `chart_caption` 是空的**。只查图块自己的 caption 会得出「题注丢失」的错误结论——用户会直接指出「可能有些图题被当脚注了」。必须先做一次全量 discarded 扫描，逐块判定它到底是注释还是被误判的题注/表题/小节标题/正文：
  - 以 `图N-M`/`表N-M` 开头，且图号后面**不是**引用动词（所示/所列/描述/表明/显示/说明/演示/解释/估算/展示/运用/提供/简要/仅/表示/所/中/到/和/与/及/的/给出/描绘/呈现/列出/告诉我们/清楚/概括/总结/以/第/为/对/在/有/把/被/从/由/至/（/、/，）→ **题注**
  - 去空白后与书前目录小节名完全一致 → **被误判的 header 标题**（本案例 15 条：当今的混合经济/生产函数/政府采购/休谟的调整机制/短期的菲利普斯曲线…，之前整节无标题）
  - 本页正文末块无句末标点 + 页脚注块是长句、以汉字开头、且能跟下一页首块接上 → **被甩到上一页页脚的跨页正文**（本案例 p131「机技术的改进…」「我们要区分产品创新和工艺创新…」）
  - 剩下的、以数字或圈码开头的才是真注释
- **`[A-Za-z]?` 必须写在 `\d+` 之后**：`图\s*\d+[A-Za-z]?[-—]\d+`。写成 `图\s*[A-Za-z]?\d+` 会漏掉全部「图1A-4」「图5A-1」型图号（症状：这些题注被当普通段落渲染成斜体，而不是加粗题注）。**这个 bug 在 attach/normalize/build 三处都要改**，漏一处就静默失效
- **缺号检查的正确口径 = 「正文引用过的图号」−「已有题注的图号」，`cap` 和 `fnote` 两边都要算**（题注可能被 OCR 归到 `chart_footnote`）。用「1..max 里的缺口」会误报几十个本来就没有题注的图；本案例 242 引用 vs 235 题注，真实缺口 7 个，全部是文字整行丢失
- **题注与图释粘连在同一个 text 块**：按锚点（`在临界点`、`名义GDP的上升夸大了`）或 `\n` 拆成「标题→cap」「说明→fnote」；**拆开前先把原文按 `cl()` 清洗但存储时保留 PUA token**，否则 `$q = 0$` 这类行内公式会被剥成空
- **题注被挂到相邻 table 块**：`table.cap` 里出现 `图5A-1 …` 时移到同页图块（本案例 3 处）；反向同理，`table.fnote` 里出现 `表 16-1 …` 要移回 `table.cap`
- **题注被挂到下一章「小结」框的续文位置**（图22-11）：`fig.cap` 里装的其实是上一页「小结」段落的尾巴——用「上页末块结尾正是这段的开头」验证后拼回正文，题注另从被误判成 `####` 的 title 块取
- **TOC 小节标题补齐三招**（正文 810 条 vs 目录 876 条）：① 精确匹配要在**整个剩余区间**里找，只在前 8 个里找会漏（前面有块被跳过时）；② 前缀匹配救「补充读物」→「补充读物和互联网站」（`sn.startswith(tn) and len(sn)-len(tn)<=6`）；③ 章末按 TOC 页码把仍缺的标题插到**同页已输出标题之后**（`max(h[1] for h in page_heads[pidx] if h[0]<k) + 3`），不能一律插页首（会把「总结提要」插到「国民账户简评」前面）
- **页脚注合并后必须保留 y/x0**：`merged.append({'text': t, 'y': n['y'], 'x0': n['x0']})`。只存 text 会让后续「按 y 挂到最近图块」直接 KeyError
- **双栏提要框按视觉行交错输出**（章末「总结提要」：1、3、2、4…）：按 `x0` 分左右栏，栏内按 y 排并合并未结束段落，再拼跨栏续句。**只对人工核对过的页白名单生效**，不要做全局启发式（单栏页里的引文框也有 2 个右侧块，会误判）
- **跨页合并排除「下页首块是题注/图释」的规则不能写太宽**：`本页底部 y>380 有 fig/table 且下页首块以汉字开头就不合并` 会误伤正常续段（本案例因此丢过 图29-7/图29-9 的题注，需要回退重跑）。宁可用「下页首块长度 < 200 且本页底部图块 y > 380」并逐条核对
- **22×22 左右的 image 块是章节装饰图标**，按面积过滤；编分隔页是整页全图（`w*h > 300000`）
- **概念复习/关键术语的短行列表判定用「≥3 行且每行 < 26 字且无句号」**，写成 ≥2 行会把两行正文误拆成列表
- **卷首题词 `——作者` + 书名/年份分成 2–3 个块**：按「含 `——` 开头」合成一条斜体署名，不要渲染成 `- ` 列表
- **豆瓣封面**：`subject_suggest?q=经济学` 命中「经济学 (第19版)」id 25922243，但图是 3D 立体书影；同页其他 `s5757950.jpg` 是别的书（《经济分析基础》）。**必须 `vision_analyze` 确认书名与平面/立体**再交付

## 插图/表格的插入位置与分隔线（用户明确要求，属交付验收项）
- **用户原话**：「对于那些插入的内容要移到合适的位置，不要切断正文，同时上下加入分隔线」。杂志式排版的书（教科书尤甚）插图嵌在段落中间、正文绕图继续，OCR 按视觉行输出后段落就被切成「前半句 → 图 → 后半句」，必须重排。
- **插入组 = fig/table + 题注 + 图释 + 资料来源**，整组一起搬、绝不拆开；每组上下各一行 `---`（EPUB 里渲染成 `<hr />`）。全书 373 组实测。
- **判断「哪一段才是真正的续文」**（三步，按可靠性降序）：
  1. 前半句以 `，；：、` 结尾 → 紧随插入组之后的那段就是续文，直接拼；
  2. 前半句停在半个词上（「表示只」「特」「变」）→ 用「末字＋首字」二字组在全书出现的次数打分（`CORPUS.count(ta[-1] + hb[0])`，CORPUS = 去空白、去图片链接的全文），取最高且 ≥5 的候选；
  3. 打分前**必须**用「段首常见起首字」黑名单排除新段落（这/那/但/然/因/所/此/同/另/其/第/在/从/对/由/随/当/如/例/值/应/需/我/你/他/她/它/近/目/本）——否则「这里我们可以看到市场经济的循环」会被误判成续文，把两段粘成一句。
- **三块交织的典型**（第2章「看不见的手」）：原序 `…看似矛盾的论断，特` ｜ 图2-1 ｜ `这里我们可以看到…` ｜ `别注意一下其中看不见的手…`。修整后段落合成完整一句、图移到段后。
- **`out` 里取「上一段」要用 `out[-2]`**：`add()` 每次追加「段落 + 空行」两条，`out[-1]` 恒为空串，用它当 prev 会让整条规则静默失效（本会话第一版报「接回 0 处」就是这个 bug）。
- **重复题注去重**：同图号两条加粗题注相邻时只留一条，**优先保留不以 `。` 结尾的那条**——带句号的其实是图释首句被误当题注（本例 图26-1：「图26-1 2000年的预期寿命和收入」 vs 「图 26-1 是预期寿命和人均 GDP 的散点图。」）。去重要找上一个**非空**元素（`while k >= 0 and not clean[k].strip(): k -= 1`），不要直接取 `clean[-1]`。
- **编分隔页（第N编）后的整页插图**同样加分隔线，否则会和编名黏在一起。
- **接回只改顺序、不改文字**：源数据本身断在句中的残句（「…从网络股票到钻石，再到」「…虚线 HG」「…沿着令人满」）保持原样 + 图前有分隔线，在交付说明里列清单与印刷页码，**不猜写**。本例 89 处接回、53 处如实保留。
- 脚本：scripts/reflow_inserts.py（book.md → book_final.md；术语表/索引区自动排除，因为那是词条列表不是正文）

### 用「读」代替「猜」：直接审校成品 EPUB（用户明确要求，优先级高于一切启发式）
- **用户原话**：「你可以直接阅读epub内容来排版修复吗，你自己思考判断，而不是完全用py脚本的形式」。**位置/归属是语义判断，必须自己读原文**；脚本只用来把上下文导出成可读报告。本会话按「首次提及」纯启发式重排 279 组，反而把图搬错段落（用户下一轮就说「你对插入部分的内容判断不是很准确」）。
- **审校对象是成品 EPUB，不是 book.md**：解包 → 按 xhtml 的真实文档顺序取元素序列（`p/h1–h4/table/hr/blockquote/ul`）→ `<hr>` 成对切出插入组 → 每组导出「前 3 段 / 组内各块（图片、题注、图释、表格首行）/ 后 3 段」→ 逐条读（本例 373 组 ≈ 4700 行）。脚本：`scripts/dump_insert_context.py`（同时打印四类可疑信号统计）。
- **四个机器可判的信号**（只用来挑可疑项，判断仍要人读）：A 组紧跟 `h1–h4` 之后；B 组前段落无句末标点；C 组前没有任何正文（章首）；D 组后首段以接续式字开头（的/了/着/而/就/也/还/又/则/是/别/格/化/性/者/所/以/为…）。
- **B 类不能一律当 bug**：教科书正文本来就跨表格——「表 1A-1 列出了 ｜表｜ PPF 的基本数据」「在图 1-1 的横轴上向右量取 5 个单位的黄油，在纵轴 ｜图｜ 上向上量取…」。本会话 47 处 B 类里多数属正常排版，强拼会改坏原文；**只有「组后首段明显是半句续文」时才动**。
- **重排规则**：插入组紧跟「本章内第一次提到该图号/表号」的段落之后；同章多组按出现顺序处理、目标位置单调不减（这样「图 1-3 到图 1-5 给出了…」一句提到三个图时，三组会依次落到各自段落之后）。章边界用 `## ` 切；同章内不要回退锚点。
- **⚠ `[图表]` 共用一个字符类会让「图1-1」和「表1-1」互相命中**——本会话唯一一个「修完比修前更糟」的 bug：第一版重排把图1-1 搬到表1-1 前面。必须 `re.escape(kind) + r'\s*' + re.escape(no) + r'(?!\d)'`，图/表分开匹配。凡按编号定位，**编号前的主字（图/表）必须参与匹配**。
- **题注被复制进正文**：句中出现「…看看表中的**表 3-5 均衡价格发生在需求量等于供给量之处表中显示了不同价格水平上的供给量和需求量。**」= 题注整条混进句子。判据：句中 `图/表N-M` 之后紧跟的 ≥6 字片段与该号题注相同 → 从正文切掉；正文恢复成「…看看表中的 D 行便可以发现，在 2 美元的价格下消费超过了生产。」
- **句子被图切成两半的英文残句**：`需求向下倾斜规律（law of downward sloping` ｜ 图3-2 ｜ `demand）：当一种商品的价格上升时…`。判据：后段以 `demand/upply/ply/emand）：` 这类英文残词开头 → 与上一段直接拼接。
- **一组里混了两个图**（图1-2 组里还带着图1-3 与两个面板标签）：OCR 把相邻图块并成一组。这是**多面板图**被拆散的典型症状，按下一节的方法重建，不要只加分隔线糊过去。

### 多面板图重建（一组里混了两个图 / 面板标签张冠李戴）
- **触发**：教科书里大量插图是「一张图由 (a)(b)(c) 几个面板拼成」。OCR 把每个面板识别成独立 fig 块、面板标签挂到相邻块上，成品里表现为：面板被正文隔开、(a) 标签出现在 (b) 的图上、同一行的 (b) 排在 (a) 前面。
- **必须回原始 layout 取坐标**，不能只改 book.md：fig 块的 `bbox`，以及 `chart_caption`/`image_caption`/`chart_footnote`/`image_footnote` 子块**各自的** `bbox`（题注的 y 与图的 y 不是一回事，用图的 y 归组必然错）。脚本：`scripts/rebuild_panels.py`（跑在 build 之前，直接改 pages.json）。
- **四步**：① **去重**——同页某图块 ≥80% 面积落在另一更大图块内即视为重复裁切（本案例 图8-12 = 「第一人+第二人」整图 + 它的左半/右半裁切共 3 块，交 `vision_analyze` 看图确认），丢弃并把题注/图注并入保留块；② **题注归属**——竖向距离 `min(|图底−题注y|, |题注y−图顶|)` 最小者胜，**要求横向重叠**，无重叠时只允许「题注纵向严格在图内且紧贴图的左右边缘」的侧边题注；③ **面板标签**——只用原始数据里真实存在的 `(a)/(b)/(c)`，缺就留空**绝不臆造**；④ **排序**——先按 y 重叠 >50% 聚成行，行内按 x 左→右，行间自上而下。
- **`inside`（侧边题注）判据写松会互换题注**：本案例 `f['y']-5 <= c['y'] <= f['y']+f['h']+5` 让下方题注也被当侧边题注，图1A-5 与图1A-6 的题注对调（两图并排、题注 y 只差 16px）。收紧成「纵向在图内且横向紧贴边缘」才正确。
- **面板标签常被 OCR 混进正文段**：整段以 `(a)` 开头且含句号的 text 块 → 其实是该页图的**图释**（转 `fig.fnote`）；段末粘着 `(a) 史密斯的需求` → 拆出来当面板标签。**标签在页末、图在下一页时**要跨页归位（`y=-1` 占位，到下一页取 `min(fig.y)-5`），否则那一组永远是「无标签」。
- **重建会丢掉前面步骤修好的题注**：`rebuild_panels` 从原始 layout 重读题注，`fix_captions` 塞进 `fig['cap']` 的修补全被覆盖 → 必须先把 `fig['cap']` 里已修好的题注并进候选池（按图号去重）。症状：图号缺口从 1 个反弹回 4 个。
- **同图号两条题注时，带句号的那条是图释**：题注是短标题不以 `。` 结尾；以图号开头、含句号、较长的其实是图释首句被误当题注（图8-4「图 8-4 用两个企业的情况来说明这一点。…」）。合并成一个单元，长的降级为 `fnote`。
- **必须原地替换，不能 `blocks = 非fig块 + units`**：追加到页末会让整组图跑到该页所有正文之后（本案例 图1-3 一度落到页底）。建 `fig→unit` 映射，遍历原 blocks，首个成员位置放 unit、其余成员跳过；被去重丢弃的块也要显式跳过，否则残留半幅裁切图。
- **面板标签文字与图释重复**：面板标签用的是 `(a) 消费者的需求` 全文时，图释里同一条 `(a) …` 要跳过，否则同一句出现两次。
- 验收：`正文引用编号 − 已有题注编号` 归零（`scripts/check_caption_completeness.py`）+ 抽 2–3 个多面板组交 `vision_analyze` 读图确认面板数与内容对得上。

### `reflow_inserts` 的致命 bug：接回续文时丢掉夹在中间的插图
- **症状**：全书图片引用数从 344 掉到 337，成品缺 7 张图（图28-4、图24-4、图22-7 等），而所有校验都是绿的（epubcheck 0 error、链接全通）——**只有「改前 vs 改后的图片哈希集合差集」能发现**。
- **成因**：把插入组后的续文提到前面时，只保留了 `range(j, pick)` 里的 `text` 块（`between = [blocks[x] for x in … if ks[x]=='text']`），夹在中间的 fig/table 块被静默丢弃。
- **修法**：保留**全部**中间块（`[(blocks[x], ks[x]) for x in range(j, pick)]`），并给其中的图/表加分隔线；相邻的 `---` 合并成一条（`if ln.strip()=='---' and out[-1].strip()=='---': continue`），否则出现 `---`/`---` 连排。
- **通用教训**：任何「重排/提升段落」的 md 后处理，都要在改完后跑一次**图片与表格的引用集合差**（`set(改前) - set(改后)` 必须为空），不要只看 epubcheck 和字符数——字符数几乎不变，因为丢的是图不是字。
- **编分隔页上「第一编」会重复两次**（`# 第一编 …` + 紧随的 `第一编` 正文块），去重条件：`text` 块全匹配 `第[一二三四五六七]编` 且前一块是 `#第…编`。

## 管线（两阶段，便于分步调试）
1. extract.py：layout.json → pages.json（过滤噪声、合并多块脚注、分类标记）
2. build.py：pages.json → book.md（标记替换、跨页合并、类型状态机、脚注配对）
3. pandoc：book.md → EPUB

## 多文档合并（同一本书分多个 layout.json）
- 每部分独立跑 extract/build（tag 前缀区分：第一部分 `pXX-N`，第二部分 `p2-XX-N`）
- 合并：正文区拼接 + 脚注区拼接（去重）；注意：
  - 第二部分封面标题去掉，从 `---` 后开始接
  - 两个 `## 脚注` 区合并为一个
  - 层级修复（如 `## C. 尺度` → `### C. 尺度`，与第一部分同级）
  - 标题上的脚注引用（如 `# 第一版序言[^p15-1]`）移到正文首段，否则删标题时引用丢失
  - 合并后统一补标题前后空行（pandoc TOC 识别）
- 验证：§ 跨部分连续无缺失（如 §1-244）、脚注总数 == 两部分之和
- **去除 OCR 原书目录区**（用户要求）：正文中 OCR 提取的原书目录（`# 目录` 到 `# 总序` 之间，带 "…… 1" 页码的条目列表）整块删除；EPUB 阅读器导航目录由 pandoc `--toc` 自动生成，不受影响。删除逻辑固化进合并脚本防重建复活

## 关键步骤
1. **探索**：页数、块类型统计、脚注标记分布、书前页/目录/正文/索引的页区间（FRONT_PAGES / TOC_PAGES 规则）
2. **提取**：过滤 Ground Truth / "quick brown fox" 噪声；脚注按标记分类（circled/stars/dstars）；无标记续行并入上一脚注
3. **构建**：
   - 跨页段落合并：页末块以非终止标点结尾 → 续接（TERMINAL 正则 `[。！？….!?]["」』”’)\]]*$`）
   - **类型状态机**（用户核心规则）：每个 § 内，正文持续到 [说明] 出现，[说明] 持续到 [附释N] 出现，[附释N] 持续到下一类型或 § 结束
   - **同类型连续段落合并为一个引用块**（用户最终确认的规则，勿再改回独立渲染）：首段带标签（`> **说明**`），后续同类型段落用 `>\n>\n> 正文` 保持在同一 blockquote 内；块内段落间用 `>` 空行分隔（保留段落感），块与块之间用空行分隔
   - **格式投诉排查顺序**：① 先确认用户下载的是最新文件（/tmp 副本可能过期——md5sum 对比！本会话用户两次因旧版误报格式问题）② 再查 pandoc 空行（§ 标题/引用块/`#` 标题前后缺空行会粘连成一段或渲染成字面 `&gt;`）
   - § 标题渲染为 `**§ N**`；章节标题按层级 `#`/`##`/`###`
   - 脚注引用 `[^pXX-N]`（页码-序号），定义集中在文末"## 脚注"区，按 (页码, 序号) 排序
   - **注中注**（脚注内引用其他脚注）：定义内联展开，否则 pandoc 转 EPUB 时定义丢失
4. **EPUB**：`pandoc book.md -o out.epub --metadata title=... --metadata lang=zh-CN --toc --toc-depth=3 --epub-chapter-level=2`

## 陷阱
- **终止符字符类里不要放引号/括号（本会话实测）**：把 `”』」）` 也算作终止符时，以「…还远远早于"冷战"」结尾的段落被判为已结束，下一页的「的结束、原共产主义经济体的…」整段不合并，且不报错。**终止符只认句末标点**：`([。！？…；：!?])[”’』」）)\]]*$`——引号括号只允许作为**尾随字符**，本身不算终止（与下面「必须含全角括号」那条并存：括号出现在句末标点之后才是正常收尾）
- **TERMINAL 正则必须整条锚定在句末（`$` 只加在最后一个分支上＝没锚定）**：写成 `r'[。！？…]|\.["”]?$'` 时第一个分支没有 `$`，`re.search` 会匹配段中任意位置——于是任何**句中含 `…`** 的段落都被判为「已结束」，跨页断行整段不合并（本次症状：总序首段 `…教育事业的快速` + 下一页 `发展，国内…` 没接上，且不报错）。正确写法把两个分支包进一个组：`r'([。！？…”』」）)\]\】：；]|[.!?])["”’』」）)\]]*$'`。**改完用 3 行断言自测**（`ends_terminal('…快速')` 必须 False）。
- **教科书类任务第一步就导出图片清单发给用户**：layout.json 只给哈希名，图永远不在本机，用户找图/传图是最长的外部等待。先把唯一 `image_path` 列成清单发出去（顺带说明「放哪、怎么压」），再回头跑 extract/build——本次把索图留到最后，结果 build 全绿却交付不了。
- **保真度比值 >1.01 先查「重复渲染」而不是「丢块」**：图题既被 `image_caption` 配给 fig 块、又作为正文短行输出，会让比值升到 1.017；比值 <0.97 才是丢块。
- **工作目录含 PDF 二进制时 terminal 命令报 "embedded null byte"**：Hermes 生命周期守卫会扫描命令引用的脚本/目录，遇到 PDF 等二进制文件抛 `ValueError: embedded null byte`（exit -1）。绕过：用 execute_code 的 `subprocess.run([...])` 跑命令，或把 PDF 移到独立目录（如 /tmp/enpdf/）再操作
- **交付前必须同步 /tmp 副本**：重新生成 EPUB 后 `cp` 到 /tmp 并 md5sum 对比；用户通过 Telegram 下载的是 /tmp 路径，旧副本会导致用户看到旧格式并误报"格式乱了/换行没了"（本会话两次因此误报）；**改了 extract.py 必须重跑 extract.py 重建 pages.json**——只跑 build.py 用的是旧 pages.json，改动静默无效，交付出去还是旧内容
- **文件过大投诉：先看字节数再下结论（本会话教训）**：Telegram 机器人收发上限 **20 MB**。用户上传超限时平台回执会作为**入站消息**转给 agent（"The document is too large or its size could not be verified. Maximum: 20 MB."），gateway.log 同时记 `[Telegram] Document too large: <bytes>`。**先拿日志里的字节数跟自己发出去的/对方声称的文件大小比对**——本例 115,269,237 字节显然是用户那个 zip 被拒，不是自己 841 KB 的 EPUB 投递失败（曾误判成"中文/全角文件名导致投递失败"并白白换名重发一次）。用户说"文件已发给你"而 `~/.hermes/cache/documents/` 里没有新文件时，先查 `grep 'Document too large' ~/.hermes/logs/gateway.log` 再回复，别让对方重复上传
- **`<br>` 必须写成自闭合 `<br/>`**：markdown 里的裸 HTML `<br>` 会被 pandoc 原样输出到 XHTML，`xml.etree` 解析报 mismatched tag（EPUB 校验才暴露，pandoc exit 0）。诗行/署名行分组时尤其容易踩。
- **raw HTML 表格内的脚注要用 HTML 锚点**：pandoc 不解析 raw HTML 里的 markdown（表格单元格里的 `[^id]` 不会生效）→ 星号表注写成 `<a href="#tn{页}-{i}"><sup>&#42;</sup></a>` + 表后 `<a id="tn{页}-{i}"></a>` 注释行；同一条注被两格引用时**复用第一个锚点**并只输出一次注文。
- 案例：references/sweezy-capitalist-development-case.md（斯威齐《资本主义发展论》三册合订；**`table` 块的 HTML 在 `table_body` 子块里，`spans(b)` 直接取会拿到空 → 表格全部静默消失**；`html_table_to_grid()` 返回二维 list 要再 `grid_to_md()`；表题/表注在 `table_caption`/`table_footnote` 子块；**行内公式里的脚注引用不能被包进 `$...$`**（MATH 先存私有标记、token 阶段剥引用，否则相邻公式的 `$` 会配错把正文吞进公式）；`wrap_math` 花括号未配平要继续右扩；半角括号 `(1946年）` 要成对处理；插图判定 `area>400000`）
- **诗行（引诗）分组**：同页/跨页连续的短块（≤34 字且含中文标点）合并为一段、行间用 `<br/>`；跨页要按**节点流**分组而不是按页（否则一首诗被页边界切成两段）。**小标题判定要把「以 `……`/`——` 结尾的行」排除，但不能整体排除 `—`/`·`**——否则 `“堪萨斯—内布拉斯加法案”`、`德雷德·斯科特案件的判决` 这类小标题会被降级成正文（实测踩过）。
- **Python `'' in CIRC` 为 True**：空字符串匹配任何字符串！classify 时须 `marker and marker in CIRC`，否则无标记脚注（如 "8。"）被误存
- **pandoc 块识别需要空行**：`**§ N**` 标题、`> **说明**` 引用块、`#` 标题前后都必须有空行，否则 pandoc 把它们并进前一段，渲染成字面文本（`&gt;`）或整段粘连——render 函数里每个段落/标题后都要 append('')
- **pandoc 段落开头数字+点 → 有序列表**：段落以 `2. ` 开头会被解析为 `<ol>`，且段内 `(a) (b)` 子项会嵌套列表导致标签不匹配（XML 校验报 mismatched tag）。修复：render 时 `re.sub(r'^(\d+)\.\s', r'\1\\. ', text)` 转义
- **pandoc `<sup>*</sup>` → 强调解析**：`<sup>*</sup>` 中的 `*` 被 pandoc 当强调标记，输出 `<sup><em></sup>` 不匹配标签。修复：星号上标用 HTML 实体 `<sup>&#42;</sup>`（数字上标不受影响）
- **EPUB 双向跳转脚注（用户要求，勿只输出死文本上标）**：用户问"脚注注释没配置？"说明上标必须是**可点击链接**，不是纯 `<sup>` 文本：
  - **markdown 阶段生成锚点链接**（mdgen.py）：
    - 正文数字标记：`<a id="chN-ref-M" href="#chN-note-M"><sup>M</sup></a>`（id 是返回锚点）
    - 正文星号译注：`<a href="#chN-tr"><sup>★</sup></a>`（本章译注区）
    - 章末注释：`<a id="chN-note-M"></a><sup>M</sup> 文本 <a href="#chN-ref-M">↩</a>`（↩ 返回正文）
    - 译注区标题：`#### 译注<a id="chN-tr"></a>`
    - 导言（ch0）正文无标记 → 注释不加 ↩（避免死链）
  - **必须 `--epub-chapter-level=2`**（pandoc 2.17 用 `--epub-chapter-level`，不是 `--split-level`）：不拆章则正文+注释全在一个大 xhtml，锚点反而有效但文件巨大；拆章后跨文件锚点需要 post-process
  - **跨文件锚点修正脚本**（pandoc 拆章后同一文件内锚点变跨文件）：解包 → 建 `id → 文件` 映射 → 每个 xhtml 内 `href="#id"` 若目标在其他文件则改为相对路径 `posixpath.relpath(target_file, dirname(cur_file))` → 重新打包
  - **锚点命名必须全书全局唯一（第三套实测）**：节用真实节号 `s{sec}-ref-{N}`（跨章唯一），章用运行章号 `c{idx}-ref-{N}`，附录 `a-{page}-ref-{N}`。**每章重置的节索引做锚点会严重重复**（s1-ref-1 出现 6 次、s20-ref-1 4 次、c6-ref-1 2 次）。正文/注释双向链接在 markdown 阶段生成（mdlinks.py 模式）：正文 `<a id="s{sec}-ref-{N}" href="#s{sec}-note-{N}"><sup>{N}</sup></a>`、注释条目 `<a id="s{sec}-note-{N}"></a><sup>{圈码}</sup>{文本} <a href="#s{sec}-ref-{N}">↩</a>`；附录条目解析 `[页码]` 前缀，正文标记 `[[MARK:pg-N]]` 拆 page+num。生成后立即用 `Counter` 校验：重复 id == 0 且 href 目标全部存在
  - **校验路径陷阱（第三套实测）**：nav.xhtml 的 TOC 链接 `text/ch001.xhtml#标题` 相对 EPUB/ 根而非 nav 所在目录——校验时 `os.path.join(WORK, parts[0])` 失败须 fallback `os.path.join(WORK, curdir, parts[0])`，否则 TOC 全报假错（108 条 parse fail，实际 0 错）。跨文件 href 修正只改 `href="#id"` 形式的锚点，`href="file#id"` 已带路径的不动
  - **验证**：所有 `href="file#id"` 目标解析（相对当前文件目录）后存在且 id 存在；nav.xhtml 的 TOC 链接按 `EPUB/` 为基准解析；输出统计：前向链接数、返回链接数、无效链接应为 0

- **德文标题结构提取**：hegel-system.de 的标题常挤在一行（"A Das Wesen als Grund der Existenz a. Die reinen Reflexionsbestimmungen a. Identität"），用 `re.split(r'\s+(?=[abc]\.\s)', t)` 拆分；再找标题行后第一个 § 编号定位归属

- **§ 标题层级（用户确认）**：`**§ N**` 保持加粗段落格式（模拟原书黑体），不进 EPUB 目录（`--toc --toc-depth=3` 只收录 `#` 标题层级）；用户否决了改为 `#####` 标题的方案——勿再改成标题层级

## 表格与双栏页（中译本高频翻车点，用户会直接指着某一节说「格式有问题」）
- **grid table 列宽必须按显示宽度算**：`len(c)` 把中文当 1 列，中文单元格溢出到相邻列，pandoc 把整行拆错——成品里出现 `<td>| 实</td><td>际GDP | 模型</td>`、`<pre><code>| 内生变量</code></pre>` 这种残片。修法：`unicodedata.east_asian_width(ch) in ('W','F')` 计 2 列，`' ' * (w - 1 - dw(c))` 补位（不是 `ljust`）。**表格看起来「没对齐」就是这条**，不要去改 CSS 或换 pipe table
- **单元格里的裸 `<` 会被 HTMLParser 当标签开头吃掉**（`Y<C+I+G` 之后整段消失）：白名单标签之外一律 `&lt;`。源数据里还常见 `<eq>x</eq>` 包公式 → 先转 `$x$`，否则标签被剥掉只剩文字
- **跨页续表合并：删重复表头会造出非法 grid table**。两张表各自 padding 宽度不同，只删第二张的头两行 → pandoc 静默降级成一段文本。正确做法：取两张表的 rows，`grid_to_md(rows_a + rows_b[1:])` 按统一列宽重新渲染。判定条件收紧为「两表之间除空行外别无他物 + 表头去空格完全相同」
- **表格校验要有机器判据**（`validate_epub.py` 只数表格个数，看不出拆坏）：解包后遍历每个 `<table>`，若去掉标签后正文里还有 `|` 或出现 `<pre>/<code>` → 该表拆坏了；再查每行 `<td>` 个数是否一致（ragged 行）
- **grid table 单元格必须单行，绝不折行（本会话踩过）**：为了控制列宽而把长单元格切成多行（`wrap_cell`），pandoc 会把多行合并成一个单元格但**插入空格**（`马克思的资本分 类`），且 `check_grid_tables.py` 报满屏「行宽不对齐」——因为多行渲染时 `+` 分隔线位置与单行行宽不一致。正确做法：**列宽取该列最大显示宽度，不设上限、不折行**（宽表交给阅读器横向滚动即可）；窄屏可读性不是这里的优化目标
- **OCR 会把整列零值错读成一串 `. 0. 0. 0. …`**（实测表 A-1/A-9 一整行 33 个 `. 0.` + 结尾 `. 15`）：这是**信息已丢**，不要拼成数字。判定 `c.count('. 0') >= 5` → 输出 `⋯` 并在交付说明里列明；单格变体可安全清洗：`.0.00000`/`. 0.00000` → `0.00000`、`. 15` → `0.00015`、纯 `[. 0]+` → `0.00000`
- **逐表 pandoc 验证（比 `check_grid_tables.py` 更硬）**：`scripts/check_tables_pandoc.py`——把 book.md 里每个 grid table 单独喂 pandoc，断言 ① 渲染出 `<table>`（否则被降级成文本）② 每行 `<td>` 数一致（无 ragged）③ 剥标签后无 `|` 残留。实测 33 张表全绿才算通过
- **双栏页排序：纯列优先会把右栏内容排到下一节标题之后**。症状：1.3 的「复习题 3」跑到「问题与应用」之后、术语表条目跨栏错位。修法：以本页 title 块的 y 为锚点先分「所属小节」，组内再「左栏 → 右栏 → 跨栏」三档排序（`col_of(r)`：`x1<=270` 左、`x0>=230` 右、其余跨栏且排该节最后）
- **跨栏续文要合并**：左栏末块没有终止标点 + 右栏首块不是新条目（`^\d+[.、]`/`^[A-D][.、]`/`^[a-d][.、]`）→ 直接拼接，否则「用供给和需求模型解释冰冻酸奶价格的下」和「降会如何影响冰激凌的价格」会分成两段
- **双栏 OCR 交错（信息已丢，只能白名单修）**：有些页整块只有一个 span、line 没有独立 bbox，左右栏按视觉行合并成一串（`A. 盈余，升值  B. 盈余，贬值  A. 减税  B. 投资增加`），栏位信息彻底不可恢复。**只在能 100% 确证时手写修正表**（题干齐全 + 选项按内容与题干一一对应），并在 build 里用 `assert got == want`（原始片段集合 == 重构片段集合）守住；对不上的页（题干跨页被截断）保持原样，不要猜
- **章末双栏区（复习题/问题与应用/关键概念）的选项必须显式拆行**：只有标成 quiz 的块才走选项格式化时，`问题与应用` 的 `A. … B. … C. … D. …` 会全糊成一行（用户会指着说「左右两版内容混在一起、有些内容没有换行」）。判定放宽成「块内 `(?<![A-Za-z])[A-D]\s*[.、]` 出现 ≥2 次即当选项块」，再按序切：题号粘上行尾、题干与选项粘连（`…是多少？A.0.02`）、选项间只隔 2+ 空格。**切完再逐个 `fix_text`**——`fix_text` 会把 `1. ` 转义成 `1\. `（防 pandoc 有序列表），先转义就再也匹配不上题号
- **选项字母会 OCR 成乱序**（`A. / D. / C. / D.`）：一组正好 4 个选项时按位置重写为 A/B/C/D；相邻两个纯选项块（A/B 一段、C/D 一段）要合并；题干跨栏被切成两段且短的是长的前缀时丢短的
- **`discarded_blocks` 的 header/footer 默认应当作正文救回**：用「含句末标点且 len>40」这种白名单捞正文会静默丢整段（章末双栏区的提要/小题/图注常常整块落在 footer 里）。正确做法是**黑名单**：只排除确属版式的行（书名、`第N章…`、`第N篇…`、页码、`续表`、`Preface/Contents`、出版社网址、源 PDF 混进来的别本书文字），其余全部按 y 排回正文流；header 里无句读的短行判 title。改完必跑「discarded 块去空白后是否出现在 book.md」的丢失清单，噪声扣完应为 0
- 案例：references/mankiw-macroeconomics-11e-case.md
