# 案例：格兰茨《巴巴罗萨脱轨》第一卷（中译本，4 册 705 页）

**形态**：4 个 layout.json（200/200/200/105 页）+ 分包图片（images.z01–z05 + .zip，6 卷、120 图）；
章末数字「注释」13 处共 647 条（每章从 1 重编）+ 页脚圈码译者注 96 条；12 章、44 个小节、8 个附录、参考文献；60 张表（多为 `rowspan/colspan` 作战序列长表）。

## 差异清单（换书会再遇到的已归入机制篇）

1. **四册顺序＝A p1–170 → C p171–370 → B p371–570 → D p571–673**（A、C 册名与页码完全错位）。
   定序依据：每册 `printed` 中位数偏移（A −29、C +171、B +371、D +571）。A 册 pi<30 是罗马数字前置页，`printed` 必须置 None，否则前置页被算进正文页号。
2. **章标题块三种形态**：`text` 单列「第七章」+ 紧随 `title(1)` 才是章名／`title(1)` 带「第N章」前缀／章名不带前缀。
   **第八章章名在源数据里整体缺失**（p392 是上一章注文、p393 直接是「总统帅部大本营重组」），只能按目录补章名，否则第八、九章并章。
3. **章锚点被当成小节锚点会吞掉首个二级标题**：第八章锚在该章首个 `title(2)` 上，补章名后必须再补一个 `<h2>总统帅部大本营重组</h2>`。
4. **小节标题在 `title` 与 `text` 间摇摆**（「渡过第聂伯河」「西方面军战役集群的反突击」「施图梅集群的进攻」等 5 处是 `text`），定位要 page+文本双匹配，不能只认 `title`。
5. **两套注释都在章末**：`注释`（数字）与页脚圈码（译者注）分列，各 647 / 96 条。页脚注文有 1 条印在相邻页，配对要允许 ±1 页回退。
   ⚠️ 修正上一版结论：初版报「96 条里 33 条正文无圈码」是**我自己的渲染路径丢的**——表格 `<eq>` 圈码 22 条、表题 1 条、注释条目正文 7 条、第九章首頁归属错 1 条，真重复只有 1 条（p23 同页同号）。四条路径与修法见 `references/missing-marks-recovery.md`「自身管线自查」。修完 96/96 全部建链。
6. **块尾裸数字是唯一能机械捞回的上标形态**：`…”8` / `。45` / `。44`（17 处）都在块尾、无空格。句末标点后的裸数字（`”2`、`、7`）经核全是日期或数量词，不可用。
7. **正文表格里藏注号**：作战序列表用 `<eq>^{1}</eq>`、`<eq>^1</eq>`、`<eq>^{\text{1}}</eq>` 三种写法（32 处），extract 若只统计 text 块会把这批落点判成「缺号」。
8. **附录一图版页的编号说明被 OCR 当成 `page_footnote`**（`1. 霍缅科集群…` 共 9 条）：它们不是译者注，要按图版题注发回正文，否则既丢题注又多出 9 条孤儿译注。
9. **封底广告混进参考文献**：D p674–675（「指文图书®」「上架建议：畅销书·军事/历史」+ 2 张二维码）必须按页截断。
10. **串页噪声**：D p578 整页只有一句无关文字（「2017年1月1日，公司与上海浦东发展银行…」），按块白名单剔除。
11. **50 处缺标里 33 处是语义可补的**：用户看了第一版（「不猜」）后直接说「这些注释你自己人工审查原文应该能补上吧」。逐条读注文＋窗口（做法见 `references/missing-marks-recovery.md`）补回 33 处，剩 17 处是「同上/泛引资料」且落在长引文中段。补的过程中顺手抓出 2 处号型误读：**A p30 的圈码 ⑩ 实为注 10、A p31 的 `^{[1]}` 实为注 11**——它们以前被算进「缺号」，其实是数字被读成了圈码/带括号数字。
12. **注释区里夹着一张图/表时**（附录表注、章注里的损失统计表），注释渲染要按「该条注文 + 其下的表格」成组输出，不能只读文字块。

## 本次实测数字

- 705 页、正文块 4767、`book.md` 78 万字符、成品 EPUB 18.3 MB（Telegram 20 MB 内）
- 注释 647 条：v1 落点 601（50 条无落点）→ v2 落点 630（33 条语义补插）→ **v3/v4 落点 647（另 17 条由用户给锚句，含 3 处号型改判）**；译者注 96 条 **全部建链（102 个圈码引用）**，其中 22 条来自表格 `<eq>`
- 用户给锚句的形态：`注号：原句片段`（可带 `^{[1]}`／`” 实为4` 这类「号型实为 N」的批注），按锚句「句末」落位、连标点一起跳过再插

- epubcheck 5.1.0：0/0；内部链接 1491 条无效 0；xhtml 28 个

## 引文（blockquote）阶段（v5，用户第二轮追加要求）

用户原话：「对于书中引用的部分使用 md 的引用格式，特征有：1. 上一段以：结尾 2. 内容是引用的指令、指示、报告等。**你人工审查来解决**。」

- **判定口径**：引导句以全角冒号结尾 + 后接文件正文（命令、训令、作战摘要、报告、电报、回忆）。共 **127 处 / 193 个 blockquote**（多块因引文内夹小节标题或图表而拆开）。
- **不能用「上段以：结尾」单条规则**：这本书筛出 317 条候选，其中一大半是引文内部的小标题（`★步兵第51军：`、`· 7月25日21点——第20集团军`）——它们本身就是 doc 行，必须先用 `is_docline()` 排除。
- **边界判定是人工活**：状态机只负责「起」（上段冒号 + 非 doc 行 + 下一块非标题）和「止」（叙述信号词 / 新小节标题），**但以「因此」开头的整句也可能是文件正文**（希特勒第21号指令那条尾巴被切掉，靠人工复核补回）。交付时把 127 条的「起句/止句/下一段」写进 `引文清单.txt`，并在说明里主动写「仍可能有 2–3 处多吃一段，指出来就改」。
- 两个已经踩过的实现坑（详见 M6）：`spans_for(ci)` 忘按章过滤（第一章叙述段被吞进引用块）、引文块参与跨页合并（页末引文与下页叙述粘成一段）。
- CSS 用左竖线（`border-left: 2px solid #b9b9b9`）+ `text-indent: 0`；引文体内的 `·`/`★`/`☆`/`（签名）`/日期行原样保留。

## 用户的交付节奏（本书实测）

四轮追加需求，每轮都是一次「不猜 → 补 → 再补 → 改版式」：① 先出 v1（50 条缺口如实报）→ ② 「你自己人工审查原文应该能补上吧」（补 33 条）→ ③ 用户给 `清单.md` 锚句表（17 条，含 3 处号型改判）→ ④ 「引用的部分使用引用格式」。**先交可校验版、同时给出缺口清单，比一次求完美更快收敛**；用户从不介意多轮，但介意「把源缺当结论」。

## 管线（本书直接复用）

`extract.py`（块+页脚注+页号）→ `structure.py`（目录解析 + 显式章/节锚点表）→ `notes.py`（条目 1..N 完整率核对）→ `build.py`（HTML 直出：`<h1>/<h2>/<div>`）→ `pandoc -f html -t epub3 --toc --toc-depth=2 --epub-cover-image` → `epubcheck`。
全部在 `/root/book_nov02/`，`gaps.txt` 是「缺号＋注文＋上下文」候选表（给用户填锚句用）。
