# 方法记录：OCR 整处丢标的「语义补位」（不是源数据缺陷就收工）

> 什么时候读：章末/尾注条目齐全、但正文某些号找不到上标（`缺口清单` 非空）时。
> 与 M3 配合读；这是「补不补」的判定顺序，不是选做题。

## 用户口径（硬约束）

- 先把「注文齐全、正文无标记」当**待办**，不是当结论。实测用户原话：「这些注释你自己人工审查原文应该能补上吧」——直接把 OCR 丢标写成「源数据缺陷，未做任何补插」会被打回。
- 正确的交付顺序：**机械捞回 → 语义补位 → 剩下的才进缺口清单**。缺口清单是残留清单，不是第一版产物。
- 补出来的落点必须能逐条核对：随成品给一份「补插清单」（章 + 注号 + 锚句末 20 字），用户会拿书对。

## 三步做法（可机械执行）

1. **导出候选窗口，不做判断**：逐章列出「缺号 + 注文全文（截 150 字）+ 前后两个已知标记之间的全部块（截 230 字）」。窗口天然很窄（注号严格递增，缺号只能落在 n−1 与 n+1 之间），这是安全的根源。
2. **逐条读注文，认它指向哪类东西**，再在窗口里找那一句：
   - 具名档案/训令/命令（「第00455号训令：关于以坦克加强战役集群」「大本营第270号令」「第110号作战摘要」）→ 落到正文**描述这条命令**的那句末尾。
   - 具名日记/回忆录（《哈尔德战时日记》《博克战时日记》、霍特《装甲作战》）→ 落到**叙述该判断**的那句末尾。
   - 人名/地名/编制注 → 该名字**首次出现**处。
   - 纯页码型（「同上，第1020—1021页」）且窗口内没有明显对应句 → **不补**，进残留。
3. **锚句必须唯一**：`md.count(anchor) == 1` 才插，多于 1 条就换更长的句子；插在锚句之后。

## 报「缺」之前的自身管线自查（第二轮实测：33 条「缺」里 32 条是我自己丢的）

用户第二次的原话是「你自己审查原文先补」。查下去发现：页脚圈码译者注 96 条里报「正文无圈码」的 33 条，**真正缺标的只有 1 条**，其余全被四条渲染路径吃掉——它们的落点本来就在源数据里：

1. **表格单元格里的 `<eq>^{1}</eq>` 其实是本页圈码**（22 条）。作战序列表的「勒佩尔少将①」「费尔特②」在原书是圈码，OCR 写成数字。做法：表格里的数字 token 先按「本页页脚有无同号圈码」判断，有就当圈码建链，没有才当注号（实现上是给表格 token 一个独立类型 `T:`，`resolve` 时先试 `CIRC[n-1]` 再回退 `N`）。**只按数字处理会出现「表里全是纯上标、页脚注全成孤儿」**。
2. **表题/表注里带标记**（`第20集团军1941年8月15日的战斗编成 ^{①}`）——表题我是用 `esc()` 直接输出的，标记被当文本转义掉了。表题、表注也要走与正文相同的 `stamp → resolve` 通道，页戳取该表所在页。
3. **注释条目正文里也带圈码**（`《最高统帅部战时日志》第一卷，第102—129页 ^{①}`，7 条）。注释条目的渲染函数若只做 `esc(strip_marks())`，这些圈码永远不建链。条目文本要按**该条所在的印刷页**打戳后走同一通道；注意页戳要用页键（`A052`）而不是印刷页码（`23`）——用页码时 token 正则 `@[A-D]\d{3}` 匹配不上，全部静默落空。
4. **边界页归属**：章区间若含下一章的锚点页（页首就是「第九章」+章题），该页的页脚注会被算进上一章，正文那个圈码在上一章的 fmap 里找不到对应 → 判成「缺」。修法：建 fmap 时跳过 `next_anchor` 所在页，让注跟着正文走。

另有一种真重复：**同页同号印了两条注文、正文只印一处**。不要硬插第二个圈码，标「〔与同页同号注重复，正文只印一处〕」并让它在译者注区可见即可。

自查顺序固定为：**表格 `<eq>` → 表题/表注 → 注释条目正文 → 边界页 → 最后才是真缺**。每条都要给出「源注文数 / 成品建链数 / 未建链数」三个数对账；`未建链 = 0` 才算收工。

## 补完的验收（唯一硬指标）

- 逐章核对正文标记序列 == `1..N`（N = 该章条目数）。**缺号会让序列出现「跳号」，顺序错会让序列出现倒退**——倒退一定是补错了位置（实测两次：一次是同章两条互换、一次是「同上」条目补早了一格）。
- 条目数 > 落点数是正常的（还有残留），但**任何倒退或重复都必须修掉**。
- 残留率参考：某 705 页军事史 50 处缺标 → 补回 33（66%），剩 17 全是「同上/泛引资料」且位置在长引文中段。

## 判「缺」之前的预检：号型误读

同一位置可能根本不是「缺标」，而是号型被读错，先查再判：

- 块尾/段中出现**圈码**但该页页脚**连 ① 都没有**（整页无任何页脚注）→ 多半是数字注号被读成圈码。
- `^{[1]}`、`^{(2)}`、`^{\text{1}}` 这类带括号/花括号的形态，是数字注号被包了一层（本书 `^{[1]}` 实为注 11，落在「…编有 35 个新组建的师」这句）。
- 本书两处实测：`⑩` → 注 10、`^{[1]}` → 注 11。改判后该章序列立刻 1..N 连续。
- 改判写显式表（`TEXT_FIX[(file, pi, block_idx)] = [("^{⑩}", "^{10}")]`），在原块文本上替换后再打页戳。

## 实现坑（踩过一次）

插入 token 时**页戳必须是合法形态** `@[A-D]\d{3}`：写成 `@X000` 时 token 正则匹配不上，懒惰量词 `(.+?)@([A-D]\d{3})` 会一路吞到下一个合法 token，症状是 `ValueError: invalid literal for int(): '7@X000\x02德军情报部门称…'`（把后面整段正文吞进注号）。用 `@D999` 之类合法假页戳即可——数字注号的渲染路径并不用页戳。

## 交付话术

- 说明里写：原书 N 条、源数据缺 M 条、**补回 K 条（逐条见补插清单）**、仍缺 M−K 条及其特征。
- 「补插清单」格式：`第一章 注7 ← 句末「…德国日后最有可能发动一切军事侵略的方向。」`，用户对不上会直接说「第X章 注N」，按锚句改一行重出即可。
