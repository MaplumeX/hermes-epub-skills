**最终交付**：7.96 MB EPUB，epubcheck 0 error / 0 warning；8 篇 19 章 15 扩展章，398 条导航；323 脚注双向对齐；9109 MathML；149 图题 / 23 表 / 196 插图。工作目录 `/root/bookwork/`（extract.py / build.py / inject.py / check.py / scripts/）。

## 结构判定

- 分册边界：A = 第1篇~第7章(p199)；B = 第7章续(p0-14) 起 → 第13章；C = 第13章续(p0-18) → 第19章；D = 各章「扩展」+ 请回答答案 + 奇数题答案 + 术语表 + 教学支持。
- 篇分隔页：整页插图 image + `第N篇` title（+ 竖排篇名 title）+ 本章列表 text。篇号从 title 块取，篇名查常量表 `{1:引言, 2:选择与需求, 3:不确定性与策略, 4:生产与供给, 5:竞争性市场, 6:市场势力, 7:要素市场定价, 8:市场失灵}`。
- 章标题 `第N章 名称`（注意 OCR 插空格：`第 3 章`、`垄 断`）→ `##`；「第N章扩展 名称」也是独立 `##`（15 个扩展章）。
- 小节 `N.M` → `###`；`N.M.K` → `####`；`例N.M` / `定义` / 小结 / 练习题 / 分析问题 / 推荐阅读材料 → 加粗段或 `###`。**小结/练习题/推荐阅读材料之后的内容不再判小节标题**（backmatter 状态，否则文献条目里的 `2.11`、`3.3` 会被当小节标题）。
- 跳过页：封面(A0)、封底简介(A1)、版权页(A2-3)、OCR 目录(A11-15)、空白(A17)、教学支持重复页(D86)。献词页(A8) 输出为斜体行。
- 前置章节：A4 出版者序 / A6 代译者序 / A9 前言 → `#`，其内小节（第11版的新变化/配套内容/致谢）→ `##`。

## 脚注：圈码、按章连续编号

- 圈码 ①-⑳，**每章从①重新开始、跨页连续**（第1章 ①-⑦ 跨 p19-31；第2章 ①-⑲ 跨 p35-70；第13章 ①-⑳ 跨 B185-C8）。
- OCR 变体：⑩→`^{10}`、⑪-⑳→`^{11}`..`^{20}`（全书 17 处纯数字上标）；`②3`（=②+③被读成 23）；`^{②}` 正常包裹。
- 判定 `^{N}` 是脚注还是数学上标：看前一个字符——汉字/中文标点 → 脚注；`=`/字母/数字/`^`/`_` → 数学（`x^{2}`、`e^{-r}`、`2^{0.5}` 全部保留为公式）。
- 全书合计 323 条注释 / 323 个正文落点（按章懒分配后完全对齐）。
- **注释标记被 OCR 丢掉时**（本案例 5 处：C35/C130/A71/C72/C134 页脚注无圈码）：按「本页第一条且是成句中文（含汉字 + len>15）」收成 `mark=''` 的条目，仍编号输出，内容一条不丢。

### 关键 bug：脚注编号不能预先分配

第一版 build 的做法是「每页先扫出 N 个正文标记 → 生成 nums 区间 → 把本页 notes 依次配上 nums → 再把 nums 按顺序发给正文标记」。结果：`refs 646 / defs 323`（同一 id 被多处引用、12 个定义无人引用、4 个引用无定义）。

改为懒分配后一次全对：

```python
def next_ref(self):
    if self.pnote_i < len(self.pnotes):
        n = self.note_no + 1
        self.note_no += 1
        self.notes_buf.append((n, self.note_text(self.pnotes[self.pnote_i])))
        self.pnote_i += 1
        return n
    self.warnings.append('mark without note')
    return None
```

- 页级队列 `self.pnotes = pg['notes']; self.pnote_i = 0`，每页重置；`note_no` 每章重置。
- **标题块也要走这条路径**（标题带标记时先 `sub_marks` 再 `do_title`，否则该注释变孤儿）。
- 页末 `while self.pnote_i < len(self.pnotes)` 把剩余注释补编号（宁可多一条定义也不要丢注释）。

## 双栏页

- 出现位置：推荐阅读材料（文献双栏 + 中文说明块）、答案区（请回答答案/奇数题答案，题号+解答成对分栏）、术语表（A/B/C… 分栏）。
- 判定（**不要加跨栏块数量限制**）：
  ```python
  left  = [b for b in blocks if b['x1'] <= 445 and b['x0'] < 250]
  right = [b for b in blocks if b['x0'] >= 340]
  two_col = len(left) >= 2 and len(right) >= 2
  ```
  加 `len(full) <= 2` 会把「小结」「推荐阅读材料」页判成单栏（这些页有整段跨栏导语），整节内容按 y 交错串栏。
- **右栏阈值实测**：392 太大——答案区右栏题号 `x0=395` 被划进左栏，`2.2` 的题号后跟 `1.1` 的解答；改 340 后正确。
- 排序：跨栏块（`x0<300 and x1>500`）切段，段内左栏按 y → 右栏按 y；每块打 `_col='L'/'R'`。
- 跨页续段条件必须带栏位变化：`cont = prev_open and (not first_prose_done or col_changed)`。只看「本页首块」会把右栏首块接到左栏末段（症状：`2.2` 的题号后面跟着 `1.1` 的解答）。
- 参考文献区：`ref_text` 里以汉字开头的块是上一条文献的中文说明 → `out[last_para] += '<br/>' + 说明`，不要独立成段（否则说明与文献脱钩）。
- 术语表条目**按栏独立排序**（同一 y 上左右各一条，`(col, y)` 排序才对）。

## 图组与面板标签

- 单张图常有 `(a) 消费者无差异曲线`、`(b)` 这类面板标签，OCR 成**独立 text 块夹在两个 chart 块之间**。分组逻辑：连续 chart/image 块 + 中间夹的「短、`^(a)`/`(b)` 开头、无标记」text 块算一组；组内至少一张有 caption 才输出（否则整组是装饰条/分隔线）。
- 面板标签按「第 k 张图之后的标签」归属（`labels[len(grp)-1] = 标签`），输出为斜体行。
- 本案例：源图块 372 个 → 滤掉 175 个装饰块 → 输出 196 张真图、149 个图题。
- **面积过滤陷阱**：`area > 300000` 一律丢会误杀单幅大图（图 5.8 `补偿性差异` area=350196 被丢，图号连续性报「图5 缺 8」）。改用「宽度 > 650 或 area > 450000」判整页图。
- **图 2.4 在源数据里整组缺失**（正文 p64 仍引用「图 2.4(a) 和 2.4(c)」），只能插〔图〕占位并写进缺图清单——不要伪造。

## 表格与公式

- `table` 块的 html 在 `blocks[]` 的 `table_body` 子块，题注在 `table_caption`（本案例 23 张表全部走 `html_table_to_grid` + `grid_to_md`）。
- `interline_equation` 的 span 同时有 `content` 和 `image_path`；本案例按「可复制公式」走 MathML（`$$…$$` + `--mathml`），裁图作为备选。
- `clean_tex`：`\tag{1.1}` → `\qquad\text{(1.1)}`；`\begin{array}{r l}` 列格式去空格；**OCR 拆数字三条正则**（`2 0 0`→`200`、`0 . 5`→`0.5`、`7 9 \mathrm{e}`→`79\mathrm{e}`）。
- **行内公式夹圈码**（`d^{⑨}`、`^{④}g(x_1,\cdots,x_n)=0`）：先 `CIRC_ANY.findall` 摘出标记，再 `re.sub(r'[\^_]\{\s*\}','')` 清空花括号残留、`re.sub(r'[\^_]\s*$','')` 清尾部 `^`，公式与标记并列输出。不处理会得到 `$d^{}$` 这种残式，pandoc 直接报 `Could not convert TeX math`。
- **公式块内嵌条目编号**（`7. \frac{…}`、`2. U(x,y)=…`）：extract 时 `re.match(r'\s*(\d{1,2}|[a-h])\.\s+(?=\\)', tex)` 摘出存 `num`，build 输出 `7\.` 独立一行再接 `$$…$$`（直接塞进公式会让 pandoc 当列表项或把编号算进公式）。

## 重制（2026-10 会话）：缺页 p49 的定位与修复

用户第一次交付的成品「中间缺了一页」。重传的 4 个 layout.json 页数与旧版几乎相同（688 vs 687），**逐页对比才能发现差异**：

- 按**印刷页码**建索引（`discarded page_number` 里 `re.fullmatch(r'\d{1,3}')`），再比新旧两套的 pn 集合 → 只差 **p49**（A 册）。
- 缺的这页正是**图 2.4 所在页**（三张 3D 曲面图 + 式 2.120 推导 + `图2.4 凹函数和拟凹函数` 题注）——所以旧成品的「图 2.4 缺失」不是源数据没有图，而是**整页没进数据**，当时的 `POSTFIX` 占位补丁是误判，重制时必须删掉。
- **缺页检测器（可复用，比字符保真扫描更硬）**：字符级保真扫描查不出「整页不存在」——那页没有内容可供比对。正确做法是拿印刷页码序列做算术校验：相邻两个已知 pn 为 `a`(下标 i) 与 `b`(下标 j)，必须满足 `b - a - 1 == j - i - 1`；不满足就是缺页/重页。本案例 618 个已知 pn 里只有 3 处「异常」，全在前言的 `2011年7月`→pn=201、重复的 `2`/`4` 这类 OCR 噪声上，人工确认即可。
- **插入一页会让后续 (tag, pi) 全部位移**：`SKIP`/`FRONT`/`DEDICATION`/`TWOCOL` 这类按 pi 写死的集合必须重算。本案例 A 册 pi≥64 +1、D 册整体 +1（旧 C 末页 p585 被划进 D 首），于是 `SKIP ('D',86)→('D',87)`、`TWOCOL range(55,85)→range(56,86)`。**别只改 FILES 就重跑**，否则跳过的是错页（教学支持重复页没被跳过、答案区双栏判定整体偏移一页）。
- 重制后的核对基线（同一套脚本，可直接对比）：汉字连续串保真 `19746 串 / 0 未命中`、页级覆盖 `<80%` 为 0、`refs 323 == defs 323`、图题 150（+1 即图2.4）、插图 199（+3 即三张面板）、MathML 9105、表格 23、epubcheck 0/0。
- 顺手修掉的一个小缺陷：注释文本中段残留标记 token（`[^c6-20]: . \ue000⑳\ue001 我们将现值…`）——`note_text()` 里要 `TOK.sub('', body)` 并剥掉标记前的孤立 `.`/`·`。

## 章末区（小结/练习题/分析问题/推荐阅读材料）的双栏排版修复

用户反馈「小结、练习题等章尾部分也是左右双面排布的」。原 build 的 `order_blocks` 只做「跨栏块切段 + 带内左栏→右栏」，在章末页上错得很明显：

- **同一页上下两个小节**（如 p68：上半页是上一章 小结 的两栏续文，下半页从左边起 练习题）整页当成一个带 → 左栏排完接右栏，于是 `练习题` 标题夹在 小结 要点中间，右栏的小结要点被排到练习题题号之后（症状：第2章「练习题」里冒出 6 条 `- ` 小结要点，`b. …求这两个偏导数` 和 `优选择如何变化的时候…` 粘成一句）。
- 修法：**分带（band）**——双栏页按「跨栏（整幅）块」和「**左栏**的章末小节标题」切带，带内再「左栏 y 升序 → 右栏 y 升序」。关键细节：
  - 小节标题**只有在本带左栏上方已有内容时才切带**。若标题就是本页左栏第一块（如 p584 `分析问题` 在 y=142，而右栏顶部 y=134 是 `a. 没有选票交易的多数原则。`），切带会把右栏顶部那几行判给上一节，跑到标题前面去（症状：`a. 没有选票交易的多数原则。` 出现在 `### 分析问题` 之前）。
  - 双栏页里 **右栏顶部常是左栏末段的续文**（`…在考察参数（价格）变化时最` + `优选择如何变化的时候…`；`…使` + `得无谓损失…最小。`），所以跨栏合并（`col_changed` 触发续接）要保留。
- **`is_two_col` 不能把居中公式算成右栏**：`right = [b for b in blocks if b['x0'] >= 340]` 会把单栏页里居中排的行间公式（x0≈350-400）当成右栏，整页误判双栏 → 公式全部被排到正文段落之后（症状：复利附录里「在时期1的期末…」「在时期 2 的期末…」两句话挨着，后面才跟两个公式）。修法：只统计 `text/ref_text/title` 块。本案例因此有 **93 页**由「双栏」改判「单栏」，正文里 (1.8)(2.5)(2.10) 等公式回到正确的引导句之后。
- **单栏页里同一 y 上左右并排的两块**（如 小结 页 y=998 左右各一段）要打 `_col` 标记，否则跨栏续接不触发、句子被切成两段。
- **装饰性小图标不要打断续接**：章末小节前的图标 image 块无 caption、`img` 为空 → `do_fig` 不输出，但旧代码仍 `prev_open=False`，导致跨栏/跨页续接失效（症状：`…材料作` / `为参考资料是很有用的。` 分成两段）。改成「本组图块有实际输出才 `prev_open=False`」。
- **`TERM` 要含半角 `.` 和 `$`**：文献条目以 `.` 结尾、公式块以 `$` 结尾都算完整段落，否则会被当成「未结束」而与下一块错误合并（症状：`…University of Chicago Press, 1990.` 后面粘上下一栏的 `ford, UK: Blackwell Reprints, 1989.`）。
- **推荐阅读材料区（refs 模式）**：`说明` 行与条目会被 OCR 拆成不同块、类型在 `ref_text`/`text` 之间跳。规则：
  - 进入 `### 推荐阅读材料` 置 `self.refs=True`；文献区里的小标题（`方法论方面的文献`，len<24 且不以「附录/第」开头）**不结束** refs，`附录:…`/章标题才结束。
  - 块首连续的中文行 → 用 `<br/>` 接到上一条文献；中文短块（≤160 字、不以 `：` 结尾）同理。**不要用 `not self.notes_buf` 当条件**——章末注要到文末才 flush，这个条件会让同一页的说明时接时不接（本案例 Dadkhan/Hoy/Mas-Colell 的说明全部脱钩，而 Dixit/Luenberger 的说明恰好在同一块内所以正常）。
  - 条目跨栏/跨页续文：`prev_open` 且本块不匹配 `^[A-Z][A-Za-z'’\-]+,\s*(?:[A-Z]\.|[A-Z][a-z])`（新条目开头）→ 接回上一条；**上一条以 `-` 结尾时删掉连字符再拼**（`Advanced Microeco-`+`nomic` → `Microeconomic`）。
- **题号被 OCR 判成 text 而非 title**（40 处，如 `3.5`/`2.1`）：`do_text` 里补一条 `re.fullmatch(r'\d+\.\d+', t)` → 主文模式输出 `**N.M**`，答案区模式设 `pending_qno`。
- 验收探针（都跑一遍，几秒）：① 每个 `### 练习题/分析问题` 里不得出现 `- ` 小结要点（本案例残留 6 条全是题目内部的合法要点，人工确认）；② 每章 `**N.M**` 题号序列单调递增无重复（按 `(int,int)` 元组比，`float('2.10')==2.1` 会造假异常）；③ 文献区不得有以小写字母/`)` 开头的段落（本案例仅剩 1 处，是 OCR 整行丢失的真缺陷）；④ 章末四节顺序 `小结→练习题→分析问题→推荐阅读材料` 单调。

- **OCR 会整块丢掉「推荐阅读材料」里的条目和中文提要**（本案例 A p18 一处丢 4 块）：症状是成品里出现以小写字母开头的残行（`ford, UK: Blackwell Reprints, 1989.`），而它其实是上一条文献的续行。
  - **不能靠字符保真扫描发现**：丢的块根本没进 pages.json，没有可对比的源文本；只能靠「成品里出现了不该出现的开头」+「文献条目数少于预期」发现。
  - **探针**：扫 `ref_text` 块首是否为小写字母（本案例 6 处，5 处是正常跨栏续行，1 处是真丢块）；再看文献区里是否出现「说明脱钩」的孤立段。
  - **修法：`extract.py` 里加 `MANUAL_ADD = {(tag, pi): [{'t','y','x0','x1','txt'}, …]}`，插在 blocks.sort 之前**（插完重新排序），据用户提供的扫描页逐字录入。不要直接改 pages_*.json（重跑 extract 会覆盖）。本案例补回：Boland 条目+提要、Friedman/Hausman/McCloskey 三条提要、Sen 条目开头 `Sen, Amartya. On Ethics and Economics. Ox-`（右栏顶部 `ford,…` 靠 do_ref 的「上一条以 `-` 结尾则删连字符拼回」自动接成 `Oxford, UK: Blackwell Reprints, 1989.`）。
  - 补完校验：该书这一节的条目数从 6+6 变成 7+6（方法论 7 条），每条都有中文提要，`Sen` 条目完整。
  - 顺手修 OCR 错拼（TEXT_FIXES）：`Mathematical Psychis.`→`Psychics.`、`Michael S. Mcpherson`→`McPherson`。

## 小题（a. b. c.）被挤成一行

用户反馈「练习题部分出现 abcde 等小点排在一行」。两个原因叠加：

1. **块内换行被 `join_lines` 吃掉**：源块 `对于下列效用函数：\na. U(x,y)=xy\nb. …` 本来一行一项，join_lines 把它们拼回一行。
2. **OCR 把整块并成一个 span**：`a.  $U(x,y)=3x+y$b.  $U(x,y)=\sqrt{x\cdot y}$c. …`（标签紧跟在数学 `$` 后面，没有空格）。
3. **跨块续接误合并**：`e. …不同?` 以半角 `?` 结尾、`TERM` 只认全角 `？`，下一块 `f. 如果政府…` 被当续文拼上去。

修法（`build.py`）：

- `split_items(raw)` **吃原始 text（带 `\n`）而不是 join_lines 结果**：先按行分组（`ITEM_START = ^[a-h]\.\s|^\d{1,2}\.\d{1,2}(?:\s|$)` 开新组，纯题号行 `^\d+\.\d+$` 单独成组且不与后面的解答正文合并），组内再用 `_split_letters` 按「连续递增的字母链」切。
- **链只要求 ≥2 且连续**，不要限定从 `a` 起——`b. … c. …` 这种跨页断开的块也要拆。
- 标签正则 `(?<![\w\\])([a-h])\.\s`：**不要把 `$` 放进负向前瞻**（`$U(x,y)=3x+y$b.` 里 b 前面就是 `$`，放了就永远拆不开）；`\w` 排除掉能挡住 `0. 5` 和 `图2.4(a)`。
- **续接守卫**：`TERM` 补上 `!?`（半角），且 `do_text` 里 `ITEM_START.match(seg)` 为真时不参与跨块续接。
- 答案区/正文区：段内自带的纯题号段（`2.1`）统一输出 `**2.1**`（单独一段）。
- 注意 **`pending_qno` 前缀必须在拆分之后加**，且拆分前的 `t` 不能覆盖成 `segs[0]`——否则 `re.fullmatch(r'\d+\.\d+', t)` 会把「2.1」当成独立题号块并 `return`，把同一块里 a.–g. 的答案**整段丢掉**（本案例曾丢 2.1 的 7 条答案，靠「内容字符数比对」才发现）。
- 验收：`book.md` 与上一版**去掉 `**` 和 `\.` 转义后字符完全相等**（874880 vs 874880），且 `同段多标签 = 0`（book.md 与成品 EPUB 各扫一遍）。

### 第二轮：题号与首选项挤一行、无空格标签

用户接着举例「第三章的练习题 3.1」。练习题区的 3.1 已拆，真正漏的是**答案区**（`奇数题号的习题答案`）：

- **`pending_qno` 把题号和第一个选项拼成一段**：`3.1` 是独立 title 块 → `pending_qno`；下一个 text 块拆出 `a. 不是` → `segs[0]` 加前缀变成 `**3.1** a. 不是`。修法：`pending_qno` 且 `segs[0]` 匹配 `^[a-h]\.` 时，题号单独 emit 一段再继续。
- **标签后无空格**（`c.1.6美元`、`d.2.1美元`、`c.运用斯拉茨基方程式`）：`LETTER_LABEL` 只认 `\.\s` 会全部漏掉。改成 `([a-h])\.(?=\s|[\u4e00-\u9fff$0-9])`，`esc()` 里再补一条 `^([a-h])\.(?=[汉字$0-9])` → `\1\. `（插入空格并转义）。
- **负向前瞻不能用 `\w`**：Python 的 `\w` 含汉字，`热狗c.1.6` 里 `c` 前面是汉字 → 被挡住永远拆不开。写 `(?<![A-Za-z0-9_\\])`。
- **孤立标签也要能拆**：`…即可得出结果。b.-d，步骤同a。c.运用…`（`b.-d` 不匹配标签正则）——除了「≥2 连续链」，再收集「紧跟在 `。！？；` 后面的标签」作为切点。
- 验收补充探针：`^\**\d{1,2}\.\d{1,2}\**\s+[a-h]\.`（题号与选项挤一段）必须为 0；`book.md` 与 EPUB 各扫一遍。

- **篇分隔页的导语会挂到上一章「推荐阅读材料」的最后一条文献上**（本案例第2/3/6篇）：篇首页的章节清单与 3–4 段导语都是 `text` 块，处理时 `self.refs` 仍为 True（上一章的推荐阅读材料没被任何标题结束），于是被当成「中文说明」用 `<br/>` 接到最后一条文献后面（症状：成品里 `…一部微积分学基础教科书…<br/>第3章 偏好与效用第4章 …<br/>在第2篇中,我们将考察…`）。
  - 修法：篇分支里 emit `# 第N篇 名称` 之后立刻 `self.refs = False; self.last_ref = None`（与 `backmatter = False` 同理）。
  - 同时：竖排篇名块（`text` 类型、内容等于篇名，如第8篇的「市场失灵」）要跳过，否则标题下会多一行重复文字；篇首页的章节清单（`第3章…第4章…` 挤在一块）按 `(?=第\s*\d+\s*章)` 拆成每章一行。
  - **章节清单拆分要加「纯清单」判据**：`len<90 且不含 。！？，、；：`，否则导语里的「第 1 章分析了…」也会被切开（本案例踩过，第1篇导语被切成三句）。
  - 验收：逐个篇页打印 `# 第N篇` 后 3 段，应是「章节清单 → 导语」；再扫「推荐阅读材料」区里是否还有含 `第N篇` 的文献条目（应为 0）。

## 多行公式：一个编号多行 / 每行一个编号（2026-10 会话）

用户提醒「书籍里存在一个编号多行公式，每行公式一个编号，一个编号公式里存在连等和多行等情况」。实测确有其事：

- **每行一个编号**：OCR 只把其中一个编号读进公式（作 `\qquad\text{(N)}`），其余编号落成**独立 text 块**——判定 `re.fullmatch(r'\s*\(\s*\d{1,2}\.\d{1,3}\s*\)\s*', txt)`，本案例 4 处（A p108 `(4.43)`、A p177 `(7.28)`、B p264 `(9.57)`、C p499 `(17.10)`）。
- 回挂规则（`extract.py`，blocks.sort 之后）：向上找 y 差 <90 的最近块，按目标类型分四种：
  - `interline_equation` **已带 tag 且含 `\\`** → 这是「每行一个编号」：已有编号给第一行、新编号给第二行（`split_array_rows()` 拆出头部与各行，逐行追加 `\qquad\text{(N)}`），然后删掉该 text 块。
  - `interline_equation` 已带 tag 但**不是多行** → 不挂（避免重复编号）。
  - `interline_equation` 无 tag → 挂到公式末尾。
  - 最近块是 `text` 且**含行内公式**（`其中，$\frac{\partial f}{\partial k}\cdots=e_{q,k}$` + 孤立 `(9.57)`）→ 编号属于这句正文，追加到该段首行末尾，**不要**挂给上面的公式。
- 已验证结果：3 处逐行编号合并成功（4.42/4.43、7.27/7.28、17.9/17.10），4 处独立编号块全部消化、无残留。

### 等号对齐：目前没有验证过的方案（重要，别重复试）

- texmath 输出的是 `<mtd columnalign="right|left">`（**逐单元格**属性）。实测（本机 Chrome 147 for Testing，用 `getBoundingClientRect` 量每个 `mtd` 与其首子元素的 x 坐标）：`mtable columnalign="left/right/center"`、`mtd columnalign="right"`、完全不加属性，**四种写法渲染结果逐像素相同**，一律居中。→ 靠 columnalign 做等号对齐在 Chromium 系阅读器里无效。
- 「把 `=` 单独放一列（`array{rcl}`）」是**未验证**的候选：本会话改写没真正生效（`book.md` 里 `begin{array}{rcl}` 出现 0 次、仍是 `{rl}`），**不要当成已解决**。
- 若继续做，两条候选（都未实测）：① 每行左式补 `\mspace`/固定宽度，让右式起点一致；② 多行公式渲染成 SVG 图片嵌入（对齐完全可控，代价是不可复制）。
- **`align_multiline` 的既有约束必须保留**：只在「单列 array 且每行都有**顶层** `=`」时改写；找 `=` 必须按**花括号深度**（`_top_level_eq`）跳过 `\prod_{i=1}`、`\text{...}`、`\frac{a=b}{c}` 里的 `=`。本会话第一版没做深度判断，在 (9.60) 的 `\prod_{i & = 1}` 里插了 `&`，公式被改坏（pandoc 报 `Could not convert TeX math`）。
- **逐公式 pandoc 探针（改完必跑）**：把 book.md 每个 display 公式单独写进 `/tmp/one.md` → `pandoc /tmp/one.md -t html --mathml`，输出里出现 `class="math display"` 即该公式转换失败。本会话靠它精确捞出 2 处（`\prod` 下标被插 `&`、`{G_q & = 2.75\%}` 花括号内 `=`），比只看 `grep -c 'Could not convert'` 的计数更有用。

## 多行公式的等号对齐（MathML / mtable）

**结论：用 `mtd style="text-align"`，不要用 `columnalign`，更不要用 `justify-items`。**

实测（Chrome 147，两行公式：第一行第二格很长、第二行很短，正是等号飘走的场景）：

| 写法 | 两行 `=` 的 x 坐标 | 结果 |
|---|---|---|
| 无属性（texmath 默认） | 241.3 / 336.6 | 错位 95px |
| `mtd columnalign="right"` | 241.3 / 336.6 | **被忽略** |
| `mtd style="text-align:right"` | 241.3 / 241.3 | **对齐** |
| `mtd style="justify-items:end"` | 241.3 / 431.9 | 更糟 |
| `text-align` + `justify-items` 同时 | 241.3 / 431.9 | justify-items 把 text-align 覆盖 |
| `mtable style="justify-items:end"` | 241.3 / 336.6 | 无效 |

- **根因**：MathML Core 规范删掉了 `columnalign`，Chromium/Safari 只实现 MathML Core，所以 texmath 输出的 `columnalign` 全部失效，mtd 内容一律居中 → 短的续行等号被推到中间。`text-align` 是 CSS 属性，在 mtd 上生效。
- **保留 `columnalign` 属性**（Firefox 走 MathML3 实现，认这个），双保险，无副作用。
- **`justify-items` 不是 mtd 的适用属性**，且会覆盖 `text-align`，別用。

### 管线（extract.py → pandoc → mathml_layout.py）

1. **`extract.py: align_multiline()`**：把所有多行 array 统一成「左式 & = 右式」两列。
   - 先 `_strip_row_braces()` 剥掉包住整行的 `{…}`（本书 (9.60) 式每行都被包着，不剥就找不到顶层等号）。
   - `_top_level_eq()` 按**花括号深度**找第一个顶层 `=`（必须跳过 `\prod_{i=1}`、`\text{...}`、`\frac{a=b}{c}` 里的 `=`，否则会在下标里插 `&` 把公式改坏 —— (9.60) 踩过）。
   - 已有 `&` 的行取 `&` 之后的部分找等号；`\vdots` 这类短行（≤12 字）输出 `X & `。
   - **任何一行找不到顶层等号且不是短行 → 整块原样返回**（长公式换行续写、`&\quad + …` 悬挂缩进式的不动）。
2. **`mathml_layout.py`**（pandoc 之后、inject 之前）：解包 EPUB，对每个 `display="block"` 的 `<math>`：
   - 从 `<mtd columnalign=...>` 读出每格意图对齐（texmath 会写），重建时改成 `<mtd style="text-align:X">`。
   - 每行一个编号 → 编号从行内挪到新增编号列，逐行对齐（本书 3 处：4.42/4.43、7.27/7.28、17.9/17.10）。
   - 整段一个编号（原在末行之后）→ 外层 `mtable`（`rowalign="center"`）+ 右侧编号列，编号相对整块垂直居中。
   - 无编号多行 → 只做列对齐 + 补齐行数（`\vdots` 单格行补空单元格）。

### 验收（像素测量，不看图）

用 headless Chrome 打开成品公式，`getBoundingClientRect()` 量每行「**单元格开头的** `<mo>=</mo>`」的 x 坐标：

- **只认单元格首元素是 `=` 的**（跳过 `mspace`）。否则 `\sum_{i=1}` 下标里的 `=` 会被误当成对齐目标，得到 8 个假异常。
- 本次结果：204 个多行 display 公式，160 个有单元格级等号，**错位 >1.5px 的 0 个**。
- 测量脚本模式：把每个公式塞进 `<div class=case>`，注入 JS 算完写入 `<pre id="OUT">`，`chrome --headless --dump-dom | grep '<pre id="OUT">'`。
- **`--dump-dom` 里 JS 字符串本身也会被 grep 到**（`document.title = 'RESULT|' …` 会先匹配），所以结果要写进带 id 的元素再 grep 该元素，否则拿到的是源码。

## 一个编号多行公式被拆成多个独立 $$ 块（合并）

用户反馈「有些一个编号多行公式被拆成多个单行公式，导致没有对齐」「不止，还有一些是有左式的」。

实测：`book.md` 里有 106 对**紧邻且中间只有空白**的 `$$` 块，其中 41 对是「A 无编号 / B 有编号」、26 对是「A 有编号 / B 无编号」——都是**同一个编号的多行公式**被 OCR 拆成了 2～3 个 `interline_equation` 块。编号可能印在**第一块、中间块或最后一块**：

```
块1 ∂L/∂x₁ = 0
块2 ∂L/∂x₂ = 0        (2.51)     ← 编号在中间
块3 ∂L/∂xₙ = 0
```

### 判据（严格，不猜）

1. 把 `book.md` 里的 display 块按位置分组：**相邻两块之间只有空白** → 同一个 run。
2. run 内**恰好只有 1 个编号** → 整个 run 是一个公式（编号印在哪一行都行）。
3. run 内有 **≥2 个编号** → 按「**有编号的块结束一个组**」切分（编号属于该组最后一块）；末尾剩余的元编号块并回最后一组。
   - 依据：`Wg=95100` / `Wb=94100 (7.69)` / `期望效用=… (7.70)` → 切为 {584,585}=(7.69) 与 {586}=(7.70) ✓
   - `0=∂L/∂x=… (18.24)` / `0=∂L/∂e=…` / `∂π/∂e[…] (18.25)` → 切为 {1428}=(18.24) 与 {1429,1430}=(18.25) ✓（后者是公式被拦腰截断）
4. run 内 **0 个编号** → 不动。实测 11 对无编号相邻块（`f_x=` / `f_y=` / `f_xx=` 这种并列式子、`p_b` / `p_t` 这种符号），不是多行公式，合并会误伤。

### 合并时的行构造（`_to_array_rows`）

- 剥掉外层的 `array` 包装后按 `\\` 拆行；已有 `&` 的行原样保留（幂等）。
- 有顶层 `=`（花括号深度 0）→ `左式 & = 右式`；`=` 在行首 → `& = 右式`（等号列对齐）。
- **无等号且 len>12 → `& 续行`（放右列）**；无等号且短（`\vdots`）→ `左式 & `（放左列）。
- 全部行用一个 `array{rl}` + 单一编号 `\qquad\text{(N)}` 收尾，再由 `mathml_layout.py` 加 `text-align`。

### 两个坑（本会话踩过）

- **`ARRWRAP` 的 `(?:array|tabular)` 不能是非捕获组**：写成 `\end{\1}` 时 `\1` 会指向 `(.*)` 的内容，永远匹配不上 → 嵌套 array 原样保留，成品里出现 `array` 套 `array`（(2.120) 实测）。必须是 `(array|tabular)` 捕获组、正文取 `group(2)`。
- **合并会让 MathML 总数下降**（9106 → 9028）：N 个块合为 1 个 `<math>` 是预期行为，不要当成丢公式。

验收：`单编号的紧邻对` 必须为 0；再跑全量像素测量（208 个多行公式、等号错位 >1.5px 为 0）。

## 脚注的公式跑到正文里（页脚注区规则）

用户反馈「有些脚注的公式不见了，可能是丢了或者放到正文里了」。

**根因**：本书的脚注排版不统一——同一个页面上，脚注正文可能是
- `discarded page_footnote` 块；
- `preproc text` 块（以圈码 ④⑤⑥ 开头）；
- 而脚注里的**公式是独立的 `preproc interline_equation` 块**，脚注续文是**无标记的 preproc text**。

旧逻辑只搬「以圈码开头的 text 块」，于是脚注公式和无标记续文全留在正文里（症状：脚注以「定义如下:」「因此：」结尾，公式却出现在正文）。

**诊断探针（几秒定位）**：扫所有脚注定义，找**以 `：`/`:`/`，`/`,`/`得`/`为`/`即`/`如下` 结尾**的条目——正常脚注不会这样结尾，说明后面本该跟着公式。本案例找到 7 条，全部命中。

**修法**：按「页脚注区」整块归属，不再逐块猜：

```python
H = (pg.get('page_size') or [812, 1178])[1]
zone = None
for b in pg.get('discarded_blocks', []):
    if b.get('type') in ('page_footnote', 'footer'):
        bb = b.get('bbox') or [0,0,0,0]
        if bb[1] >= H * 0.6:                      # 页脚注总在页面下部
            zone = bb[1] if zone is None else min(zone, bb[1])
for r in blocks:                                  # 无 discarded 脚注的页（如 B p96）
    if r['t'] in ('text','ref_text') and r['y'] >= H*0.6 and r.get('txt','').startswith(M0):
        zone = r['y'] if zone is None else min(zone, r['y'])
```

- `zone` 以上（`y >= zone - 2`）的**所有**块（`text`/`interline_equation`）从 `blocks` 摘出、按 y 顺序并入 `moved`；后续既有的「以标记开头 = 新条目，否则续行」逻辑自动把它们挂到正确注释上。
- `interline_equation` 转成 `$$tex$$` 文本后追加到注释。
- **阈值 0.6 有数据依据**：统计 243 个含 `page_footnote` 的页，起始 y/页高 最小 0.71、中位 0.92，0.6 以下一个也没有。

**验收**：
- 「以冒号结尾的脚注」从 7 → 1（剩下 c16-12 的「因此：」是源数据本身跨页断掉，下一段是另一主题，不猜）。
- EPUB 里 323 条脚注内 MathML 从 314 → **337**，脚注内裸 LaTeX 为 0。
- 抽查渲染：c16-5 / c17-3 / c17-4 的公式都已在脚注内、续文也在脚注内。

## 表格单元格里的「I. / II. / 1.」被当成有序列表

用户反馈「9.3 的那个多行公式怎么没有对齐」。实际不是公式问题，是**表格单元格**里的三行公式没对齐。

**根因**：`html_table_to_grid` 把单元格文本原样写进 grid table，`II. $f(tk,tl) < tf(k,l) = tq$` 被 pandoc 解析成**有序列表标记** → `<ol type="I" start="2"><li>`，整行被列表缩进右移；而 `I.` 因为后面紧跟公式、被当作普通文本留在左侧 → 视觉上就是「I. 靠左、II./III. 右移」。

**两处修复**：

1. **`scripts/html_table_to_grid.py: esc_cell()`**：单元格开头的罗马数字/阿拉伯数字加 `\.` 转义。
   - 正则必须允许**单元格末尾**：`^([IVXLCDM]{1,4}|\d{1,2})\.(?=\s|$)`。只写 `(?=\s)` 会漏掉「单元格里只有 `I.` 一个词」的情形（拆列后就是这种）——不转义会渲染成 `<ol type="I"><li></li></ol>` 一个空列表。
2. **`build.py: split_roman_cells()`**：把首列「`I.` + 公式」拆成「序号列 + 公式列」，让三行公式从同一 x 开始。
   - 仅当**除表头外每一行**首列都匹配 `^(I{1,3}|IV|V|VI{0,3})\.\s+(.+)$` 时才拆，否则不动（避免误伤普通表格）。
   - 表头处理：`[''] + hdr[:1] + hdr[1:]`（序号列留空，原首列表头移到公式列上方）。

**验收**：
- 成品 `<table>` 里不得出现 `<ol>`（本案例修前 2 个，修后 0）。
- 截图目视：三行公式左边界一致、`=`/`<`/`>` 成列、无缩进错乱。
- `check_tables_pandoc.py` 仍是 23 表、1 个已知假阳性（单元格内容本身含 `|`）。

**顺带确认**：(9.27)/(9.28) 这类真·多行公式本来就是对齐的（实测 eqX=[387.2,387.2]、[416.1,416.1]），不要因为用户提了节号就去改公式。

### 合并会被两个东西搞坏（本会话踩过）

1. **脚注里的单行 `$$tex$$` 让 `DISP_RE` 跨块错位**。`extract.py` 把脚注公式写成单行 `$$tex$$`（无换行），而 `DISP_RE = \$\$\n(.*?)\n\$\$` 要求 `$$` 后紧跟换行 → 这些 `$$` 被当成「内容」跨过去，后续所有块的 start/end 全部错位。
   - **症状极具迷惑性**：单步调用 `merge_display_runs(局部片段)` 能正常合并，但全书跑就不行；(9.3) 这类永远合并不上，而且 `blocks[i]` 的「内容」会是整段正文。
   - **诊断**：`len(re.findall(r'\$\$', md)) / 2` 与 `len(DISP_RE.finditer(md))` 不相等就是错位了（本案例 1814 vs 1784）。
   - **修法**：按脚注行切段，只对正文片段做合并——
     ```python
     parts = re.split(r'(?m)(^\[\^c\d+-\d+\]:[^\n]*$)', md)
     out = [p if k % 2 else _merge_in_text(p) for k, p in enumerate(parts)]
     ```
2. **两个行内公式首尾相接成 `$$`**：源数据 `$p_{x}=1, p_{y}=4,$$p_{z}=8$`（缺空格），pandoc 会把 `$$` 当 display math 起点，后面整段解析错乱。全书 34 处。
   - 修法：`re.sub(r'(?<=[^\s$])\$\$(?=[^\s$])', '$ $', md)`。
   - 只匹配「前后都非空白非 `$`」的 `$$`，所以 display 块（前后是换行）和脚注单行 `$$tex$$`（前是空格、后是空白）都不会误伤。

### 验收

- `len(re.findall(r'(?<=[^\s$])\$\$(?=[^\s$])', md))` 必须为 **0**。
- `$$` 总数 / 2 == `DISP_RE` 块数（否则又错位了）。
- 像素测量：207 个多行公式，等号错位 >1.5px 为 **0**。
- 抽样 (9.3)/(9.27)/(9.28)/(2.51)：`eqX` 各自全部相等。

### 脚注里的「即：」「因此：」被当噪声丢掉

`extract.py` 有一条「长度 ≤2 的短块视为页眉/页码碎片，跳过」的规则。但「即：」「因此：」「其中：」这类**承接词只有 2~3 字**，它们是后面那个公式的引导语。丢了就只剩光秃秃的公式，或整段脚注以冒号结尾。

修法：`if len(s.strip()) <= 2 and not s.strip().endswith(('：', ':')): continue`。

**探针**：扫所有脚注定义，找以 `：`/`:`/`，`/`得`/`为`/`如下` 结尾的——正常脚注不会这样结尾。本案例命中 7 条，6 条是脚注区归属问题，1 条是真缺公式（p261 脚注⑫）。修完应为 0。

### TEXT_FIXES 不作用于脚注

`TEXT_FIXES` 只在 `esc()` 里应用（正文），`note_text()` 是另一条路径。脚注里的 OCR 错拼（如 `\frac{f_{1}}{f_{k}}` 应为 `\frac{f_{l}}{f_{k}}`）需要在 `note_text()` 里也跑一遍 TEXT_FIXES。

### 短公式被「长度 ≤12 就丢」吞掉

「表达式为 `r(t)=A'(t)/A(t)`」这类只有十几个字符的正式公式，被“纯公式碎片去重”里的 `len(nm) <= 12 → continue` 一刀切掉了。脚注里大量丢公式都是这个原因（c18-4 的 `π(q)=Pq-C(q)`、c20-12 的 `π_i=(P*-AC_i)q*`、c18-5 的 `SC=SFC+SVC`）。

**正确判据**：只丢「能证明重复」的，不要按长度一刀切——

```python
def add_part(nt, t, dup):
    key = sq2(t)
    if key and key in sq2(nt['txt']):   # 内容已在前文出现过
        return
    if dup and not re.search('[%s]' % CJK, t) and len(key) <= 3:
        return                            # 同一行切出的无汉字短残字
    nt['txt'] += ' ' + t
```

### OCR 把同一行切两遍（bbox 套嵌）

p311 脚注⑤ 整行「只要 π > -SFC，厂商就将进行一定的生产。但是这意味着」之外，又多出 `π > -SFC, 厂`、`产。` 两块，混进来就把句子插花。

**判据**：碎片的 y 区间被另一块覆盖 ≥80%，**且容器也是单行块**（`kh <= 2.0 * h`），x 区间也包含在内 → 同一行被切碎。必须加「容器也是单行」这一条：否则多行段落块会把段落里的**独立公式**整行吞掉（本案例一次误删了 20 多条脚注公式）。

### 判重键 sq2 的坑

同一式子 OCR 给两份，写法常不同：`\mathrm{max}` vs `\max`、`F^{\prime}` vs `F'`、`x^{2}` vs `x²`、`\left[...\right]` vs `[...]`。归一顺序：

1. `\mathrm{...}`/`\text{...}`/`\mathbf{...}` → 剥壳留内容（`\mathrm{max}` → `max`）
2. `\left \right \big prime circ quad qquad` → 整条删
3. 其余 `\cmd` → 去反斜杠留名字（`\max` → `max`，与第 1 步对齐）
4. `²³¹` → `231`，删 `′ ° ◦ '` ` `
5. 只保留字母/数字/汉字/希腊字母 + `= + - < > / *`（保留运算符，否则 `x-2` 与 `x2` 会误判相同）

### 验收（必做）

- **汉字丢失检查**：新旧 `book.md` 逐条比脚注，`Counter(旧汉字) - Counter(新汉字)` 必须只剩已知的重复句/残字。
- **公式丢失检查**：逐条比 `$...$` 集合；被删的必须能证明内容仍在（写成另一种 TeX 形式）。
- **反查探针**：把每页脚注区的所有块（`discarded page_footnote/footer` + y ≥ 区首的 preproc 块）归一后逐个查是否出现在该页 notes 里；只剩 2 条已知重复时才算干净。

## 加粗还原（layout.json 没有字重信息）

用户要求「该加粗的地方要加粗：定义部分的第一个词、有列表标号的性质、段首总结文字」。`layout.json` 的 span 只有 `bbox/type/content`，**没有字体/字重**，所以只能靠版式特征推。`build.py: apply_emphasis()` 三类：

1. **定义条目**：`定义` 标签加粗；**紧接的下一个非空段落**的首个词加粗。
   - 切词：先剥列表标号（`1\. ` / `a\. `），再按三种形式取——`X。X…`（取 X 连句号）、首个「空格 + 汉字」之前（`替代弹性 $(s_{ij})$  投入要素` → 取到 `$(s_{ij})$`）、整行即词（`短期供给弹性 $(e_{s,P})$`）。
   - **陷阱**：`定义` 后面不一定就是术语——p 里出现过「我们已经知道补偿性需求函数的形式为…，有：」这种纯引导句。判据：切出来的东西含 `，。；` 或长度 >24 → 不加粗。
   - **陷阱**：术语前面有列表标号时（`1. 需求的价格弹性 $(e_{x,p})$ :`），`l.startswith(term)` 会失败，必须用 offset 定位。
2. **段首总结词（run-in heading）**：`^([^。！？]{2,13})。(?=\S)`，再加过滤器——
   - 含标点（`。，、；！？,;!?`，**半角逗号也要算**）→ 句子
   - 以 `这/那/其/此/该/的/我们/例如/如果/当/因/…` 开头 → 句子
   - 含 `是|有|会|能|要|将|使|让|得|可|需|应|开始|包含|表示|说明|计算|求解|证明|我们|很多|非常|…` → 句子
   - 长度 2–13，不含 2 位以上数字
   - **在 `练习题/分析问题/推荐阅读材料/小结/答案` 区里一律不加粗**（那里的 `c\. 不在契约曲线上。均衡在…` 是答案正文，不是小标题）
   - 不靠长度一刀切也能把真标题（`机会成本。` `凹性。` `停业决策。` `庇古税。` `情况 2: 固定比例。`）和句子（`现代经济是一个很复杂的实体。` `链式法则还有一个特殊的例子。`）分开。
3. **列表标号**：`^(\d{1,2}|[a-h]|I{1,3}|IV|V)\\.` → `**标号** `。注意 `esc()` 已把标号转义成 `1\.`，加粗后是 `**1\.**`，pandoc 仍不会当列表。

3. **带列表标号的总结词**：`**1\. 齐次性。**例 4.4…`、`**(1) 齐次性。**利润函数…`、`**I．完备性（completeness）：**如果…`
   - **标号和总结词一起加粗，标号单独出现时不加粗**。曾把全书 1157 个 `a\.`/`1\.` 标号单独加粗，用户纠正是「带列表标号的总结词」。
   - **标号写法比想象的杂**，四种都要覆盖，否则整类漏掉：
     - 半角点：`1.` `a.` `I.`，且 `esc()` 转义后的 `1\.`（正则需允许 `\\?\.`）
     - 全角点：`I．` `II．`（本书 3.1 理性选择公理）
     - Unicode 罗马字：`Ⅲ．`（U+2162，不是 ASCII `III`）→ 字符类 `\u2160-\u217f`
     - 括号数字：`(1)` `（1）`（本书 11.5.1 利润函数的性质）
   - 两种收尾都要处理：句号式 `(1) 齐次性。` 与冒号式 `I．完备性（completeness）：`。
   - **带标号时放宽过滤**（`strict=False`）：标号本身就是列表的强证据，不再按「含动词」排除，长度放宽到 30。否则 `(2) 利润函数是产出价格 $P$ 的非减函数。` 会因含「是」被当句子排掉。
   - **冒号必须原样保留**：不能硬写成全角 `：`，否则逐字比对会差一个字符（`II．传递性(transitivity):` 原文是半角）。
   - **禁止字符类要含半角冒号**：`[^。，、；：:！？]`。漏了半角 `:` 会把 `3. 总成本函数对于投入价格是凹的:用图形…最简单的。` 整句吞进去加粗。
4. **无序列表（`- ` 项目符号）**：`- **模型中所有价格都是内生的。**模型的外生变量…`
   - 主循环原本对 `-` 开头的行直接 `continue`，整类漏掉。改成只跳过 `-` 但不是 `- ` 的（分隔线 `---`）。
   - 判据比无标号段落宽、比带标号严：`strict=False` 的长度限制 + 「句号后必须还有文字」。后半条很关键：`- 交叉价格替代效应是对称的。` 是完整条目（句号后无文），不会被误加粗。
5. **书末答案区要整块跳过**：那里按 `### 第N章` 分节，节名不含「答案」二字，光靠标题关键词拦不住（`c\. 不在契约曲线上。均衡在点(40H,80C)…` 会被误加粗）。做法：遇到 `## …简明答案/习题答案/常用术语表` 后置 `deep=True`，之后一直跳过。

**注意：图题计数器会被 run-in 带偏**。`verify.py` 用 `^\*\*图\s?[A-Za-z]?\d+[.\-—]\d+` 数图题，加粗后 `**图7.1 说明了这一论点。**` 这类正文 run-in 也命中 → 150 变 156。真实图题要用「整行加粗」判定：`^\*\*图…\*\*$` = 150。

**验收**：
- 去掉 `**` 并把空白归一后，新旧 `book.md` 必须**逐字节相等**（`re.sub(r'\s+','', t.replace('**',''))`）。
- 加粗占比 >60% 的段落只能是图题/表题。
- 渲染抽样目视：`定义` 标签与术语都粗、术语后正文不粗；run-in 只粗到句号；标号粗、正文不粗。

## 教训（下一本同类书直接照做）

- 圈码脚注**先判定是「按章连续」还是「每页重编」**（逐页打印 body/notes 序列看是否递增），判错整章脚注全错位。
- 编号一律懒分配，别预分配。
- 双栏阈值要拿「答案区」实测校准，不能照抄上一本书。
- 图块按组处理 + 图号连续性探针，比人工翻图快得多。
- 保真度自检：**同一归一化函数 + 显式 SKIP 清单 + 块级前 40 字命中**，三者缺一就会得到假结论。
- `discarded header` 里的标准小节名要救回，否则导航树少条目、正文缺标题（本案例 4 处）。
