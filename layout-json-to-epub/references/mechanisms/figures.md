## 来自「教科书（MathML 公式 + HTML 表格 + 页面圈码脚注 + 缺失插图）」

- **插图补齐路径**：layout.json 只给哈希文件名，图在**OCR 产出目录**里（本体不在这台机器上）；先把全部 image/chart 块的 `(tag,pi,bbox,src,path)` 导出成 `figures.json` + 把唯一文件名列成清单发给用户，用户把 jpg 放进 `images/` 后 build 自动把 `〔图〕` 换成真图（`os.path.exists` 判定：存在→`![](images/<hash>.jpg)` + 斜体图题，缺失→占位）。**图题挂靠**（`^图\s*[A-Za-z]?\d+`、短、无句末标点）先归到同页最近的 fig 块再渲染
- **图题判定要看句读，且必须加「引用动词」黑名单**：正文里 `^图\s?\d+-\d+` 且**无句号**、len<80 才**可能**是题注；带句号的是图释正文，保持普通段落。**但只靠「短+无句号」会把正文吃掉**——OCR 常把「图 6-1 也可以表明劳动的边际收益递减规律。假定土地和其他投入保持不变……」截成 70 字无句号块，被误挂成图题、正文凭空消失（本会话实测踩过，保真度没掉是因为字仍在、只是位置错）。所以还要判「图号后是否紧接引用动词」：`描述|表明|显示|说明|是|将|表示|所|中|到|和|与|及|（|(|给出|描绘|呈现|列出|用|可以|还|也|概括|总结` → 是正文的交叉引用，不是题注。原书大多数图没有独立题注 → 直接 `〔图〕` 占位
- **图题挂靠顺序：先上后下**：题注几乎总在图**下方**，但同页可能有两张图 + 两个题注，按「|Δy| 最小」会把上图配到下题的题注。规则：先找 `0 <= cap.y - fig.y < 330`（图在上、题在下）里最近的一张；没有才退到 `0 < fig.y - cap.y < 180`（题在图上）。配对用「已占用 fig 索引」防重复

  - 双归属 → **M5**（表格本身的渲染在 M5）

## 来自「学术专著（全书 MathML + HTML 表格 + 页脚圈码脚注 + 图目录/索引…」

- **图目录/表目录/索引 = 多行 text 块**：块内按 `\n` 拆成 `- ` 列表项；**索引跨 5 页**（本案例 p118-122），页区间必须扫到「条目消失」为止，只取首两页会丢掉大半索引（症状：索引里 `劳动过程` 等条目跑到正文段落里、单段长 1313 字符）
  - 双归属 → **M7**（索引与目录的结构判定在 M7）
- **缺图处理**：只输出**带 caption 的 fig**，无题图的 image 块是出版社 logo/封面装饰，直接跳过（否则封面页会多出 `〔图〕`）；正文按位留 `〔图〕` + `**图X-Y 标题**`，并在交付说明里列全缺图编号

## 来自「中译本学术专著（页脚圈码脚注 + MathML 公式 + HTML 表格 + 少量插…」

- **`table` 块的 HTML 在 `blocks[]` 的 `table_body` 子块里**，`table_caption`/`table_footnote` 同样是子块——只扫块自身的 `lines/spans` 会**静默得到 0 张表**（与曼昆 `chart` 块的 `chart_caption` 同一类坑）。extract 阶段必须遍历 `b['blocks']`；表题/表注也从子块取，别靠「同页最近短文本」猜（会把「续表」页错配给上一张表）
- **诗行合并**：连续 ≥3 个 ≤18 字、以 `，`/`。` 结尾的 text 块 → `<br/>` 连成一段（p288「没先也没后，/统统在一道，/突然全爆开，/好像肥皂泡。」）

## 来自「中译本教科书·多分册（圈码页脚注按**章**连续编号 + 答案/术语表双栏 + 图组…」

- **图块成组输出，组内有题注才收**：连续 `chart/image` 块（中间可夹 `(a)`/`(b)` 面板标签 text 块）算一组，组内至少一张有 caption 才输出，否则整组是装饰图标/分隔条（本案例滤掉 175 个装饰块，保留 196 张真图）。面板标签按「第 k 张图之后的标签」归属，输出为斜体行
- **图号连续性校验是最快的「图被误杀」探针**：逐章收集 `**图N.M …**` 的 M，必须 == `1..N` 无缺口、单调递增（脚本几行，秒级出结论）

## 来自「中译本教科书·单册拆多文件（`title` 自带 level + 图题被拆散 + 书…」

- **图题被 OCR 拆成独立块（本变体最高频缺陷）**：`chart_caption` 常整段跑出 fig 块变成 `title`/`text` 块，且**图号与标题还可能再拆两块**（`图1A-4` + `坡度不等于斜率`）。挂回判据：
  - `title` 块以 `图N-M`/`表N-M` 开头 → 一定是题注
  - `text` 块以图号开头 + len<80 + 无句号 + **图号后不接引用动词**（黑名单见上节「图题判定」）→ 题注
  - 拆开的两块先拼接（`图1A-4` + `坡度不等于斜率`）再判
  - 宿主 = 同页**最近的无题** fig/table 块；同页没有则看下一页前 6 块
  - 脚本：scripts/attach_captions.py（跑在 build 之前；幂等）
- **图号正则：字母在数字后面**：`图1A-4`、`图5A-1` 这类必须写 `图\s*\d+[A-Za-z]?[-—]\d+`。写成 `图\s*[A-Za-z]?\d+[-—]\d+` 时这些题注**全部不匹配**——题注被当普通段落渲染成斜体（别处是加粗）、图号连续性检查也数不到（症状：明明有题注却报缺号，且格式不统一）。本会话因这一处漏掉 图1A-1~1A-8、图5A-1~5A-6 整批
- **报「源数据缺失」前必须穷举四类**（用户会直接要求「你能人工审查一下吗」；实测初次只查 `cap` 就误报「11 个粘连硬拆会切错」，穷举后 18 个可恢复）：① `chart_caption/chart_footnote/image_caption/image_footnote` 子块；② 同页 `preproc` 的 title/text（题注可能整段落成独立 text 块）；③ `discarded`（header/footer/page_footnote/**aside_text**——本例表题「表7-8」就藏在 aside_text）；④ 把图块交给 `vision_analyze` 确认图内是否印有图题。四类全空才允许下结论，并**给出印刷页码清单**。**不要用「OCR 粘连、硬拆会切错」当交付理由**——那正是用户会追问的地方
- 图题错位的**六种形态与恢复方法**（题注挂到 table 的 cap 上、藏进 fig.fnote、粘在 text 块里、丢了「图N-M」前缀、被当成 title 小标题、被粘进上一段正文中间）：references/figure-caption-recovery.md
- **题注/标题被判成「脚注」或「页眉」是独立的一类缺陷，必须专门扫一遍 `discarded_blocks`**（用户会主动点出来：「可能有些图题被当脚注了」）。本例实测：`page_footnote` 里藏着 图9-3/图9-4 的整条题注+面板说明+资料来源、**7 条表题**（表16-1/19-2/19A-1/26-2/27-4/28-2/30-2）、以及**下一页正文的开头**（第6章 p131「机技术的改进…」「我们要区分产品创新和工艺创新…」，本页正文正好断在句中）；`header` 里藏着 **15 条小节标题**（「当今的混合经济」「生产函数」「政府采购」「休谟的调整机制」…，去空白后精确等于 TOC 小节名）。四类判据 + 恢复代码见 references/figure-caption-recovery.md「七」
- **`check_caps.py` 要 cap + fnote 两边都数**（`python3 check_caps.py pages.json table` 查表题）：题注可能整条落在 `fig.fnote`（本例图30-10），只数 `cap` 会把它报成缺号，然后去「修」一个本来没坏的东西
- **`table.cap` 里会混进正文**：`表 4-1 说明了如何计算价格弹性。价格上升 20%…`（以「表N-M」开头、很短）被当表题。拆分判据：**第一句到第一个句号 ≤70 字**才算「题注标题 + 说明」，否则整块是正文，不要挂
- **多阶段修 pages.json 时每段必须容错**：`find_block()` 找不到要 `return None` 并 `continue`，不能 `raise`——上游规则一改（挂回顺序、合并策略）块就被消费掉了，一处失配整条链断在中间，前面所有修复白跑。固定顺序：`merge_pages → fix_captions（硬编码白名单）→ attach_captions（通用规则）→ rescue_discarded → normalize_caps → build`，每次都从 `pages_raw.json` 重跑

## 来自「中译本教科书·单册拆多文件（`title` 自带 level + 图题被拆散 + 书…」

- **最大教训：图题/表题会整条掉进 `discarded_blocks`，而 `chart_caption` 是空的**。只查图块自己的 caption 会得出「题注丢失」的错误结论——用户会直接指出「可能有些图题被当脚注了」。必须先做一次全量 discarded 扫描，逐块判定它到底是注释还是被误判的题注/表题/小节标题/正文：
  - 以 `图N-M`/`表N-M` 开头，且图号后面**不是**引用动词（所示/所列/描述/表明/显示/说明/演示/解释/估算/展示/运用/提供/简要/仅/表示/所/中/到/和/与/及/的/给出/描绘/呈现/列出/告诉我们/清楚/概括/总结/以/第/为/对/在/有/把/被/从/由/至/（/、/，）→ **题注**
  - 去空白后与书前目录小节名完全一致 → **被误判的 header 标题**（本案例 15 条：当今的混合经济/生产函数/政府采购/休谟的调整机制/短期的菲利普斯曲线…，之前整节无标题）
  - 本页正文末块无句末标点 + 页脚注块是长句、以汉字开头、且能跟下一页首块接上 → **被甩到上一页页脚的跨页正文**（本案例 p131「机技术的改进…」「我们要区分产品创新和工艺创新…」）
  - 剩下的、以数字或圈码开头的才是真注释
- **`[A-Za-z]?` 必须写在 `\d+` 之后**：`图\s*\d+[A-Za-z]?[-—]\d+`。写成 `图\s*[A-Za-z]?\d+` 会漏掉全部「图1A-4」「图5A-1」型图号（症状：这些题注被当普通段落渲染成斜体，而不是加粗题注）。**这个 bug 在 attach/normalize/build 三处都要改**，漏一处就静默失效
- **缺号检查的正确口径 = 「正文引用过的图号」−「已有题注的图号」，`cap` 和 `fnote` 两边都要算**（题注可能被 OCR 归到 `chart_footnote`）。用「1..max 里的缺口」会误报几十个本来就没有题注的图；本案例 242 引用 vs 235 题注，真实缺口 7 个，全部是文字整行丢失
- **题注被挂到相邻 table 块**：`table.cap` 里出现 `图5A-1 …` 时移到同页图块（本案例 3 处）；反向同理，`table.fnote` 里出现 `表 16-1 …` 要移回 `table.cap`
- **22×22 左右的 image 块是章节装饰图标**，按面积过滤；编分隔页是整页全图（`w*h > 300000`）

## 来自「插图/表格的插入位置与分隔线」

- **用户原话**：「对于那些插入的内容要移到合适的位置，不要切断正文，同时上下加入分隔线」。杂志式排版的书（教科书尤甚）插图嵌在段落中间、正文绕图继续，OCR 按视觉行输出后段落就被切成「前半句 → 图 → 后半句」，必须重排。
- **插入组 = fig/table + 题注 + 图释 + 资料来源**，整组一起搬、绝不拆开；每组上下各一行 `---`（EPUB 里渲染成 `<hr />`）。全书 373 组实测。
- **判断「哪一段才是真正的续文」**（三步，按可靠性降序）：
  1. 前半句以 `，；：、` 结尾 → 紧随插入组之后的那段就是续文，直接拼；
  2. 前半句停在半个词上（「表示只」「特」「变」）→ 用「末字＋首字」二字组在全书出现的次数打分（`CORPUS.count(ta[-1] + hb[0])`，CORPUS = 去空白、去图片链接的全文），取最高且 ≥5 的候选；
  3. 打分前**必须**用「段首常见起首字」黑名单排除新段落（这/那/但/然/因/所/此/同/另/其/第/在/从/对/由/随/当/如/例/值/应/需/我/你/他/她/它/近/目/本）——否则「这里我们可以看到市场经济的循环」会被误判成续文，把两段粘成一句。
- **三块交织的典型**（第2章「看不见的手」）：原序 `…看似矛盾的论断，特` ｜ 图2-1 ｜ `这里我们可以看到…` ｜ `别注意一下其中看不见的手…`。修整后段落合成完整一句、图移到段后。
- **`out` 里取「上一段」要用 `out[-2]`**：`add()` 每次追加「段落 + 空行」两条，`out[-1]` 恒为空串，用它当 prev 会让整条规则静默失效（本会话第一版报「接回 0 处」就是这个 bug）。
- **重复题注去重**：同图号两条加粗题注相邻时只留一条，**优先保留不以 `。` 结尾的那条**——带句号的其实是图释首句被误当题注（本例 图26-1：「图26-1 2000年的预期寿命和收入」 vs 「图 26-1 是预期寿命和人均 GDP 的散点图。」）。去重要找上一个**非空**元素（`while k >= 0 and not clean[k].strip(): k -= 1`），不要直接取 `clean[-1]`。
- **编分隔页（第N编）后的整页插图**同样加分隔线，否则会和编名黏在一起。
- **接回只改顺序、不改文字**：源数据本身断在句中的残句（「…从网络股票到钻石，再到」「…虚线 HG」「…沿着令人满」）保持原样 + 图前有分隔线，在交付说明里列清单与印刷页码，**不猜写**。本例 89 处接回、53 处如实保留。
- 脚本：scripts/reflow_inserts.py（book.md → book_final.md；术语表/索引区自动排除，因为那是词条列表不是正文）

## 来自「插图/表格的插入位置与分隔线 / 用「读」代替「猜」：直接审校成品 EPUB（用户明…」

- **用户原话**：「你可以直接阅读epub内容来排版修复吗，你自己思考判断，而不是完全用py脚本的形式」。**位置/归属是语义判断，必须自己读原文**；脚本只用来把上下文导出成可读报告。本会话按「首次提及」纯启发式重排 279 组，反而把图搬错段落（用户下一轮就说「你对插入部分的内容判断不是很准确」）。
- **审校对象是成品 EPUB，不是 book.md**：解包 → 按 xhtml 的真实文档顺序取元素序列（`p/h1–h4/table/hr/blockquote/ul`）→ `<hr>` 成对切出插入组 → 每组导出「前 3 段 / 组内各块（图片、题注、图释、表格首行）/ 后 3 段」→ 逐条读（本例 373 组 ≈ 4700 行）。脚本：`scripts/dump_insert_context.py`（同时打印四类可疑信号统计）。
- **四个机器可判的信号**（只用来挑可疑项，判断仍要人读）：A 组紧跟 `h1–h4` 之后；B 组前段落无句末标点；C 组前没有任何正文（章首）；D 组后首段以接续式字开头（的/了/着/而/就/也/还/又/则/是/别/格/化/性/者/所/以/为…）。
- **B 类不能一律当 bug**：教科书正文本来就跨表格——「表 1A-1 列出了 ｜表｜ PPF 的基本数据」「在图 1-1 的横轴上向右量取 5 个单位的黄油，在纵轴 ｜图｜ 上向上量取…」。本会话 47 处 B 类里多数属正常排版，强拼会改坏原文；**只有「组后首段明显是半句续文」时才动**。
- **重排规则**：插入组紧跟「本章内第一次提到该图号/表号」的段落之后；同章多组按出现顺序处理、目标位置单调不减（这样「图 1-3 到图 1-5 给出了…」一句提到三个图时，三组会依次落到各自段落之后）。章边界用 `## ` 切；同章内不要回退锚点。
- **⚠ `[图表]` 共用一个字符类会让「图1-1」和「表1-1」互相命中**——本会话唯一一个「修完比修前更糟」的 bug：第一版重排把图1-1 搬到表1-1 前面。必须 `re.escape(kind) + r'\s*' + re.escape(no) + r'(?!\d)'`，图/表分开匹配。凡按编号定位，**编号前的主字（图/表）必须参与匹配**。
- **题注被复制进正文**：句中出现「…看看表中的**表 3-5 均衡价格发生在需求量等于供给量之处表中显示了不同价格水平上的供给量和需求量。**」= 题注整条混进句子。判据：句中 `图/表N-M` 之后紧跟的 ≥6 字片段与该号题注相同 → 从正文切掉；正文恢复成「…看看表中的 D 行便可以发现，在 2 美元的价格下消费超过了生产。」
- **句子被图切成两半的英文残句**：`需求向下倾斜规律（law of downward sloping` ｜ 图3-2 ｜ `demand）：当一种商品的价格上升时…`。判据：后段以 `demand/upply/ply/emand）：` 这类英文残词开头 → 与上一段直接拼接。
- **一组里混了两个图**（图1-2 组里还带着图1-3 与两个面板标签）：OCR 把相邻图块并成一组。这是**多面板图**被拆散的典型症状，按下一节的方法重建，不要只加分隔线糊过去。

## 来自「插图/表格的插入位置与分隔线 / 多面板图重建（一组里混了两个图 / 面板标签张冠李…」

- **触发**：教科书里大量插图是「一张图由 (a)(b)(c) 几个面板拼成」。OCR 把每个面板识别成独立 fig 块、面板标签挂到相邻块上，成品里表现为：面板被正文隔开、(a) 标签出现在 (b) 的图上、同一行的 (b) 排在 (a) 前面。
- **必须回原始 layout 取坐标**，不能只改 book.md：fig 块的 `bbox`，以及 `chart_caption`/`image_caption`/`chart_footnote`/`image_footnote` 子块**各自的** `bbox`（题注的 y 与图的 y 不是一回事，用图的 y 归组必然错）。脚本：`scripts/rebuild_panels.py`（跑在 build 之前，直接改 pages.json）。
- **四步**：① **去重**——同页某图块 ≥80% 面积落在另一更大图块内即视为重复裁切（本案例 图8-12 = 「第一人+第二人」整图 + 它的左半/右半裁切共 3 块，交 `vision_analyze` 看图确认），丢弃并把题注/图注并入保留块；② **题注归属**——竖向距离 `min(|图底−题注y|, |题注y−图顶|)` 最小者胜，**要求横向重叠**，无重叠时只允许「题注纵向严格在图内且紧贴图的左右边缘」的侧边题注；③ **面板标签**——只用原始数据里真实存在的 `(a)/(b)/(c)`，缺就留空**绝不臆造**；④ **排序**——先按 y 重叠 >50% 聚成行，行内按 x 左→右，行间自上而下。
- **`inside`（侧边题注）判据写松会互换题注**：本案例 `f['y']-5 <= c['y'] <= f['y']+f['h']+5` 让下方题注也被当侧边题注，图1A-5 与图1A-6 的题注对调（两图并排、题注 y 只差 16px）。收紧成「纵向在图内且横向紧贴边缘」才正确。
- **面板标签常被 OCR 混进正文段**：整段以 `(a)` 开头且含句号的 text 块 → 其实是该页图的**图释**（转 `fig.fnote`）；段末粘着 `(a) 史密斯的需求` → 拆出来当面板标签。**标签在页末、图在下一页时**要跨页归位（`y=-1` 占位，到下一页取 `min(fig.y)-5`），否则那一组永远是「无标签」。
- **重建会丢掉前面步骤修好的题注**：`rebuild_panels` 从原始 layout 重读题注，`fix_captions` 塞进 `fig['cap']` 的修补全被覆盖 → 必须先把 `fig['cap']` 里已修好的题注并进候选池（按图号去重）。症状：图号缺口从 1 个反弹回 4 个。
- **同图号两条题注时，带句号的那条是图释**：题注是短标题不以 `。` 结尾；以图号开头、含句号、较长的其实是图释首句被误当题注（图8-4「图 8-4 用两个企业的情况来说明这一点。…」）。合并成一个单元，长的降级为 `fnote`。
- **必须原地替换，不能 `blocks = 非fig块 + units`**：追加到页末会让整组图跑到该页所有正文之后（本案例 图1-3 一度落到页底）。建 `fig→unit` 映射，遍历原 blocks，首个成员位置放 unit、其余成员跳过；被去重丢弃的块也要显式跳过，否则残留半幅裁切图。
- **面板标签文字与图释重复**：面板标签用的是 `(a) 消费者的需求` 全文时，图释里同一条 `(a) …` 要跳过，否则同一句出现两次。
- 验收：`正文引用编号 − 已有题注编号` 归零（`scripts/check_caption_completeness.py`）+ 抽 2–3 个多面板组交 `vision_analyze` 读图确认面板数与内容对得上。

## 来自「插图/表格的插入位置与分隔线 / `reflow_inserts` 的致命 bug：…」

- **症状**：全书图片引用数从 344 掉到 337，成品缺 7 张图（图28-4、图24-4、图22-7 等），而所有校验都是绿的（epubcheck 0 error、链接全通）——**只有「改前 vs 改后的图片哈希集合差集」能发现**。
- **成因**：把插入组后的续文提到前面时，只保留了 `range(j, pick)` 里的 `text` 块（`between = [blocks[x] for x in … if ks[x]=='text']`），夹在中间的 fig/table 块被静默丢弃。
- **修法**：保留**全部**中间块（`[(blocks[x], ks[x]) for x in range(j, pick)]`），并给其中的图/表加分隔线；相邻的 `---` 合并成一条（`if ln.strip()=='---' and out[-1].strip()=='---': continue`），否则出现 `---`/`---` 连排。
- **通用教训**：任何「重排/提升段落」的 md 后处理，都要在改完后跑一次**图片与表格的引用集合差**（`set(改前) - set(改后)` 必须为空），不要只看 epubcheck 和字符数——字符数几乎不变，因为丢的是图不是字。

## 来自「陷阱」

- **保真度比值 >1.01 先查「重复渲染」而不是「丢块」**：图题既被 `image_caption` 配给 fig 块、又作为正文短行输出，会让比值升到 1.017；比值 <0.97 才是丢块。
