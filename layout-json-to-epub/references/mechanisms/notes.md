# M3 注释体系（标记、编号、双向链接）

> **什么时候读**：书里有任何形式的注释（页脚圈码 / 章末数字 / 星号译注 / 尾注），或正文上标与注释条目对不上时。
>
> **相关脚本**：`scripts/diag_two_note_systems.py`、`scripts/align_marks_notes.py`、`scripts/batch_report_marks.py`、`scripts/renumber_marks_notes.py`、`scripts/repair_endnote_marks.py`、`scripts/read_marks_from_scan.py`

> 本篇内容自 SKILL.md 拆出，条目逐字保留（含实测数字与原节出处）。

## 来自「章末注释（prose 类书籍，无 § 结构）」

- 触发：正文标记为 `inline_equation` span（`^{N}` 每章从 1 重新编号 / `^{*}` 译注），注释集中在书末"注释"区
- 注释块：ref_text 为主，**部分误分类为 text**——注释区页区间内 `re.match(r'^\d+\s', t)` 的 ref_text 和 text 都算注释
- 章节边界 = title 块（章名）；**每章注释起始页页首块是上一章注释续文**（title 之前，归上一章）
- 译注 `*` 对应 discarded_blocks 的 page_footnote（页脚译注），与章末注释是两套体系，分开处理
- **译注配对（页脚 * ↔ 正文 * 标记）**：
  - 页脚续行合并：无 `*` 开头的条目并入前一条；正则用 `^\*+` 而非 `^\*+\s`（`**奥尼尔` 星号后无空格案例）
  - 优先按星号数精确匹配（OCR 漏识别个别标记会错位，如 `^{**}` 漏识别导致圣餐注释错配）
  - 标题带 `*`（如 `从无规定的思想到有规定的思想*`）→ 该页页脚注释是标题译注，须先于 orphan 收集处理
  - **marks 元组必须携带来源页 (tag, pi)**：跨页段落拼接后块的 page 属性是前块页，译注配对会错页
- **诊断**：每章正文标记数 vs 注释条目数逐章比对（int 比较，勿 str vs int），找出 OCR 漏识别的标记——**先尝试修复，不要默认"忠实保留"**（用户明确要求用英文原文解决，见下节"OCR 标记缺陷修复"）
- 引用格式 `[^chN-M]`（章-序号），定义按章分组
- 案例：references/houlgate-introduction-case.md

## 来自「逐节讲解+注释（圈码脚注，每节重新编号）」

- 触发：title 块为"第N节"（非 § 结构），每节 = 讲解正文（可跨页多段）+ "注释：" + 圈码①②③条目；圈码**每节从①重新编号**（书末附录除外，见下）
- 案例：张世英《黑格尔〈小逻辑〉绎注》（references/zhang-shiying-yizhu-case.md）
- **裸圈码 = 丢失上标**：正文里未包 `^{}` 的裸 ① 等字符是 OCR 没识别出上标包裹的注释标记（如 "……浪漫主义哲学家的哲学。⑤耶柯比主张……"），必须计入正文标记数——只数 `^{X}` 会严重低估（诊断脚本 scripts/align_marks_notes.py）
- **注释两套体系混用**：节末注释区（preproc text）与页脚注释（discarded page_footnote）可能并存——第48节案例：注释①②③在页脚 discarded、注释区只有④；诊断时页脚注释也要归入当前节
- **附录页脚注释每页从①重新编号**（第二套文件 P2 p190 起 + P3 全篇实测：p190 ①-④、p191 ①-⑥、p192 ①-②、p193 ①-⑥、p194 ①-⑤、p195 ①-③、p196 ①-④、p197 ①-⑤、p198 ①-③、p199 ①-②、P3 p0 ①-②、p1 ①-③、p2 ①-⑧、p3 ①-②、p4 ①-④、p5 ①-④、p6 ①、p7 ①-②）。正文标记须带页码前缀 `[[MARK:page-N]]`（如 `[[MARK:371-1]]`）才能与注释唯一配对；注释条目按 (页码, 文本) 元组收集、输出加 `[页码]` 前缀。**不能按"每节从①开始"或"跨页连续"对齐**（第一套文件旧分析曾误判为连续编号，第二套文件证实是每页重编号）
- **OCR 圈码错读变体**：`^{42}` `^{[1]}` `^{j}` `^{(2)}` `^{30}` `^{33}` `^{14}` 等均为圈码 ①-⑱ 被错读；注释条目开头也会错读（①→"中"、③→"3"）
- 诊断：逐节"正文标记数（`^{}` 上标 + 裸圈码）vs 注释条目数"对比，缺口≈OCR 丢失的标记（本案例 243 节中 141 节不匹配、缺口约 300 处）
- **页眉/页脚噪声按 y 坐标过滤**（第二套文件实测）：text 类型 + y>640（页面高 796）+ 精确匹配章节名（可带页码后缀，如"第二版序言7"）即页眉噪声，须在 is_helper() 里按 `y>640 and HEADER_FOOTER_RE.match(t)` 过滤——**否则页眉会混入注释区成为伪注释条目**（"第一版序言"混进第一版序言注释①的续行）。注意：y>640 的短块不全是噪声（第113节标题 y=651、注释条目 y=641-712 都是正文），所以必须"精确匹配章节名"而非"y>640 即丢"
- **注释区内的子标题**：`(b) 定量`、`(b) 实存` 出现在"注释："区之后（页末），会被注释续行逻辑吞并成上一条注释的尾巴。修复：in_notes 分支里先判子标题（text + len<40 + 无标点 + 下一块是节标题）→ flush 当前节、in_notes=False、按层级 start_chapter
- **章节级注释收集（无节结构的章）**：第一/二/三版序言等章节有独立"注释："区（正文标记 `^{①}` 等上标 + 注释条目）。需要 cur_chapter_notes 收集器：遇到"注释："且 cur_sec 为 None 时初始化，条目按圈码/数字开头分新条目、否则续行；**start_chapter() 切换章节前先 flush 上一章的注释区**（否则只输出最后一章的注释）
- **交叉引用不能转标记（第二套文件实测）**：正文里的"注①""节注⑤""上节注⑤"等交叉引用不是注释标记，norm_marks 必须排除——检查标记前 3 字符 `re.search(r'注$|节注$', pre)` 则跳过（第120节"可联系上节注⑤所引《大逻辑》的话"曾被误转成 `[[MARK:5]]`，导致该节多出 2 个假标记）。**注意 re.sub 回调里用原始文本 orig 取 pre，不能用已被替换的 text（位置偏移）**
- **注释续行判定：数字开头是续行不是新条目**：注释条目跨页续行常以数字开头（如"33、34、35页):"惟有当思想……"是注释①的续行），若把 `^\d` 当新条目会多计。正确规则：**只认圈码开头（含 OCR 错读"中"=①）为新条目，其余全部并入前一条**。旧技能"注释条目开头错读（①→"中"、③→"3"）"的表述要修正——"3"开头的行是续行而非错读的新条目
- **特殊子标题（title 类型短行无标点）**：`※ ※ ※`、`直接知识或直观知识` 是 title 类型但不匹配 A./B./C.、(a)(b)(c) 等标准模式。规则：title + len<20 + 无 `[。！？，、：]` + 非"注释"开头 + 不匹配标准子标题模式 + 不在简称表区域（P1 p5-7 的书名 title 块）→ 输出 `###`。**注意 `A. 思想对客观性的第一态度;形而上学` 只有 18 字符，若此规则不排除标准模式会被降级为 ###**
- **跨文件诊断脚本必须用 (file, pi) 定位**：P1/P2/P3 的 pi 是各自文件内索引，跨文件比较会冲突（第112节曾混入 P1 p10 第一版序言的注释）。sections 元组带 file，collect 时按 `(f, pi)` 元组比较区间
- **修复表 fixes.json 模式**：OCR 错读上标（`^{2}`→`^{②}`、`^{[1]}`→`^{②}`、`^{(1)}`→`^{①}`、`^{®}`→`^{⑧}`、`^{③}`→`^{④}`、`^{5}`→`^{⑥}`）写入 fixes.json（`{节名: [{old, new}]}`），build.py 的 apply_fixes 在 norm_marks 之前应用——防重建回归，且修复可审计
- **fixes.json 键与目标形式（第二套实测）**：正文修复键 `"第N节"`，注释区修复键 `"第N节注释"`（build.py 两处分别 apply：正文在 norm_marks 前、注释在 flush 时）。
- **apply_fixes 覆盖范围易漏（第三套实测）**：章节级正文分支（cur_sec 为 None 的 `# 章节` 正文）与附录正文分支都必须 apply_fixes——键分别用**章节标题**（如 `"第二版序言"`、`"第三版序言"`）和 `"附录"`。漏加则序言/附录的 fix 静默失效（第二版序言 ⑦⑫⑬ 落点最初全没生效；附录 p370 注释②落点 `[[MARK:370-2]]` 靠 `附录` 键注入）。
- **fix 的 old 必须是该文本流 apply_fixes 执行点上的实际形式**：正文分支在 norm_marks 之前 → old 用原始 `^{①}`/裸文本；个别路径（第121节）在 norm 后 → old 用 `[[MARK:N]]`。fix 不命中时 showsec.py 查证并用另一形式重试；被漏过的错号最终由严格递增序列校验 + 重编号兜底。**fix 目标可能是已归一化的 `[[MARK:N]]` 形式**：部分块先过 norm_marks 后过 apply_fixes（build.py 存在两条路径），此时 `^{[1]}` 等原始形式已不存在，fix 不命中（第121节案例：`"…客观标准”  ^{[1]}"` 无效，`"…客观标准”  [[MARK:2]]"` 才生效）。**锚点必须匹配 book.md 实际文本**（OCR 变体如"也不同于脱离特殊性和个体性的抽象普遍性"与印象中的"…和抽象普遍性"不同）——fix 应用后用 showsec.py 查证，不能只看 exit code
- **批量写 fixes.json 用 Python json dump**（execute_code 内 load→改→dump，原子且避免 patch 模糊匹配静默失败）；改后 `json.dumps(f['第N节'])` 打印确认实际落盘内容
- **逐节语义配对修复流程（收尾阶段，本案例 213→0 不匹配）**：
  1. 诊断：align.py 输出不匹配节；`showsec.py 第N节`（book.md 正文标记序列+上下文 vs 注释条目）或 `showraw.py 第N节`（layout 原始上标+注释）
  2. diff=-1 节（注释多一条）＝某注释无落点：按注释内容语义（人名引用：费舍/莱布尼茨/康德/斯宾诺莎；主题关键词："充足理由律"、"形式的真理"、"内在目的"）在正文找对应句插 `^{N}`
  3. **OCR 错读序列整体重排**（第24节案例：⑤⑩⑪⑫⑬⑭⑮⑯⑱ 全被读成 ①-③）：不要逐条修，按注释内容 ↔ 正文短语语义批量重写整个序列（每条 fix 用带引号的独特短语作锚点）
  4. 注释条目被并入前一条（第50节案例：⑤"耶柯比《关于斯宾诺莎学说的书信》"被并入④）→ 在 `"第N节注释"` 键里用 `\n⑤ ` 插入拆分
  5. 重复标记＝OCR 重复错读（第81节"割裂开来。^{①}"与第1段重复）→ 直接删除而非改号
  6. 最终指标：`align.py` 输出 `mismatch: 0 / 243`
  7. **count 对齐 ≠ 编号正确——严格递增序列校验（第三套实测）**：锚点生成时发现 id 冲突才暴露"数量对但编号错"（正文序列 `1,2,3,1,5`、`8,3,10`、`1,3,3,4` 等 37 处"缺 N 补 1"型 OCR 错读，注释编号同步错）。校验：逐区域（节/章/附录每页）收集正文标记序列与注释圈码序列，检查 `marks == list(range(1, len+1))` 且 `marks == notes`。**修复：按出现顺序统一重编号**（正文第 k 个标记→k、注释第 k 条→k，计数器独立；附录按页重置且保留页码前缀 `[[MARK:pg-N]]`；章节/节正文与注释各用一个计数器）——一次清 37 处，比逐节写 fix 高效得多。例外：语义配对验证过的顺序颠倒（第146节 `5,6,4` 对应"萌芽⑤→潜在⑥→实在④"）必须 SKIP 保留，重排会破坏语义锚点。重编号后 mdlinks 的 id 唯一性检查（`Counter` 查重复 id + href 无目标）是最终把关
- **跨页注释区无"注释："标题（第二套实测）**：注释区跨页续页时，续页首块可能直接是注释条目（第155节案例：p77 首块 `①《小逻辑》，第319页。` 被当正文输出为 `[[MARK:1]]《小逻辑》…` 行）。修复规则：**正文块以圈码开头且 len<80（未在注释区）→ 归入当前节 notes**；cur_sec 为 None 时归 cur_chapter_notes（注意判空顺序防 NoneType 报错）
- **跨页/跨文件断行必须合并（第三套实测，全书 100+ 处）**：layout.json 每页块独立，句子在页末截断、下一页续接是常态（"写成的。由于"+"作者水平有限"；P2 尾"Die setzende"+P3 首"Reflexion), 是指"跨文件；P3 p0 尾"规"+p1 首"定，达到"）。build.py 流构建默认不合并。**必须在 pages.json 层面合并**（页边界已知），**不能在 book.md 层面做后处理**——book.md 无法区分"页边界断行"与"页内正常分段"会误合并，且单遍遍历不做链式合并（前一行被合并后仍以非终止标点结尾，下一行被跳过，如"…纯粹的反思和规定的"+"反思的统一"）。合并规则：页末块以非终止标点结尾（TERMINAL 正则，先剥 `[[MARK:...]]`/圈码再判）+ 下一页首块是纯续文（单行、非结构元素）→ 合并；结构元素（章节/节标题、子标题、注释条目、圈码开头、`[页码]` 条目、※ ※ ※、注释：、德文副标题、页眉噪声）绝不合并。跨文件边界同样处理。脚本：scripts/merge_page_breaks.py。**合并 5 大陷阱（第三套实测，逐一踩过）**：
  - **① 合并后保留下一页首块的原始 y**：`first_b['y'] = last_b['y']` 会把正文块 y 改成上一页底部 y，破坏该页按 y 排序——正文被排到注释区之后，`in_notes` 状态机错乱，整节注释区崩溃（第25节 113 条注释被吞，align 报 `body marks=0, note entries=113`）。合并只改 text，y 不动。
  - **② TERMINAL 正则必须含全角括号**：字符类只写半角 `)` 时，以全角"页）"结尾的注释条目被误判为"未结束"，与下一页错误合并（第三版序言注④+目录页）；正则写 `[。！？….!?]["」』”’）)\]]*$`。
  - **③ 拆行页脚噪声**："导\n言\n23"被 OCR 拆成三行，逐行匹配章节名失败 → 被当正文块与下一页首块合并（第17节注③被"导言23"污染）。修复：y≥600 的块先去空白拼接（`re.sub(r'\s','',t)`）再匹配 HEADER_FOOTER_RE，整块命中即删。
  - **④ pass1 页脚噪声清理只限 y≥600**：对全页清理会误删真正的章节标题（y<600 的"导言"等 title 块、目录页内容，曾误删 246 块）。y<600 的块一律不动。
  - **⑤ 附录区（P2 pi≥190、P3）页末块含上标/圈码则跳过合并**：附录页脚注释每页独立编号，跨页合并会把上一页正文（含其注释上标）并入下一页块，标记页归属错乱（check_appendix 报 375/376/377 错位，marks 6 vs notes 4）。**合并后必须重跑全部校验**：align.py（节级）+ check_appendix（附录每页）+ check_chapters（章节级）——只跑 align 就进 EPUB 会漏掉附录错位。
  - 另外：P1 封面/目录页（pi≤1、27-29）不参与合并（与 build.py 的跳过规则一致）。
- **诊断脚本从 book.md 统计（align.py v3）**：build 归一化标记后，从 book.md 逐节统计 `[[MARK:...]]` 数 vs 注释条目数（`^[圈码]` 开头），比从 pages.json 统计更准（已含全部归一化）。批量报告脚本（batch_report.py 模式）：输出每节正文标记序列（含上下文）+ 注释条目开头，快速定位 OCR 错读——正文标记序列与注释编号序列对照，错位处即错读处（如第48节 `^{③}` 重复出现、第50节序列 1,3,4,6,7,8,3 明显错位）

## 来自「OCR 标记缺陷修复（对照英文原文，用户要求）」

- **用户偏好**：缺失注释标记/星号数错误**必须尝试用英文原文修复**，不要默认"源数据缺陷，忠实保留"（本会话用户主动问"你有办法根据英文原文来解决吗"）
- **第一步：扫描"被 OCR 识别成普通文本"的上标**——很多"缺失"标记其实就在正文里，只是没被识别为上标：
  - 正则 `([。！？”’）\]》])(\d{1,3})(?=[\u4e00-\u9fffA-Za-z])` 全书扫描（如 "27因此"、"5因此"、"9这样的"）
  - 变体：`^{[41]}` 是标记 141 被方括号包裹（`^{[N]}` → `[[MARK:N]]`）
  - 变体：**Unicode 上标字符** `¹²³⁴⁵⁶⁷⁸⁹⁰` 也是 OCR 变体（第8章 1-3 案例：`¹`→`[[MARK:1]]`）——全书扫描 `[¹²³⁴⁵⁶⁷⁸⁹⁰]`
  - 变体：**纯文本星号串**（如 "修拉 *****"、"比亚兹利 *****" 星号未转成标记）——扫描 `[\u4e00-\u9fff]\s*\*{2,}` 上下文核对
  - **扫描技巧：先屏蔽标记再找残留**——`re.sub(r'\[\[MARK:[^\]]+\]\]', '', t)` 把已转标记的文本挖掉，再正则扫 `\*{1,6}` 和 `\^\{\w+\}`，剩下的都是真残留（第9章"马奈 **""杜乔 ***""乔托 ****"案例、第10章 `^{*86}` 案例）；`^\{...\}` 数学公式（m/s²、t²）不是注释标记，保留
- **第三步：英文标记定位**：DJVU 文本中上标模式 `([.!?\"'\)\]])(\d{1,3})(?=[\sA-Za-z])` 或 `([a-z])(\d{1,3})(?=[\sA-Za-z])`（如 `relationship.1`、`vocabulary*.14`）→ 提取标记前 ~250 字符英文上下文
- **插入后必须验证标记顺序**：批量插入后重扫每块 `[[MARK:...]]` 出现顺序，确认与编号递增一致——本会话第10章 6/7 曾插到标记5 前面、第7章 3/4 曾插进引文内部（锚点字符串在文本中出现多次或锚点本身含引号时易错位）。修正方法：先 `replace` 撤销错误插入，再按正确锚点重插
- **最终验证（两套体系分别核对）**：
  - 数字注释：`正文标记集合 == 注释条目编号集合`（逐章，int 比较）
  - 星号译注：正文 `[[MARK:*+]]` 集合 == 译注文本开头 `^\*+` 集合（按星号数）
  - 全部对齐才算修复完成；残留的纯文本星号（如 "比亚兹利 *****"）也要转成标记
- **星号配对必须按数量核对，不能只比集合**（第7章案例：正文只有 1 个 `*` 标记、译注有 2 条 `*`——集合相等但数量不符，差 1 条译注无对应正文）。核对脚本统计每种星号数的出现次数：`正文计数[k] == 译注计数[k]`，逐 k 比较
- **`^{*N}` 是合体标记**：OCR 把星号译注和数字注释合成一个 span（`^{*86}` = 好撒玛利亚人星号译注 + 数字注释86）。修复时拆成 `[[MARK:*]][[MARK:86]]` 两个标记，**不能只转数字丢星号**（本会话曾把 `^{*86}` 只转成 `[[MARK:86]]` 导致第10章星号又缺 1 个）
- **discarded_blocks 的 header/footer 类型也可能含正文**（两案例）：
  - 第10章：正文引文在"以色"处截断，续句"列人双足未湿就过了红海…加农炮差不多"被误分类为 discarded header
  - 第7章：正文首句"黑格尔的生命概念是先天的。*"整句在 discarded footer（`discarded_blocks footer` 类型）——footer 通常被当出版社页脚丢弃，但**页脚内容可以是正文引文或译文首句**

- **EPUB 生成后核对"正文星号链接数 vs 译注条数"**：渲染后统计每章 `href="#chN-tr"` 链接数 == 该章译注条数（本会话 70 条译注 vs 66 链接即漏链接信号）；链接数少于译注数的章节就是正文星号缺失/错位所在

  - 方法：**相邻已知标记夹逼**——先列出缺失标记的相邻标记 N-1/N+1 在中文中的位置（上下文），再从 PDF 文本流中取两标记之间的英文段落，缺失标记必在该区间内
  - 批量表驱动：`(章, 标记, 英文锚点词, 中文锚点词)` 列表逐个定位；英文锚点选引文原文（如 "ex opera operato"、"abstractions from the true life"）或人名（Winfield/Derrida），中文锚点选对应译文片段

- **页底注文本里的标记必须单独渲染，不能走正文渲染路径**：页底注里常夹 `①`（交叉引用「见第51页注①」）和裸数字（OCR 噪声）。若套用正文的 `render_text`，交叉引用会被当成本页脚注引用 → 产出 `[^fA30-①]: … {{MARK:12}}` 这种**未渲染的残留 token 混进脚注定义**（grep `{{` 能查出来）。正确做法写独立的 `render_fn()`：圈码保持纯文本、`*` 丢弃、数字**只在正文确实没有落点时**才建链接（顺便把这类「注释里才有标记」的条目救成有落点），其余丢弃。
- **正文标记序列修复（`^{11}` 被 OCR 读成 `^{1}`）**：表现为序列里出现重复或倒退编号（`1,2,3,1,5`、`8,3,10`）。修法写 `fix_mark_sequence()`：按文档顺序维护 `last`，遇 `n <= last` 且 `last+1` 存在于该章译注表 → 改成 `last+1`；`n == last` 且无对应 → 直接删掉这个重复标记。跑完 `dup_mark` 归零。
- **上标被读成普通数字的第三种形态**：句末引号后紧跟数字再接括注引证 —— `…才是生产力发展的界限”10（《资本论》第3卷，第484页）`、`…携手并进的。”39（《资本论》第1卷，第604页）`。扫描正则 `(\d{1,3})(（《[^）]*》第[\d、—]+页）)` 或 `([”’])(\d{1,3})(?=[（(《])`，命中后**逐处人眼核对编号与该章译注条目是否对应**，再写进 `TEXT_FIXES = [(old, new)]` 表（本书 4 处：第3章注10、第4章注39、第9章注15、第11章注81）。别用通用正则自动替换——`16、17世纪`、`第77、81页` 这类会被误伤。

  - **别一页一次 `vision_analyze` 工具调用**（84 页 = 84 次调用）。写脚本在 **Hermes venv** 里直接调辅助客户端，一次工具调用跑几十页：`/usr/local/lib/hermes-agent/venv/bin/python`（系统 python3 没有 openai 模块）→ `import agent.auxiliary_client as A` → `prov, client, model = A.resolve_vision_provider_client()` → `client.chat.completions.create(model=model, messages=[{type:text},{type:image_url,image_url:{url:'data:image/png;base64,...'}}])`。
  - **必须 `background=true` + 可续跑 JSON 检查点**（每页读完立即写盘），84 页约 30–40 分钟；中途重启自动跳过已完成页。
  - **视觉模型很可能是推理模型**：`max_tokens` 给小了会 `finish_reason=length` 且 `content=None`（实测 800/1200 全空），答案只存在于 `reasoning_content`。对策：temperature 0.1 + `max_tokens` 放宽到 4000，并 `resp = content or getattr(msg,'reasoning_content',None) or ''`——Hermes 自带 `tools/vision_tools.py` 就是 `extract_content_or_reasoning` + 空内容重试一次，照抄它的参数最稳。
  - **渲染**：`pdftoppm -f P -l P -r 250 -x ../-y ../-W ../-H ../-png`（-x/-y/-W/-H 是像素 = pt × dpi/72）切掉页眉页脚。文字页 **PNG 比 JPEG 小**（实测 148 KB vs 939 KB），不要费劲转 JPEG。pdftoppm **会在输出名后再拼一次页码**（`-png out/p023` → `out/p023-023.png`），脚本里用 glob 取实际路径，别硬拼文件名。
  - **prompt 用列表格式**：要求逐条输出 `上标数字 | 它前面紧邻的 6~12 个汉字（原样照抄）`，看不清写「看不清」，无上标不列、不解释。带表格/图版的页噪声大（会读出页眉数字），可单页重读或跳过。
  - **三道闸才允许写入**：① 号码必须在该章注释编号表内；② 前文必须在该页文本中**唯一**命中（并加「只比汉字」回退，因为模型常漏抄原文里的数字）；③ 插入位置必须落在**相邻两个已链接标记之间**（顺序单调）。任一不过 → 记拒绝日志，绝不硬塞。
  - **控制组＝免费准确率校验**：这些页上通常还有已链接的注号，模型读到的「号码+前文」若与正文已有位置一致即说明该页读得准（本案例 66 条控制读数全部对上）。把控制读数一并统计进报告，用户能直接判断这一批读数可不可信。
  - **页→章映射要用累计字符数**：把每章页文本按 `bounds.append((total,total+len(txt),pi,pageno)); total += len(txt)` 建偏移边界。**写成 `len(buf)` 会静默全错**——buf 是字符串列表，`len()` 返回元素个数而非字符数，反查永远落不进任何页（本会话在此卡了多轮）。
  - **不要在工具调用里写 `\uXXXX` 正则**：经 JSON/heredoc 传递会变成 `\\uXXXX`，在 raw string 里语义改变，规范化函数会**静默剥掉所有中文**（症状：报「前文在本页命中 0 次」，但手动 find 又能命中）。稳妥写法：`''.join(c for c in s if c.isalnum())`。
  - **双模型一致才采纳（收尾期主力手段）**：本机 axonhub 除 deepseek-v4-flash 外还有**原生多模态 `glm-5.3-flash`**（用户告知；另有 `glm-5.3`）。同一页切块用两个模型各读一遍，**号码相同且前文有 ≥6 字重叠**才算一致读数，再进三道闸。实测一致读数里仍含大量控制组可自检，且**抓出过一处错插**（见下一条）。
  - **有疑问就地做「紧裁终审」**：从 layout.json 取该块 `bbox`，`pdftoppm -r 500 -x/-y/-W/-H`（±6pt 边距）只裁这一段，问两个模型同一问题「这句句末标点后的上标数字是几」，两者一致才动手。比整页重读可靠得多——本案例第12章「……由一个有肠胃病的列兵所组成。”」早前单模型 250 dpi 读成 8 并已插入，紧裁+双模型一致读出 **3**，据此更正锚点（注8 退回待补）。
  - **插入前三道新守卫（本会话补，均实测拦下过错误）**：① 同一注号出现 ≥2 个**不同前文**落点 → 判歧义跳过（ch16 注30）；② 落点 ±80 字内**已有锚点** → 跳过（防重复插，也暴露前后两次读数矛盾）；③ 前文之后**必须紧跟句末标点**（走标点循环后 `j` 未前移即判「句中」跳过）——第1章注3 曾被插进引号内部（"任何东西都可以用机器³制造。”"），而该句三个模型都只读到 8，属误读。
  - **错插更正流程**：整段替换锚点编号（`enref-c12-8`→`enref-c12-3`）→ 扫附注区**删掉目标已不存在的 ↩**（否则留死链）→ 再跑一次补 ↩。
  - **每一步写回都要有护栏**：写 `book_full.md` 前 `assert len(body) > 100000`；每步跑完打印「正文长度 + 锚点数」并 `cp book_full.md book_full.stepN` 留档。本会话有一次生成的 apply 脚本引用了已删除变量，把中间文件写成 **1 字节**（症状：重建出的 EPUB 只有 1548 字符 / 目录 1 条）——靠「EPUB 正文总字符数 + 锚点数」异常发现，恢复办法是从上一份已验证副本逐步重跑并逐步核对锚点（268→294→298→326→330→332），不在坏文件上继续叠加。
  - 脚本：`scripts/read_marks_from_scan.py`（locate/read/apply 三段，可续跑）；实测数据与拒绝样例：`references/scan-superscript-reading.md`。读不清的页 → 放大重读，**不许猜**。
- **OCR 用逗号顶替句点会把两条注释粘成一条**（`…I, 406. 18, Takaki,…`）：在**单条注释文本内**定向搜 `\s{prev+1},\s+(?!Vol\.)(?=[A-Z][a-z]+[, .])` 拆分。**不要**为此加通用的「逗号变体」分条正则——会把 `Ser. 1, Vol. 51` 误切成新条目并污染多章注释（实测踩过）。

## 来自「学术专著（全书 MathML + HTML 表格 + 页脚圈码脚注 + 图目录/索引…」

- **页脚注释三件套（顺序固定）**：① 先把 `^{①}` 形式的 inline_equation span 与裸圈码都归一成 `[[MARK:①]]`（`text_span()` 逐字符转），注释区条目也走同一函数；② 条目切分：**以 `[[MARK:x]]` 开头的块 = 新条目**，其余并入上一条（判据要放在归一化之后，否则 `[[MARK:①]] 比如取部门1…` 会被当成续行）；③ **OCR 把页脚内联公式重复输出成独立 page_footnote 块**（本案例 39 个）：判定 `re.fullmatch(r'\$[^$]*\$', raw) and hay.count(norm_math(raw)) >= 2`（hay = 本页正文+注释拼接）→ 丢；再补一条 `len(norm) <= 8 and norm in norm_math(上一条)` → 丢（`ω`/`g`/`r=0` 这类碎片）。**不滤则注释数 66 ≠ 正文标记 76**
- **正文块以圈码开头 = 被误分类的页脚注释**：`text` 块 `startswith('[[MARK:')` 且该页注释条目数 < 正文标记数 → 从 blocks 里摘出补进 notes（本案例 p2 p93 的「① 此内容进行推广后…」）

## 来自「中译本教科书·多分册（圈码页脚注按**章**连续编号 + 答案/术语表双栏 + 图组…」

- **脚注编号必须「懒分配」，不能预先按页编号**：不要「先把本页所有注释编号成 n..n+k，再按顺序配给正文标记」。正确做法是维护本页注释队列 `pnotes/pnote_i`，正文遇到标记时才 `next_ref()` 取一条、分配编号并压入 `notes_buf`；页末再把队列里剩下的注释补编号。**症状对照**：预先编号时 `refs 646 / defs 323`（同一 id 被多处引用 + 大量「无引用的定义」），改成懒分配后 323↔323 全对齐。**标题块里的标记也必须走同一条路径消费编号**（否则该条注释变成「无引用的定义」）
- **`^{N}` 是脚注标记还是数学上标，靠前文判**：OCR 把 ⑩→`^{10}`、⑳→`^{20}`、⑬→`^{13}`。规则：`re.fullmatch(r'\^\{?\s*(\d{1,2})\s*\}?$', span)` 且**前一个字符是汉字或中文标点** → 脚注标记；前文是 `=`/字母/数字/`^`/`_` → 数学上标（`x^{2}`、`e^{-r}` 不能动）。全书扫描这种纯数字上标只有 17 处，逐处人眼核一遍即可
- **裸圈码转 token 必须只处理 token 外的片段**：先 `re.split` 出已有 `\ue000…\ue001` token，只对非 token 片段做圈码替换。否则 `\ue000\ue000②\ue001\ue001`（二次包裹）——症状是标记数虚高、编号全部错位（本案例 A71/B76/C72/C134 四处）
- **以标记开头的长 text 块 = 被误分类的页脚注释**：`b['type']=='text'` 且 `txt.startswith(M0)` 且 `len>15` → 从 blocks 摘出、按 y 并入本页 notes（本案例 5 处，B p47/p76/p95）。注意阈值：`len<=15` 的是「圈码 + 短标签」正文，别一起搬
- **多行公式的编号回挂与对齐**：一个编号多行 / 每行一个编号的处理（含 Chromium 忽略 `columnalign` 的实测结论，别再重复试）见 references/micro-theory-11e-case.md 的「多行公式」一节

## 来自「中译本教科书·单册拆多文件（`title` 自带 level + 图题被拆散 + 书…」

- **书前 OCR 目录解析（`text` 块内 `\n` 多行）**：条目两种形态——`条目名 页码` 同行，或 `条目名` + 下一行纯页码。**同一本书常印「简目 + 详目」两份**，用 `编号` / `(章号, 是否附录)` / 书末名做 key 去重，否则章数翻倍、编号重复（本例首版解析出 41 章，去重后 38）

## 来自「陷阱」

- **Python `'' in CIRC` 为 True**：空字符串匹配任何字符串！classify 时须 `marker and marker in CIRC`，否则无标记脚注（如 "8。"）被误存
- **pandoc `<sup>*</sup>` → 强调解析**：`<sup>*</sup>` 中的 `*` 被 pandoc 当强调标记，输出 `<sup><em></sup>` 不匹配标签。修复：星号上标用 HTML 实体 `<sup>&#42;</sup>`（数字上标不受影响）
- **上标语法残留**：OCR 可能输出 `^{①}`（p49/p115 案例），替换为 `①` 再走标记扫描
- **德文标题结构提取**：hegel-system.de 的标题常挤在一行（"A Das Wesen als Grund der Existenz a. Die reinen Reflexionsbestimmungen a. Identität"），用 `re.split(r'\s+(?=[abc]\.\s)', t)` 拆分；再找标题行后第一个 § 编号定位归属
- **编号条目（1. 2. 3. / I. II. III.）必须独立成段（用户要求）**：layout 中独立块的编号条目即使前块以句号结尾也会被\"句号拼接\"规则吞进同一段（§148 案例：\"1. α) 条件…2. α) 事情…3. α) 活动\"挤成一段）。修复：merge_main 中在 CITE_OPEN 分支后加规则——`re.match(r'^\d+\.\s', t) or re.match(r'^[IVXLCDM]{1,4}\.\s', t)` 的块 flush 当前段、ctype='body'、独立成段；若前段以汉字结尾且无标点（\"…显露出来\"+ \"3. \"），补句号。**该规则必须加到每个部分的 build 脚本**（本案例先只改了 build2.py，§18 的 I./II./III. 在第一部分 build.py 中仍被拼接，需同样加规则）。**但要区分块级 vs 块内嵌编号**：对照德文原文——编号在原文分行（§148 德文 a) die Bedingung / b.
