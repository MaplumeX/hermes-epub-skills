# M6 引文段落判定（学术书：整段转引 vs 作者分析段）

> **什么时候读**：要把「整段转引他人原文」的段落排成引用格式（blockquote），且必须区分作者自己的分析段时。
>
> **相关脚本**：`scripts/check_quote_paragraphs.py`、`scripts/blind_read_quotes.py`

> 本篇内容自 SKILL.md 拆出，条目逐字保留（含实测数字与原节出处）。

## 相关篇

> 一条结论常跨两个机制：**正文只在主归属那篇写一份**，这里只放指针。

- **M7** —— 竖排书名页眉会落进正文（引文判定的干扰源）
- **M9** —— 交付说明必须写清识别口径与排除数

## 来自「中译本学术专著·双注释体系（页脚圈码 + 章末「译注」数字） / 引文段落转引用格式…」

- **用户原话**：「文段结尾有标注出处且独立成段，我刚刚没说清楚。有些正文里可能也用""引号引用且正好是在段落的最后，这些不要用引用格式，不要识别错了」。即：**只有「整段都是引文」的段落**才转 `>` blockquote；作者本人的分析段、以及正文里带引号引语而引语恰在段末的段落，一律保持普通段落。
- **绝对不能用「段末有出处」单条正则**：本书 77 个段末带出处的段落里只有 57 个是整段引文；另外 **100 个是作者分析段**（例：「《资本论》开篇的论述简单得异乎寻常。马克思把商品界定为……（《资本论》第1卷，第38页）」）、**20 个是段末引语**（例：「马克思接着补充了一个颇为隐秘的说法：“成为生产工人不是一种幸福，而是一种不幸。”……」）。按正则跑会误伤 120 处，比不做更糟。
- **可行流程**：`scripts/check_quote_paragraphs.py book.md` 先把「段末带出处」的段落全导出（含所属章、是否含引号、前一段末尾），**逐条读原文**分类 → 把判定为整段引文的**段首 15–20 字指纹**写成 `QUOTE_STARTS` 常量（去空白去标记后 `startswith` 比对）→ build 时命中即输出 `> `。指纹比正则可审计、不会随改版漂移；判错时改一行常量即可。
- **读原文时的三条判据**：① 前一段以冒号 / 「写道」「认为」「总结说」「如下」结尾 → 后段大概率是整段引文；② 整段引文通常**不带引号**（原书用缩排表示引文，OCR 后引号消失），段内出现成对 `“”` 的往往是作者转述；③ 引文段常以「——」开头（接排的分条引文）。
- **一段引文可能跨多个段落（用户第三轮补充：「也有可能是多段的」）**：原书用整段缩排表示引文时，一段引文常被页边界/OCR 切成 2–4 个 `text` 块，**只有最后一段带出处**。做法：判定出引文段后**把相邻引文段合并成一个 blockquote**（段间 `>` 空行 `>` ），不要输出成 N 个独立 blockquote。本书 71 个引用块里 4 个是多段块（第1章 2 段、第2章 2 段、第3章 2 段、第7章 2 段）。
  - **合并的唯一合法条件是「前一段没说完」**：前段末去掉 `<a>`/`[^id]`/引号括号后**不带出处标注**（即以 `……` 或断句收尾）→ 与后段合成一块；**前段已经带出处 `（《…》第N页）` → 这条引文结束了，后段是新引文，必须分成两个引用块**。本书第2章「对任何种类劳动的同样看待」、第13章「在那里，资本主义制度……」都是靠这条正确分块的，早前一律合并会把两条独立引文粘成一块。
  - **绝对不要用「向前回溯把引文前未结句的段落并入」的启发式（本会话 v3 因此整版作废、用户直接说「v3 错了 撤回」）**：这条规则会把作者的话吞进引用块——实测吞进「所以，让我们回到马克思的论述。他说过，抽象劳动」（作者引导句）、「希法亭说（列宁也赞同这一点）：」（引导句）、并把残片「“这里」单独拆成一个引用块。**判据再细也不行**（加「引导动词收尾就停」仍拦不住「…他说过，抽象劳动」这类断在半句的引导句）。正确做法见下条。
  - **正确做法：逐条读原文 + 显式白名单**（用户原话：「你能不能读取一节一节的内容自己根据文本语义判断，而不是使用脚本」）。三步：① 脚本只负责**导出报告**（全部「段末带出处」候选段 + 前后各一段上下文，本书 163 条 ≈ 12 万字，`scripts/check_quote_paragraphs.py` 可扩展成这个用途）；② **逐条读**，判「整段都是马克思原文」还是「哈维自己的分析」；③ 把判定为引文的**段首 15–20 字指纹**写成 `QUOTE_PARAS` 常量，build 只按清单标记，**不做任何语义推断**。指纹比正则可审计、判错改一行；清单条目数 ≈ 引用块数 + 少量未命中（本书 78 条清单 → 71 块）。
  - **指纹匹配必须先把引号归一**：清单里写的是半角 `"`，正文是全角 `“”`/直角 `「」` → `norm_head()` 里统一替换成半角并 `lstrip('"')`，否则以引号开头的段落（`“社会需求”，也就是说…`）永远匹配不上（本书 5 条静默漏判，靠「未命中清单」才发现）。**build 后要打印「清单里哪几条 0 命中」**，命中数对不上就是漏判。
  - **逐章盲读 + 并行 subagent（第四轮，89 段清单 → 84 块，最省力也最准）**：把 book.md 按章拆成独立文件、**剥掉全部 `> ` 标记**、段落顺序编号 `[001]…`，一个 subagent 读一章只回 `{"quote":[段号…]}`；回来用段号映射回段首指纹。脚本 `scripts/blind_read_quotes.py split book.md read/` + `merge answers.json read/`。三条硬规则：
    - **必须盲读（去掉已有 `>` 标记）**：带着标记去读，模型只会核对已有标记——第一批 8 章（含标记版）报出 0 处漏判、1 处误判，全是照抄旧结论；剥标记重派后同一批章补出 20 余段。**这是本环节最容易白跑的一步。**
    - 一个 subagent 只读一章（3–4 万字），16 章分两批各 10/6 个并行，单批 2–3 分钟。
    - 提示词里写死四条排除（作者分析段／句中夹引语／引导句收尾／编号列表属作者分点）和一条并入（一条引文被拆两段 → 两段都算），并要求只输出 JSON。
  - **判读清单落地后必须删掉「自动扩展」规则**：build 里若还留着「前一段是引文且未结句 → 后一段并入引用块」，它会覆盖人工清单、把作者段落吞进去（本轮第6章「资本积累的步伐与工资率仿佛是反向变动的……」就是这样被吞的；删掉这条后多段块从 14 降到 5）。**清单是唯一真相源，不要留任何语义启发式与它并存。**
  - **TAIL_MOVE 的匹配方向极易写反**：判定要查**引文段**（`items[i+1]`）的段首，不是前段（`items[i]`）的段首；写成前段时整张表静默失效（本轮 5 条规则一条没生效，靠「引用块前一段是否结句」检查才发现）。
  - **移动文字会让指纹失配**：TAIL_MOVE 把「但是」「抽象劳动」「我们不应该」移回引文开头后，段首已与清单不同 → `is_quote_para` 要先按 `LEAD_STRIP = ('但是','所以','因此',…,'“这里','金融资本')` 剥前缀再比对，否则这几段会从引用块里掉出去。
  - **两个必做的收尾校验**：① 把每个 blockquote 按 `>` 空行拆成逻辑段，逐段比对清单指纹，**清单项 0 命中就报出来**（本轮 89 条最终全命中；中途漏 1 条是「金融资本」被留在引导句末尾）；② 扫「引用块前一段是否以 `：`/`。` 结句」，非结句且不是标题/公式/`---` 的就是引文头残留（本轮 13 处里 9 处是标题公式、4 处是正常引导语）。多段块数要单独统计并与人工判读出的跨段引文数对上（本轮 5 个）。
  - **块数 ≠ 清单数，别拿块数对清单**：本轮 89 条清单落在 **84 个 blockquote** 里（5 个多段块各含 2 段）。核对时必须把每个 blockquote 按 `\n>` 拆成逻辑段再比，否则会以为漏了 5 条、去改本来正确的分块。
  - **判「这一段引文是否已结束」不能用单条括号正则**：`[（(][^（）()]{0,100}?页[^（）()]{0,30}[）)]\s*$` 在两种常见形态下静默失配——① 段末还有脚注锚点 `[^fC186-①]`（正则要求 `）` 紧贴行尾）；② 出处用方括号 `[《资本论》第1卷，第52页]`。改用函数：取末 70 字，`re.search(r'第\s*[\d一二三四五六七八九十、，—\-]+\s*(?:页|章)', tail)` 命中且 `rstrip('。．. ').endswith(('）',']','】'))` 才算结束。写宽了会把「段末带出处的作者分析段」误判为引文结束，写窄了两条独立引文粘成一块。
  - **TAIL_MOVE 的 `a`（段首指纹）必须是「移动前」的段首**：把引文头（「这里」「金融资本」）从引导句末尾移回引文开头后，引文段段首就变成「“这里从事农耕…」。若 `a` 按移动后的样子写成 `'这里从事农耕的大量殖民者'`，规则永远不命中且**不报错**（本轮为此白跑两轮：先写成移动后形式、再改回移动前形式才生效）。同理 `is_quote_para` 必须用 `LEAD_STRIP` 剥掉移回来的碎片再比指纹。
  - **另有一类段级缺陷必须靠人读才发现，正则修不了**：① 一句话被 OCR 拆成相邻两段（`…劳动的特殊技巧越来越成为某种……` + `无差别的东西，而劳动…`）→ 拼回；② 一段里混着「引文 + 作者评论 + 下一条引文的引导句」（第13章「…细致微妙的差别。马克思说："这里"」）→ 在评论起点切开，并把「"这里」移回下一条引文开头；③ 引文开头被落在作者引导句末尾（第10章「…（列宁也赞同这一点）：金融资本」）→ 把「金融资本」移回引文首。三处都用 `JOIN_PAIRS` / `SPLIT_AT` / `TAIL_MOVE` 三张显式表实现，条目以 `(段首指纹, 目标)` 定位。
  - **极短首段（<20 字）不加段间空行**：`“这里”` 后面直接接正文的，加空行会渲染成两段，改为直接拼接。
- **blockquote 必须配 CSS**，否则多数阅读器只缩进一丁点：`blockquote { margin: 1em 1.8em; font-size: 0.95em; } blockquote p { text-indent: 0; }`。
- 交付说明里要写明「识别口径 + 排除了哪两类 + 各自多少处 + 引用块总数与其中多段块数」——用户会核这一条（他会追问「有没有识别错」「是不是多段的」）。
  - 双归属 → **M9**（交付清单与缺口列法在 M9）

> 本文件含两部分：**M6**（学术专著引文段落判定，案例哈维《资本的限度》）与 **M13**（军事档案「文件引文」转 `<blockquote>`，案例《巴巴罗萨脱轨》）。按书的类型只读对应部分。

# M13 文件引文转 blockquote（整节人工判定 + 精确定位）

适用：军事史/档案类书籍，正文里成段引用命令、训令、电报、作战摘要、日记、回忆录，要求用引用格式（EPUB 的 `<blockquote>`）。

## 判定：不能靠规则，要按小节通读

1. 从当前 `build/book.md` 按 `<h1>` 切分（含章末注释区没关系，注释条目不会被误判成引文）。每块控制在 1–2.4 万字，约 23 块。
2. 派 subagent，一块一个，要求**通读全文**（禁止只检索关键词/抽样），输出：
   ```json
   {"spans":[{"start":"引文第一段开头20字（逐字照抄）","end":"引文最后一段结尾20字（逐字照抄）","why":"是什么文件、如何引出"}]}
   ```
3. 判定依据（写进任务描述）：编号条目（`1./2./（a）`）、`·★☆` 分项、地点+时间+兵力、`我命令／我要求／必须／报告`、末尾署名或日期行；**语气是否从“作者在讲”变成“文件在写”**。不标作者概括、行内引号短句、表格插图标记；`〔表格，略〕〔插图，略〕` 夹在中间不打断引文。
4. **必须强调“引文不一定由冒号引出”**：常见 `……他写道。`、`报告称。` 之后，或直接接在小标题后、甚至无引导语。先按“冒号”口径跑一遍，再用“不限冒号”重读同一批章节，两次结果取并集——第二遍会补出“致××同志：”“·7月25日21点——…”这类小标题式引文。
5. 边界判据：引文从“文件第一句”起，到“作者重新开始叙述”止（`他说`、`随后`、`次日`、`实际上`、新小节标题）。

## 定位：写脚本，别手工数段落

块列表必须包含 `<p>` **和** `<div class="sub">`／`<div class="cap">`——文件体小标题常常就是 `div.sub`（如 `致卢金同志：`、`·7月25日21点——第20集团军下达的命令`）。

- 索引：把每块标签剥掉、空白去掉，拼成一条 `flat` 字符串，同时记 `fstart/fend`（每块的起止下标）与 `owner`（每个字符属于哪块）。
- 起点匹配：**最长前缀优先**（60→44→32→24→18 字），命中多个候选时，逐个算终点、取跨度最小的那个。否则 `· 总体情况——` 这种高频开头会错配到几十段之后。
- 终点匹配：只在 `i0` 之后的块里找，先要求“命中位置离块尾 ≤60 字”严格通过，再放宽到块内任意位置（引文可能在段落中间结束，后面同段接作者叙述）。

## 切段：引文起止落在段落中间时必须真的切

`……（参见地图9.4）：` 同一段里就跟着文件正文，不能整段进引用块。做法：

1. 纯文本下标 → HTML 下标的映射函数，**只在元素深度为 0 处切**。不判深度就会切进 `<sup><a class="enref" id="…">3</a></sup>` 内部，产出 `<a …></p></blockquote><p>3</a></sup>` 这种非法 HTML（epubcheck 报 RSC-012、id 丢失）。
2. 切开后左半留在正文、右半进引用块（起点）；终点反之。
3. 切完若右半只剩脚注号（纯数字），不要切，整块留在引文内。
4. 引文末尾的脚注号若已被切到下一段开头，用正则回吸：`</blockquote>\n<p>(<sup><a class="enref\|tnref"[^>]*>[^<]*</a></sup>)([^<])` → 把 `<sup>` 移到 `</blockquote>` 之前。

## 整段漏引的扫查（比边界复核更容易漏）

边界复核只能改已有块，**整份文件没标**要靠机械扫：

1. 标出所有 `<blockquote>` 的字符区间，给全文（含块列表）打上 in/out 掩码；
2. 找**连续 ≥2 个文档体块**（以 `·`/`★`/`☆` 开头，或是形如“7月20日20点——第XX集团军作战报告”的 `div.sub`）；
3. 保留“前一块以 `：` 结尾 / 前一块是文件抬头”的段，再看这些块是否还有 out 的（部分未包也算）；
4. 排除附录（`附录X` 章里的 ★/☆ 是作者自己的编成表，不是引文）。

一本书里这种漏通常 3—5 处，且都是整份作战摘要/命令，字数很大，漏了很显眼。

## 必须做的第二追：边界复核（首轮判定会漏包）

subagent 第一轮往往把引文止在“看得见的最后一条编号”，而文件真正的结语段还在后面（例如霍缅科报告的第 6 条之后还有一段“…经受了严重损失”）。第一轮也会反过来多吃：把下一份文件的开头半个摘要包进来。

复核做法：
1. 从最终 md 导出每章锚点清单（序号、字数、头 30 字、尾 30 字）到 `qs/chk_第X章.txt`；
2. 按章分派（4 个 subagent，每 3 章），要求逐条比对**引用块前后紧邻的段落**，只报两类：尾段之后仍属文件（编号条目、结论句、署名、发送注记）、首段之前仍属文件（受文者、抬头、命令导语）；
3. 同时要求排除“作者恢复叙述”的干扰项：“他说”“随后”“次日”“实际上”“值得注意的是”。
真实命中率约 3%（228 处报 7—8 处），但不做这一追就会持续被读者抓出来。

常见还需额外处理的粘连（源数据跨页合并造成，一段里既有文件尾又有叙述开头）：
`<p>（注）——“……（签名）××中校。”<sup>…</sup>从德方记录中可以……”` → 在 sup 后切开：注记留在引文内、叙述另起一段并移到 `</blockquote>` 外。

## 开头漏、尾巴漏（两级收尾）

subagent 报的 start 往往只从“文件第一句”算起，于是文件自己的抬头被落在引用块外：
`我命令：`、`司令员命令：`、`致斯大林同志`、`抄送沙波什尼科夫同志`、`7月20日20点——第16集团军作战报告`、`8月10日——预备队方面军司令员朱可夫`。

做法：凡 `<div class="sub">…</div>` 紧跟 `<blockquote>`（中间只有空白）→ 整行移进引文开头（`<blockquote>\n<div class="sub">…</div>`），**迭代到不再变化**（受文者行会一串两个，一轮只能移一个）。
做完复查：`<div class="sub">…</div>\s*<blockquote>` 的匹配数必须为 0。

反向同理：引文末尾的落款（`朱可夫`、`铁木辛哥，索科洛夫斯基`、`卢金、洛巴切夫`、`代表总统帅部大本营`、`总参谋长：B.沙波什尼科夫`）也要并回引文。

## 脚注号与署名行会溢出引文（必做收尾）

引文末尾的章末注释号、文件落款，常被切到引用块外面，表现为：孤零零一个数字段、“朱可夫 75”这种署名行带号。三追正则搞定（在拼装后的 md 上迭代到不变）：

1. 裸 `<sup>` 紧跟在 `</p>` 之后、`</blockquote>` 之前 → 移进 `</p>` 里；
2. `<p>…</p>\s*<p><sup>…</sup></p>` → 把 sup 并回上一段末尾（否则 pandoc 会把裸 sup 包成独立段落，渲染成一个数字行）；
3. `</blockquote>\s*<p>短行</p>`：短行（≤26 字、无句末标点）命中人名/职务白名单（朱可夫、铁木辛哥、沙波什尼科夫、索科洛夫斯基、卢金、洛巴切夫、斯大林、代表总统帅部大本营…）→ 整段移入引文。

## 三级小标题：`div.sub` 里混着两种东西

`div.sub` 既装文件抬头（“致卢金同志：”“7月25日21点——第20集团军下达的命令”），也装作者自拟的小节题（“计划和现实”“德国人的战略”“第二阶段，8月18日—21日”）。只标了前者，读者会觉得“第三级小标题没标出来”。

判定（在 `<blockquote>` 之外才处理）：
- 不转 h3：以 `·★☆■▲` 开头；以 `致|抄送|发给|我命令|我要求|为此|代表|司令员|最高统帅|总参谋长` 开头；含 `——`；`^\d+[.、]` 开头的文书编号条；`^YEAR年.*(摘要|报告|命令|训令|战斗令|日志)` 的文件抬头。
- 转 h3：其余短标题（≤34 字、无句末句号），包括裸日期（`8月17日`）、`第X阶段，…`、附录序列表分组名、参考文献子目。
- 还要删掉与所在章 `<h1>` 重名的空 `div.sub`（OCR 把章题又识别了一遍，前言的“总序/序/前言/缩略语列表/参考文献”各有 5 处）。
- pandoc `--toc-depth=3`，CSS 补 `h3`；目录条目会从 ~97 涨到 ~139。

## 自检（必做）

- **纯文字字数差**：`strip_tags(book_q.md)` 与 `book.md` 的字符数之差应等于新增换行数，`Counter` 差集里只允许出现 `\n`。曾因 `poff==0` 分支漏写 `st_html = bi["h"]` 整段吞掉引文首段，就是这个检查抓出来的。
- id 数量守恒：`id="enref` / `id="tnref` 两边数量必须相等（重复=切段把同一 id 印了两份）。
- epubcheck 0 error；再抽 5 处引用块，打印“前文尾 / 引文头 / 引文尾 / 后文头”，确认起点是文件第一句、终点回到叙述。
- 交付时附 `引文清单.txt`（序号｜章｜字数｜首尾），用户挑错时按编号定位。
