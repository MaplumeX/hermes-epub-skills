# M9 校验口径与交付

> **什么时候读**：每轮 build 之后，以及交付前。**校验全绿不等于渲染正确，本篇专治这一类。**
>
> **相关脚本**：`scripts/validate_epub.py`、`scripts/check_loss_blocks.py`、`scripts/check_end_matter_and_loss.py`、`scripts/check_tables_pandoc.py`

> 本篇内容自 SKILL.md 拆出，条目逐字保留（含实测数字与原节出处）。

## 三道校验口径（每次 build 后按序跑）

1. **保真度比值** —— `源 layout 所有 span 的非空白字符数` vs `book.md 去标记后的非空白字符数`，比值应 ≈1。
   - `>1.01` 先查**重复渲染**（图题既配给 fig 块又作为正文短行输出），`<0.97` 才查丢块
   - 两边必须用**同一个归一化函数**，否则会得到 0.66 / 0.89 这种假低值（白跑一轮）
   - 表格书要把 grid table 的 `+---+` 分隔线、`|`、`-` 从 md 侧剥掉，否则比值虚高（某案例 1.10）
2. **注释对齐** —— 正文标记集合 == 注释条目集合（逐章 int 比较）；数量对还要查**严格递增序列**与 **id 唯一性**
3. **成品校验** —— `scripts/validate_epub.py`（XML、内部链接、文件内锚点、重复 id、noteref↔backlink、MathML/表格计数、封面、nav）+ `epubcheck`
4. **抽读 xhtml** —— 解包抽 2–3 处表格 / 公式 / 引用块，肉眼确认渲染正确（第 3 步全绿也可能错）

## 来自「中译本学术专著（页脚圈码脚注 + MathML 公式 + HTML 表格 + 少量插…」

- **构建脚本改动用 write_file 写 patch 脚本再执行**：Hermes terminal 会把命令行里的 `&` 判成后台符并拒绝，`$` 会被 shell 展开，`sed … | python3` 触发安全审批——含正则/私有区字符的改动一律走 `.py` 文件

## 来自「中译本教科书·多分册（圈码页脚注按**章**连续编号 + 答案/术语表双栏 + 图组…」

- 案例：斯奈德、尼科尔森《微观经济理论：基本原理与扩展》第 11 版（北大社），references/micro-theory-11e-case.md
- **术语表**：字母标题（`^[A-Z]$`）→ `**A**` 加粗行，绝不能给 `##`（否则导航树里冒出二十几个字母）
- **交付文件名必须带版本号/时间戳**（`…-v4-10271511.epub`）：连续几轮都用同一个文件名时，用户在 Telegram 里点到的往往是更早那条消息的附件，会打开旧版并据此报「没修好 / 你是不是没检查公式」（本会话真实发生，白白争论一轮）。每次交付换新名 + 同时报 md5 与字节数；用户说「还是旧的」时先对 md5，不要先怀疑自己的构建。
- **保真度块级扫描必须先有显式 SKIP 清单**：本案例 201 条「源块文本在 book.md 里找不到」，绝大多数是主动跳过的封面/版权页 CIP/OCR 目录/献词页/重复的教学支持页。把 `SKIP = {(tag, pi)…}`、`FRONT`、`DEDICATION` 写成常量并在扫描时扣除，否则真丢块会被噪声淹没（本案例人工过前 30 条才确认全部是跳过页）

## 来自「陷阱」

- **修复必须进 build 脚本**：直接改 book.md 会被重新生成覆盖；用 fix_text() 统一处理已知缺陷
- **源头缺陷**：缺行/截断处加注记（〔此处原书缺一行〕），不猜测补全（用户要求忠实源数据）
- **验证**：脚注引用数 == 定义数、§ 连续无缺失、类型顺序（说明在附释前、附释N 递增）、无正文的 § 为 0

## 来自「整句丢失（OCR 扫描件页首/正文缺整句）」

- **现象**：§ 正文/说明缺整句，常见于页首（p170 页首缺 §88 说明第 5 条 "5. 转变的命题是：'存在是向着无的过渡…'" 整句，块直接从后半句"与之相对立的是…"开始）或 § 正文只剩残句（§81 正文只剩 "反规定的过渡。"，前面 "β) 辩证的环节是这些有限规定的固有的自身扬弃，以及它们向着" 整句丢失，且"相反"被截成"反"）
- **扫描模式**：① 用户阅读发现 ② 自动扫描——每个 § 的正文首段 <40 字符列为疑似残句，逐一对照德文原文区分**引导句**（§77 "但这两种立场也有区别："、§83 "逻辑学分为三个部分：" 是正常的，后续编号条目独立成段）vs **残句**（§81）
- **修复模式**：用户提供权威文本 + 英文版佐证（如 §88 英文版注 (5) "The maxim of Becoming, that Being is the passage into Nought..."）→ build.py 中按 `(页, y, 开头文本)` 三重匹配补前缀
- **⚠ 流构建依赖陷阱（§81 案例）**：文本在数据预处理阶段被替换后，流构建阶段（MAIN_STREAM）中所有依赖 `t.startswith('旧文本')` 的条件分支会**静默失效**——§81 的 skip 分支（"y=84 残句先跳过，待 § 标题插入后追加"）和追加分支都靠 startswith 匹配，替换后都不再命中，导致 β) 句排在 § 标题前（顺序错乱）。修复：**替换后流阶段的条件必须改为按 (pid, y) 坐标定位，不要依赖文本内容**
- **顺带统一格式**：修复时扫描同类格式——罗马数字编号条目缺空格（"II.本质论。" → "II. 本质论。"，全书 16 处罗马数字编号仅 2 处缺，正则 `re.sub(r'^([IVXLCDM]{1,4}\.)(?=[\u4e00-\u9fff])', r'\1 ', t)` 统一）

## 来自「中译本教科书·单册拆多文件（`title` 自带 level + 图题被拆散 + 书…」

- **多阶段改 pages.json 必须有 raw 备份 + 固定重建链**：`cp pages_raw.json pages.json && python3 merge_pages.py && python3 attach_captions.py && python3 build.py`。每次调参都从 raw 重跑，否则上一轮的合并/挂靠会叠加，越修越乱

## 来自「中译本学术专著·双注释体系（页脚圈码 + 章末「译注」数字） / 收尾两个「校验全绿…」

- **`validate_epub.py` + epubcheck 全绿 ≠ 渲染正确**：本书表8.1 的 `rowspan` 被 `html_table_to_grid` 展开后首列重复（「物质形式」出现两次），两项校验都不报错；只有 `unzip -p out.epub EPUB/text/chNNN.xhtml` 读实际 `<table>` 才发现。**收尾必抽 2–3 处表格 / 公式 / 引用块解包读 xhtml**，别只看校验输出。
