# M14 表格：表题加粗、不得切断正文

## 表题 vs 表注（先分清再给样式）

源数据的表标题和表注常被 OCR 搅在一起，落进同一个字段。渲染后要分两档：

- **表题**（`div.tcap`，加粗）：`表X.Y：标题`、以及短标签 `续表`、`德军`、`苏军`、`兵力`、`合计`。
  这些在原书是表头/续表标识，必须是加粗独立行。
- **表注**（`div.tnote`，小字灰）：`注：…`、`※资料来源：…`、编者/译者说明。不加粗。

经验：把 `tnote` 里 ≤4 字、不以 `注：`/`※` 开头的短串一律升为 `tcap`。一本书里“续表”常有 10+ 处，全被归进表注就会显得表题全都没加粗。

**只靠 CSS 不够**：不少阅读器（微信读书、掌阅、部分 Kindle）忽略出版方自定义样式，`div.tcap{font-weight:bold}` 不会生效，用户会说“没加粗”。表题文字必须再包一层 `<strong>`：
`<div class="tcap"><strong>表4.1：……</strong></div>`。交付前随手数一下 `tcap` 与 `含<strong>` 的数量是否相等。

## 表格不得劈开段落

典型的坏例：

```
<p>…布琼尼摩下第五个集团军是卢金中将实力虚弱的第16</p>
<div class="tcap">表2.1：…</div>
<div class="tblwrap"><table…></table></div>
<p>集团军，该部刚刚进入指定地域…</p>
```

句子被表劈成两半，读者会在表后接不上。修法：

1. 扫描所有表格单元，看**前一个 `<p>` 是否以终止标点结尾**
   （`[。！？：；…”』」）\)]$`）；不以则命中。
2. 拼接：`pA.inner + pB.inner` 合成一段（注意开头常是“集团军，……”、“军应前出到……”这种续词，直接拼接不加空格）。
3. 把 pA 与 pB 之间的**全部内容**（tcap/tnote/一个或多个 tblwrap，包括“续表”）整块挪到合成段之后：
   `new = before + merged_p + "\n\n" + q[pA.end():pB.start] + q[pB.end():]`
4. 迭代直到不再命中（挪完一个后后续位置会变）。

## 必做自检

- **字符量守恒**：`strip_tags(book_f) - strip_tags(book)` 只允许出现换行和少量空格；
  一旦看到“第 / 兵 / 师”这类字符减少，就是拼接时把表格内容丢了（第一版把两表之间的内容当垃圾删了，少了 1020 字）。
- 表数量不变（本书 59 张）；`tcap` 数量应从 22 涨到 45（含续表）。
- 图（`div.fig`）用同样方法扫一遍：本书 0 处切断。
- epubcheck 仍 0 error，`<table>` 不能被包进 `<p>`。
