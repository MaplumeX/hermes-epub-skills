# 用原扫描页读回被 OCR 丢掉的上标（实测记录）

案例：《火的考验：美国南北战争及重建南部》（layout.json 里尾注上标被整处删除 84 处）。
用户提供原扫描 PDF 后，上册 40 个缺号 → **补进 26 条**（第6/7/8 章 100% 链接），全书链接从 268 → 294/352。

## 为什么必须走图像
文本层路线三条全部不可靠（见 `ordeal-by-fire-case.md` 的「外部对照版」）：英文 4th/1st 版的文本层做
「年份+专名指纹」→ 0/1 条可靠；用已链接标记做序列插值 → 只有 8 个单调锚点。
结论：**只有中文扫描页图像能给出确定答案**（纸上印着上标数字）。

## 三段管线
```bash
SCAN_PDF=上册.pdf python3 scripts/read_marks_from_scan.py locate book.md pages.json out/
# 必须用 Hermes venv（系统 python3 没有 openai）
/usr/local/lib/hermes-agent/venv/bin/python scripts/read_marks_from_scan.py read out/     # 后台跑，30–40 min
python3 scripts/read_marks_from_scan.py apply book.md pages.json notes.json out/
```

## 实测有效的调用姿势
- **模型**：`agent.auxiliary_client.resolve_vision_provider_client()` 返回 (provider, client, model)。
  本机 auto 解析到 **主 provider 自身**（custom / axonhub / deepseek-v4-flash），不是 OpenRouter —— 即
  vision_analyze 用的就是我这条推理模型线。要换更强的 VL：`hermes config set auxiliary.vision.provider openrouter`
  + `auxiliary.vision.model <id>`（不动主模型）。
- **推理模型陷阱（最关键）**：`max_tokens=800/1200` 时 `finish_reason=length`、`content=None`，全部答案只写在
  `reasoning_content`。先读到 `content=None` 会误判成“接口坏了”。对策（照抄 `tools/vision_tools.py`）：
  `temperature=0.1`、`max_tokens=4000`、`resp = content or reasoning_content`，并对空内容重试一次。
- **prompt**：要求逐条输出 `上标数字 | 它前面紧邻的 6~12 个汉字（原样照抄）`；看不清写「看不清」；无上标不列。
- **图像**：`pdftoppm -r 250 -x/-y/-W/-H -png`（像素 = pt×250/72）切掉页眉页脚。文字页 **PNG 148 KB < JPEG 939 KB**，
  别转 JPEG。pdftoppm **会在前缀后再拼页码**（`-png out/p023` → `out/p023-023.png`），脚本里 glob 取真实路径。
- **批量化**：84 页写成脚本一次跑（background=true + 每页即时落盘的 JSON 检查点），而不是 84 次 vision_analyze 工具调用。

## 三道闸 + 控制组（写入前的硬校验）
1. 号码必须在该章注释编号表内（否则是模型看错，如把 17 读成 18；实测拒绝 `5.18`——该章只有 16 条）；
2. 前文必须在该页文本中唯一命中，并加「只比汉字」回退（模型常漏抄原文里的数字，如把「工业品产量在1860年」抄成「业品产量在年」）；
3. 插入位置必须落在相邻两个已链接标记之间（保证章内顺序单调）。
- **控制组**：这些页上还有已链接的注号，模型读到的「号码+前文」若与正文已有位置一致即该页读得准。
  本案例 **66 条控制读数全部对上** → 支撑了 26 条插入的可信度。控制读数也写进报告，用户可自查。
- 实测：100 条候选读数 → 34 条缺号候选、26 条通过三闸写入、3 条因顺序不合法被拒、其余因前文不唯一被拒。

## 两个“静默失败”教训（各卡了好几轮）
- **`len(buf)` vs 累计字符数**：`bounds.append((len(buf), len(buf)+len(txt), ...))` 里 buf 是**字符串列表**，
  `len()` 返回元素个数（1、2、3…）而非字符偏移，于是所有“文本位置→页”反查都落不进任何页、全部返回 None。
  正确：显式 `total` 累加。
- **`\uXXXX` 正则经工具调用会被多转义一层**：写进文件后变成 raw string 里的 `\\uXXXX`，字符类语义改变，
  `norm()` **静默剥掉全部中文**（现象：报「前文在本页命中 0 次」，手动 `find` 同一串却命中）。
  稳妥写法：`''.join(c for c in s if c.isalnum())`（中文/英文/数字都是 alnum）。

## 判定用户发来的扫描件是上册还是下册（一次 vision 解决）
把两个候选 PDF 的同一页号渲染成左右拼接图（ffmpeg `[0:v]scale=700:-1,pad=...` + `drawtext=text='LEFT'`，
再 `hstack`），一次提问「左右分别是什么章节、页码」。本案例据此确认 部分1=上册(ch3)、部分2=下册(ch12)、部分3=附注。

## 下册与收尾期成果（同案例后续轮次）
- 下册 82 页同管线：98 条读数（**控制组 63 条全对**）→ 27 条写入 → 全书 325/352；350 dpi 重读 19 页再补 1 条 → 326。
- **400 dpi + 每页切上下两半**重读（`max_tokens` 拉到 8000，prompt 明写「不要解释、不要描述页面、不要写思考过程」）→ 再补 4 条 → 330。这一步治的是「整页被读成思考过程、`content` 为空」的老毛病。
- 双模型一致（下节）再补 2 条并更正 1 处 → 最终 **332/352（94%）**；第5/6/7/8/10/11/14/15/17 章 100%。
- 剩余 **20 条**：ch16 11 条最集中（该批页上标又小又密），另有 ch9 3、ch1/ch2/ch3/ch4/ch12/ch13 各 1。
  这 20 处两个模型要么都答「无」、要么互相矛盾，属扫描件上确实模糊 → **留空并写进缺口报告，不许猜**。

## 双模型一致（本案例最有效的一招）
- 本机 axonhub 有**原生多模态 `glm-5.3-flash`**（另有 `glm-5.3`）：用 `resolve_vision_provider_client()` 拿到的 client 直接 `model='glm-5.3-flash'` 传图即可（同一 base_url/密钥，不必改 config；模型 id 可用 `GET /v1/models` 确认）。
- 采纳条件：两模型对同一块**号码相同**且**前文 ≥6 字重叠**。一致读数里天然含控制组（可随时自检读数可信度）。
- **它抓出过真错**：第12章「……由一个有肠胃病的列兵所组成。”」早前单模型 250 dpi 读成 8 并已插入；双模型在 **500 dpi 紧裁该段**（bbox 取自 layout.json，±6pt）后一致读出 **3** → 更正锚点为 3、注8 退回待补。**难页不要靠单模型单次读数定案。**

## 插入前的新守卫（都拦下过错误）
1. **歧义**：同一注号出现 ≥2 个不同前文落点 → 跳过（ch16 注30 两个候选）。
2. **近邻锚点**：落点 ±80 字内已有 `enref-` 锚点 → 跳过（防重复插；ch12 注3 正是被这条拦下，进而触发上面那次紧裁终审）。
3. **句末标点**：前文之后必须紧跟 `。””！？…` 等（走标点循环后位置未前移＝句中）→ 跳过。第1章注3 曾被插进引号内部（"任何东西都可以用机器³制造。”"），正是这条要拦的形态。
4. 疑难处就地 **500 dpi 紧裁单块**问两个模型，一致才动手。
- **错插更正流程**：整段替换锚点编号（`enref-c12-8`→`enref-c12-3`）→ 扫附注区**删掉目标已不存在的 ↩** → 再跑补 ↩。

## 写回护栏（本会话的破坏性事故）
- 写 `book_full.md` 前 `assert len(body) > 100000`；每步跑完**打印正文长度 + 锚点数**并 `cp book_full.md book_full.stepN`。
- 事故现场：生成的 apply 脚本引用了已删除变量 → 中间文件被写成 **1 字节** → 重建出的 EPUB 只有 1548 字符（目录 1 条）。靠「EPUB 正文总字符数 / 锚点数」异常发现；恢复是从上一份已验证副本逐步重跑（268→294→298→326→330→332），每步核对锚点数，**不在坏文件上继续叠加**。
