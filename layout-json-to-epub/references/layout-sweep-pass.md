# 全书排版通读 + 机械修复（book.md 定稿后的最后一轮）

注释、引文、表格都做完了，交付前还有一轮：**派 subagent 逐章通读，只找排版问题**（段落误合/误拆、标题层级、图表位置、引文边界、串页残留），由主 agent 落成可复现规则再重建。巴巴罗萨脱轨 v11→v12 就是这一轮，16 个 agent 报回 ~70 条，机械部分全部自动修掉。

## 派活口径（用户对这块有明确要求）

- **一章一个 agent**，不要按页或按 XML 切；给它两样东西：带标签的 HTML 片段（`build/book_f.md` 按 `<h1>` 切）+ 同名纯文本。让它**先读 txt 理解行文，再对着 html 看结构**。
- **不要给「问题清单模板」**。用户原话：「不要问题清单模版，就阅读看整体行文有没有排版问题就行了，OCR 错别字不修」。给固定分类表，agent 会按表找、表外一律不报。
- 仍然固定两条禁则：**不报 OCR 错字、不提文笔/措辞**——否则回来一半是「这里可能印错了」，无法执行。
- 输出只要 `{"issues":[{"anchor":"逐字原文（全局唯一）","problem":"…","fix":"…"}]}`，主 agent 只执行、不采信它的 fix 文本。
- 归来必须**逐条核锚点**：`anchor` 在 html 里 count==1，否则打回。上一轮 10 个 agent 有 3 个给的是改写过的句子，直接定位不到。

## 实测问题分布（这类书可以照此预判）

一章 ~70 条里，八成集中在两类，都在插图：

1. **插图嵌在 blockquote 内部**（47 处）：地图夹在 `★`/`☆`/`·` 条目之间，把一份命令或作战摘要劈成两截。引文条目连续性比「图跟着引用段」重要 → **一律把 fig 移到引文之后**。
2. **插图劈开句子或隔断引出句**（30 处）：「铺天盖｜地的指责」「第9集团｜军第5军」「而是以第｜7装甲师」「虽｜然设法找到」。人工读才看得出，机械规则只能事后修。

其余零散：图注体例不一（缺 `▲`、半角冒号）、标题半角标点、表注排在表格之前、扫页残留章题粘在注释尾部、前置部分跨页拆段。

## 机械修复规则（可直接抄）

```python
# 1) 引文内插图移出：注意 </blockquote> 是 13 字符，不是 12
inner = q[st + len("<blockquote>"):en]
idx = en + len("</blockquote>")      # 写死 12 会在正文留下裸 '>'

# 2) 合并被图劈开的句子：必须保留 pA 与 fig 之间的内容，否则中间的图被吞
middle = q[a_end:s]
q = q[:pA.start()] + merged + "\n\n" + middle + "\n" + fig + "\n" + q[pB_end:]

# 3) 章节级批量改（去重、改标题）：用 re.sub + 函数，一次原子完成
#    千万不要在 re.finditer(q) 的结果上边遍历边拼 q —— 索引会失效，实测删掉 36 K 字 / 8 张表
q = re.sub(PAT, fix_fn, q)
```

- 图注统一：`^\s*(?:▲\s*)?地图\s*(\d+\.\d+)\s*[：:]\s*(.*)$` → `▲ 地图 {num}：{rest}`。**只改匹配得上的**，别用「凡是 cap 都重写」，会把含 `<sup>` 的图注内容搞丢。
- 表注在表前：`tnote … tblwrap` → 移到表后。**必须一次扫描、收集区间、从右往左套用**——用「改完再从头发 search」的 while 循环，同一条表注会在「续表」链上被反复搬 45 次（实际只有 14 条），把 14 万字符外的一张表拖到别处（实测表4.6 跑到附录表群里），而字符总数与图/表计数全都对得上，只有瞄关键词坐标才看得出。
- 扫页残留：`<p>第X章 / 书名…</p>` 整段删；`第\d+页。第X章` → `第\d+页。`；`第X章\s*<a class="bl">` → 保留回链。
- 附录重复标题：h1 之后紧跟同名的 h2/h3/`div.sub`（只少「附录X」前缀）→ 删后者。用单条 `re.sub` 带比较函数，不要在循环里改 q。

## 前置部分跨页拆段：必须限区域

「总序/序/前言」换页处会把一段切成两段（「而军人的真正的｜实验室则永远是军事历史。」）。判据：`pA` 去掉尾部脚注号后不以 `。！？：；…”』）` 结尾、`len>20`、`pB` 不以 `\d+\.` 或 `*` 开头。

**这个规则只能在 `缩略语列表</h1>` 之前生效**。全书跑一遍会出 473 条候选——参考文献的中英对照段、将领名单、落款都是天然「两段」。限定区域后正好 13 条，全部是真拆段。

## 索引安全：三条硬规则

1. **长度用 `len()`，不要数字面量**。`<blockquote>` 是 12、`</blockquote>` 是 13；写死 12 会在正文里留下 38 个裸 `>`。
2. **搬块只做一次扫描、从右往左套用**。在**原始串**上把所有命中区间算完 `(base, note_start, note_end, block_start, block_end)`，再 `reversed()` 逐个拼。每次重搜的 while 循环会让刚搬过的块再次命中，产生漂移。
3. **块结束位置用「第一个 `</table>` + 紧邻 `</div>`」判定，不要用 div 栈计深**。单元格里出现不配对的 `</div>` 时栈计深会越界到十几万字符之后，把中间整段吞掉；再加一道保险：区间内出现 `</blockquote>` 或 `<p>` 就跳过这条。

对应错误形态：**字符守恒、结构计数全过，但内容顺序错了**。所以在守恒校验外加一条「锚点坐标回归」：定稿前后各打印若干个唯一串（人名 `切尔诺拜`、表题 `表4.6：…`）的 `find()` 位置，位置漂移超过该块自身长度就是搬错了。

## 逐规则定位回归（哪条规则改坏的）

规则一多，「改坏了」很难二分。最省事：**每条规则跑完就把全文 dump 到 `build/_step_<规则名>.md`**，再打印锚点坐标 + 结构计数。实测前四条坐标纹丝不动，第五条（表注移动）跑完 `切尔诺拜` 从 240 998 跳到 99 332——一条命令锁定元凶，不用逐条注释重跑。

规则落地顺序：先装「只动标签」的规则（图/表搬位、图注、标题），后装「动文字」的（拆段合并），最后装「重编号」。文字类规则后进场，出错时 diff 最干净。

## 每一步都要做字符守恒校验

```python
t = lambda s: re.sub(r"<[^>]+>", "", s)
print(len(t(g)) - len(t(f)), (Counter(t(f)) - Counter(t(g))).most_common(5))
```

只允许出现换行、空格、全角标点差异。**同时数结构量**：`class="fig"`、`<blockquote>`、`<table class="tbl"`、`class="tcap"`、`class="en"`、`class="tn"` 前后必须一致（或增减有解释）。

上面的「裸 `>`」和「图被吞」两个 bug 都是靠这两个计数抓出来的：文字总量看起来只差几十字（换行），但 `>` 凭空多 38 个、`<img>` 少 1 个，一查就是 off-by-one 和丢块。

## 用户说「你来解决」的三类，其实都可机械做

第一版我把这三类归进「报而不改」，用户直接回「b 移出引文 c 重排 degh 你来解决」。经验：**规则可判定、可回滚，就别推给用户**。

- **b 整表夹在文件引文中间** → 把该 blockquote 在表处**拆成两块**：`<blockquote>前半</blockquote>` + 表（带 tcap/tnote）+ `<blockquote>后半</blockquote>`。引文条目不再被表切断，不动正文文字（引文块数 +1）。
- **c 同一章多条译注都编号 `①`** → 按注块文序每章重编 `①②③…`：同时改注区 `<span class="tnm">` 与正文 `<a class="tnref">` 的文字，**id/href 一律不动**，链接自然继续有效。96 条一次重排完。
- **d 译注回指指错/缺 id** → 按章算：注块 id 集合 减 被 `href` 引过的集合 = 孤儿；正文里无 `id` 的裸 `<a class="tnref" href="#…">` 按文序与孤儿一一配对（数量相等才动手），补 id、改 href。

顺便记一个验证坑：pandoc 会把 `href="#tn-c1-10"` 重写成 `href="ch005.xhtml#tn-c1-10"`，**检查链接不能搜 `href="#id"`**，要搜 id 是否同时出现在锚与被锚侧——我因此误判过一条其实已修好的回指。

## 规则作用域：一条附录规则改到全书

附录一的图注修复用了「`<p>` 数字编号 → capnum」这种宽正则，结果全书 18 个「1. 第16集团军…」正文条目也被改成图注样式，还多加了一个 `<div class="fig">`（图数 118→119，标签包不成对）。

规矩：**任何「某章专用」规则先切出章区间再跑**，改完必复点结构计数——`class="fig"` 多 1 不是样式问题，是树坏了。做不成就别做，报给用户比硬改安全。

## 报而不改（写在交付清单里，让用户定）

这几类动了就是改原文或改语义，只能报：

- 表格两半列数不一致（补 `colspan` 属重排结构）；
- 图版有图无注 / 一张图挂两个图注（要对着原图判断谁是谁；实测 8 张图 7 条注，一条注被切成两半粘在另一条后面）；
- 原书本就没有表号/表题（**不要擅自编「表3.1」**）；
- 参考文献中英条目混排、缺中译；
- 注号上标插进日期中间、同号重复。

交付时按「已修 / 报而未改」两栏写清，比强行全改安全——用户会挑，但不会因为你如实分栏而返工。
