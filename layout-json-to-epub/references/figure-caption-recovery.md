# 图题缺口：判定、六种错位形态与恢复方法

用户对「图没有题注」的容忍度极低，而且**会亲自核对**：本会话我报告「11 个图号因 OCR 粘连不可恢复」，用户一句「你能人工审查一下吗」，重查后发现真缺口 8 个、其中 18 处完全可恢复。
结论先写在这里：**在逐块穷举之前，不要下「源数据缺失」的结论。**

## 一、先做权威判定，别用「1..max 缺号」

```python
caps = {(章, 后缀, 图号) ...}   # 来自 fig 块的 cap
refs = {(章, 后缀, 图号) ...}   # 来自所有块正文里出现的「图N-M」
missing = refs - caps            # 真缺口
```

- 「1..max 缺号」会被**章末无编号装饰小图**（22×22 的分隔图标）、**编分隔页整页图**、**跨章同号**污染：本例按缺号法报 18 个，集合差只有 8 个。
- 反向也要查一次 `caps - refs`：本例为 0（说明没有 OCR 误挂到别的图号上）；非 0 就是题注张冠李戴。

## 二、四类字段必须全查（漏一类就会误报不可恢复）

1. `chart_caption` / `chart_footnote` / `image_caption` / `image_footnote` 子块
2. 同页 `preproc_blocks` 的 title / text（题注常整段跑成独立块）
3. `discarded_blocks`：`header` / `footer` / `page_footnote` / **`aside_text`**
   （`aside_text` 在本例是表题「表3-4…」「表7-8」和「资料来源：…」，很容易漏）
4. 把图块交给 `vision_analyze`：「图里是否印有以『图N-M』开头的图题？有就照抄，没有就答『无图题』」

四类全空 → 才是真丢，报告里必须给**印刷页码**（`page['pageno']`，不是 pages.json 索引）。

## 三、六种错位形态（全部可机械恢复）

| 形态 | 症状 | 恢复 |
|---|---|---|
| ① 题注挂到相邻 **table 块**的 cap | 表格 cap 里出现「图N-M …」（本例 图5A-1 / 图5A-3 / 图18-1） | 从 table.cap 摘出、`insert(0)` 到目标 fig.cap |
| ② 题注 + 图释粘在同一个 text 块 | 一个块里既有「图N-M 标题」又有整段说明（本例 图13-4 / 图18-8 / 图20-2 / 图29-7） | 按 `\n` 或语义锚点拆：前半 → cap，后半 → fnote |
| ③ 题注和图释都在 `fig.fnote` 里 | `cap` 为空、`fnote[0]` 以「图N-M」开头且很长（本例 图13-1） | 在「随着技术进步」这类锚点处切开 |
| ④ 丢了「图N-M」前缀，只剩标题行 | 首行就是「储蓄函数是消费函数的镜像」「2006 年用 PPP 计算可以改变各国经济的相对规模」（本例 图21-3 / 图26-1 / 图27-6） | 整段作 cap，图号从正文引用页推得 |
| ⑤ 图题被 OCR 判成 `title` 块 | 成品里该行变成 `####` 小标题，导航树里多出一条（本例 图28-6 / 图22-11） | 删 title 块，标题 + 紧随的图释合成 cap/fnote |
| ⑥ 题注被粘进**上一段正文中间** | 正文里突然出现「…要求更职位空缺率和失业率\n职位空缺率和失业率在整个经济周期内…」（本例 图29-7）；或 fig.cap 里放的是**上一页方框内容的续文**（图22-11，上页结尾正好断在「…在乘」） | 按 `\n` 或图号前缀切开：前段留正文、后段作 cap/fnote；续文则拼回上一页对应块 |

## 四、两处「只剩图释」的处理（不许编标题）

图20-3、图30-9、图29-9 的原书题注标题行整行丢失，只剩图释。做法：
- `cap` 只留「图N-M」（**不加猜的标题**）
- 图释 → `fnote`，渲染成斜体
- 交付说明里点名这几条「只有图释、标题行丢失」，不要假装完整

## 五、恢复后必跑的三条校验

1. `check_caps.py`：`refs - caps` 应为 0（或只剩真正丢失的那几条，且与报告一致）
2. 逐条 `grep '\*\*图N-M'` 确认是**加粗**题注（不是斜体、不是 `####`）
3. 成品里查 `<p><strong>图N-M …</strong></p>` 存在（pandoc 层校验，防 md 对了渲染错）

## 六、修复表要可审计

每条修复写成 `(形态, 图号+标题, pages.json 索引)` 三元组打印出来，并落一份 txt 报告给用户：
修复 N 条（附证据）＋ 无法恢复 M 条（附印刷页码）＋ 判定依据四类字段的检查结论。
用户看的是「你到底查了什么」，不是「你说修好了」。

# 七、题注/标题被判成「脚注」或「页眉」（用户会主动点出来的第二类缺陷）

用户原话：「可能有些图题被当脚注了」。这一问直接暴露了形态 ⑦–⑩ ——
前一轮我只查了 `chart_caption` 和同页 text/title，**没系统扫 `discarded_blocks`**，
于是把 18 处可恢复的报成「源数据缺失」。

## ⑦ 图题整条躺在 `page_footnote` 里

症状：`fig.cap` 空、同页正文里也没有以图号开头的块，但 `discarded_blocks` 里有一条
以「图N-M …」开头的长文本，**后面还跟着面板说明「（a）…」「（b）…」**。

本例：图9-3（p207）、图9-4（p211）——题注 + 两个面板说明 + 「资料来源：表9-3。」
一共 3 个 `page_footnote` 块，全被当脚注。

恢复：按图号挂到同页最近的 fig 块；`cap` 只留「图N-M 标题」；
面板说明（`^（[a-zA-Z]）\S`）和「资料来源：…」拆进 `fnote`。

```python
if CAP.match(t) and attach(page, n['text'], kind, n['y'], as_fnote=False): ...
if t.startswith('资料来源'): attach(..., as_fnote=True)
if re.match(r'^[（(]\s*[a-zA-Z]\s*[)）]\s*\S', t): attach(..., as_fnote=True)
```

## ⑧ 表题落在 `page_footnote` 里（7 条，比图题更常见）

本例：表16-1、19-2、19A-1、26-2、27-4、28-2、30-2 的题注都在页脚注块里。
另有 `table.cap` 里混进正文的情况：`表 4-1 说明了如何计算价格弹性。价格上升 20%…`
（以「表N-M」开头、很短，被当题注，其实是交叉引用）。

拆分判据：**第一句到第一个句号 ≤70 字**才算「题注标题 + 说明」；
否则整块是正文，不要挂。

## ⑨ 下一页的正文被甩到上一页的 `page_footnote`

本例第6章 p131：页脚注里躺着
`机技术的改进，在30年的时间里，使计算能力提高了超过1 000倍。…` 和
`我们要区分产品创新和工艺创新，前者指新的或改良的产品被推向市场；后者`，
而这两句正是 p132 开头「则指对已有产品采用新的或改良的生产加工技术…」的前半段。

**判定三条件**（缺一不可）：
1. 本页最后一个 text 块**不以终止标点结尾**
2. 候选块**以汉字开头**、`len>60`、含句号
3. 候选块的结尾能接上下页首块（`我们要区分…后者` + `则指…`）

恢复：把候选块按 y 顺序插到 `pages[i+1]['blocks'][0:0]`，不要留在本页。

## ⑩ 小节标题被判成 `header`

本例 15 条：「当今的混合经济」「生产函数」「平均固定成本和平均可变成本」「向后弯曲的供给曲线」
「信息经济学」「要素需求相互依赖」「投资的价格和租费」「国家间的不公平」「非经济目标」
「政府采购」「新古典模型的几何分析」「人力资源开发」「从恶性循环到良性循环」
「休谟的调整机制」「短期的菲利普斯曲线」——整节因此没有标题。

判定：`header` 块去空白后**精确等于** TOC 里某条小节名，且同页还没有同名 title。
恢复：按 y 插回 blocks 当 title。**不要用包含/相似匹配**——页眉本身就是节名，精确即可。

## ⑪ 扫一遍就能查全的体检脚本

```python
# 对每个 discarded 块分类，四类都要报出来
if CAP.match(t):            -> caption   （图题/表题）
if t.startswith('资料来源'): -> source
if norm(t) in SECS:         -> heading   （TOC 小节名精确命中）
if typ=='page_footnote' and len(t)>60 and '。' in t and not MARK.match(t): -> body?
```

`body?` 这一类必须再叠「本页正文末块未结束」才动手，否则会把真脚注搬进正文。

## 十二、两个配套的工程细节

- **`extract.py` 合并页脚注时必须保留 `y`/`x0`**：合并后只留 `{'text': ...}`，
  后面按 y 就近挂载题注时直接 `KeyError: 'y'`。写成 `{'text': t, 'y': n['y'], 'x0': n['x0']}`。
- **`check_caps.py` 要 cap + fnote 两边都数**：题注可能整条落在 `fig.fnote`
  （本例图30-10 的「图30-10 美国实际失业率与非加速通货膨胀的失业率…」），
  只数 `cap` 会把它报成缺号，然后你会去「修」一个本来没坏的东西。
