# 章末数字尾注：流式解析 + 缺口机械捞回（方法篇）

> 什么时候读：正文上标是 `^{N}`（每章 1 起）、注文集中在「注释」小节且混在 `ref_text`/`text` 两种块里；或诊断出「注文数 ≠ 正文上标数」，缺口成串出现。
> 与 M3（注释体系）、`references/missing-marks-recovery.md`（语义补位）配合读：本篇管**机械层**，语义层仍要人读注文。

## 1. 注文流式解析（先做这个，别写逐块解析）

逐块「以数字开头即新条目」的写法在本类书上必败：OCR 会把上一条续文并进同块、把交叉引用（`见注47.`）留在块中、把条目开头的序号整处读丢。实测某书第一章用逐块法得 notes 116 / marks 201（≈40% 错），换流式解析一次到位 207/207。

```python
def parse_notes(blocks):           # blocks: [(pk, text), ...] 按页顺序
    text, offs = '', []
    for pk, t in blocks:
        offs.append((len(text), pk)); text += t + '\n'
    starts, exp = [], 1
    for m in re.finditer(r'(?<![\d])(\d{1,3})\s*[.、．。]\s*', text):
        n = int(m.group(1))
        if n == exp:               # 只有「等于期望值」才算新条目
            starts.append((m.start(), m.end(), n)); exp += 1
    out = {}
    for i, (s, e, n) in enumerate(starts):
        end = starts[i + 1][0] if i + 1 < len(starts) else len(text)
        out[n] = (page_at(s, offs), text[e:end].strip())
    return out, exp - 1            # 第二返回值 = 解析到的最大号，必须 == 正文最大号
```

要点：

- **分条正则要含 `。` 与 `、`**（`1.` `6、` `40。` `5.2003年` 四种形态都真实存在），只写 `[.、．]` 会少一条、整章 1..N 全错位。
- **不要求序号前是标点**：OCR 常把序号读成正文（`…做了调整48.《全集》第46卷…`），要求前文标点会漏；用「严格等于期望值」这条约束即可，正文里的年份/页码自然被跳过。
- **交叉引用 `见注47.` 不会误切**：它的 47 ≠ 期望值。这正是不用逐块解析的第二个理由。
- **验收三条**：`len(entries) == max号`；正文序列严格 `1..N`；`set(marks) == set(notes)`。
- 跨 `text`/`ref_text` 两种块类型要一起收（只认 `ref_text` 会让整章少一半）。

## 1b. 期望值匹配的**失效面**与兜底（同一本书下册实测，必读）

「严格等于期望值」的前提是**该章注释编号真的 1..N 连续**。一旦某章本身有缺号（源数据整段没录某几条），`exp` 卡在缺号处，**后面全部条目被丢弃**：同书下册第九章只解析出 45 条（正文 278 个上标），而上册同一套代码 207/207、436/436 全对。

- **不要用容差救**：改成 `exp <= n <= exp+4` 后，正文里的年份/编制号会劫持序列——同书上册从 207 跌到 191、前言 10 跌到 5。容差把「真缺号」和「OCR 噪声」一起放进来。
- 兜底解析（缺号章用）：**块首带编号即开新条 + 无编号块并入上一条 + 同号只留第一次**。下册实测第八章 350、第九章 281（正文 278）、第十章 676（670）、第十一章 468（471）——接近但不精确，残差进缺口清单。
- **选型规则**：两种解析各跑一遍，比 `len(notes)` 与 `len(marks)`，取接近的那个；两者差得都远，说明根本是另一套编号（附录 `[N]` 每篇独立，见下）。
- **附录/副编常常是另一套编号**：章名写作 `附录 1 … ^{[1]}`、小节 `第 46 装甲军 ^{[5]}`、甚至裸 `[6]`，每篇自带「注释」节且从 `[1]` 重起。分条正则要同时吃两种形态：`^\s*(?:\[(\d{1,3})\]|(\d{1,3})\s*[.、．。])`，取号写 `int(m.group(1) or m.group(2))`（只写 `group(1)` 会 `int(None)` 直接崩）；注键用 `a1..a5` 与正文章号分开，否则锚点互撞。

## 2. 缺口修复的固定顺序

先分清两种缺口，**不要一上来就插同号**：

| 症状 | 真实原因 | 处理 |
|---|---|---|
| 注文有、正文无上标 | 上标被读成正文数字 / 方括号 / 整处丢 | 本篇 §3 机械捞回 → 剩下的才语义补位 |
| 正文有上标、注文无该条 | 条目被并进上一块、序号读丢 | §1 流式解析就能解决，不必改正文 |

顺序：`流式解析（§1）→ 块尾裸数字捞回（§3.1）→ 方括号变体（§3.2）→ 合体标记拆分（§3.3）→ 表内 `<eq>` 注号（§3.4）→ 语义补位 → 剩余进缺口清单`。

## 3. 四类「被读成正文」的上标

### 3.1 块尾裸数字（命中率最高）

症状：段落末尾直接跟数字，如「…完全崩溃了。7」「…可疑优势。”92」「…大幅增加。70」。
**必须带单调守卫**，否则会把日期/编制数误当注号：

```python
def fix_bare(pages, chapter_notes):
    for chap, missing in chapter_notes:        # missing = set(notes) - set(marks)
        last = 0
        for b in body_blocks(chap):            # 只走正文块，按文档顺序
            for m in MARK.finditer(b.text):    # 先吞掉已有标记
                last = max(last, int(m.group(1)))
            m = re.search(r'(\d{1,3})\s*$', b.text)
            if not m: continue
            n = int(m.group(1))
            cand = [x for x in missing if x > last]
            if cand and n == cand[0]:          # 必须恰是「下一个缺号」
                b.text = b.text[:m.start(1)] + '{{N:%d}}' % n + m.group(2)
                missing.remove(n); last = n
```

守卫三件套：① 数字在**段尾**（不在句中）；② 恰等于「大于上一标记的最小缺号」；③ 只改正文块，不碰注释区。实测某书 43 处缺口有 27 处靠这条捞回，0 误插。
**注意 `\d` 匹配 Unicode 上标**（`¹²³` 的 `isdigit()` 为 True），转 int 前先 `tok.isascii()`。

### 3.2 方括号数字 `[N]`

段落末尾出现 `[7]` `[1]` 这类方括号数字：全书扫 `\[\d{1,3}\]` 通常只有个位数命中，逐条对「该章缺号」即可——命中数与缺口位置吻合就是丢失的上标，直接替换成注号（替换而非并列，否则正文留下 `[7]` 残渣）。

### 3.3 合体标记 `^{N①}`

一个 caret 组里同时有注号和圈码（`^{82①}` = 注82 + 译者注①）。按 `re.fullmatch(r'\^\{(\d{1,3})\}')` 判型会把整串原样留下：正文露出 `^{82①}`、注 82 与注① 双双成孤儿。**caret 组要拆成序列**：

```python
def caret_sub(s):
    def rep(m):
        toks = re.findall(r'\d{1,3}|[①-⑳]', m.group(1))
        return ''.join(TOK(x) for x in toks) if toks else m.group(0)
    return re.sub(r'\^\{([^}]*)\}', rep, s)
```

### 3.4 表格里的 `<eq>^{N}</eq>`

表题、表行、表注里的 `<eq>^{N}</eq>` 是注号（不是圈码——该页页脚没有这个圈码才可判注号，见 M3 四闸）。表题若走 `esc()` 输出，标记被转义成文字；表格必须与正文共用一个 `render_text()` 通道，否则「注文有、正文无落点」且不报错。

## 4. 建链层的三个静默 bug

- **`id` 存在性检查写成子串包含会假通过**：`if ('fnref-%s-%s' % (pk, i)) in md` 命中的是**回链自己的 href**，19 条死链原样留下。改查 `'id="fnref-%s-%s"'`。
- **回链必须带 `epub:type="backlink"`**：`validate_epub.py` 按 `epub:type` 统计，缺属性会报 `noteref 1594 / backlink 0`，看着像「数量不等」，其实 1:1 全对。删/改回链一律用正则匹配整个 `<a …>↩︎</a>`（属性多了以后字符串 replace 静默不命中）。
- **标题里的注号要走正文渲染通道**：`title` 块形如「德军的飞机损失 ^{209}」，h2 若 `esc(strip_marks(t))` 输出，该注既无落点也不进孤儿清单，成品「注文有、无锚点」。`<a><sup>` 放进 `<h2>` 合法。
- 同类：**圈码只写在 `inline_equation` span 里**（内容就是一个 `①`）时，只在 `text` span 做裸圈码归一化会漏，症状同上（译注有注文、正文无 `fnref`、回链死）。
- **回链要按「有没有落点」生成，不能按「有没有注文」**：`emit_notes` 若用「该号在注文表里」决定加 ↩，遇上「注文齐、正文没落点」的章（下册新增 111 条）就会产出成片 `ERROR(RSC-012): Fragment identifier is not defined`，而 `validate_epub.py` 仍报「无效 0」（它查的是另一侧）。修法：build 末尾统一后处理，`if 'id="enref-%s-%s"' not in text` → 正则剔掉回链并标「〔正文未印对应标记〕」；`div.en` 与 `div.fn` 两类都要跑。

## 5. 交付口径

- 补出来的每一处都要能复核：说明里写「章 + 注号 + 锚句末 20 字」，并标明是机械捞回还是语义补位。
- 该章注文在下册/另一文件时，上标渲染成 `<sup class="orphan">N</sup>`（不带链接、不建死链），说明里单列；**不要为了「序列全绿」在附近另插同号**。
