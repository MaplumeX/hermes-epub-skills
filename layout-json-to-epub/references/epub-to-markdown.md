# EPUB → 分章 Markdown（反解方向）

反向管线：用户发来一本已经成型的 EPUB，要求「还原成原 md、一章一文件」并加排版约定（图注引用块、例题/定义用分隔线）。与主线的方向相反，但判定口径一致。

## 开查顺序

1. **第一步不是解析 EPUB，是找原工作区**：这类书基本都走过 layout.json → book.md → pandoc EPUB，原始 md 往往还在盘上。**只在当前目录找不够**——实测同一本书有两个工作区并存（`/root/bookwork/` 是 00:53 的旧版，`/root/micro11_redo/` 是 18:11 的修复版）。先 `find /root -maxdepth 2 -type d | grep -iE '书名关键词|book|拼音'`，把候选列全。用户会直接问「你找找原工作区」——找到之后再动手解析。
2. **哪一版 `book.md` 与手上 EPUB 同源，用字符比出来**：按 `#`/`##` 切章，逐章比「剥掉公式后的 CJK 多重集」，差异 0 即同一版；再核图题数、例题数、定义数。实测两版差 4 章约 5.7 K 汉字：旧版第 4 章「推荐阅读材料」整段是第 1 章的文献（backmatter 状态机没复位）、第 1 章缺 Boland 条目、图 2.4 仍是「〔原书插图…此处缺图〕」占位。
3. **找到同源 `book.md` 就直接用它**：原生 LaTeX、原生 `[^c5-1]` 脚注号、真实图片文件名，都比从 EPUB 反解干净，也省掉 namespace / footnote-back / 脚注公式那一串坑。反解只在找不到原稿时做；此时才适用「以 EPUB 为准，旧 book.md 只用来交叉核对公式写法」。
4. 数结构：`for f in text/*.xhtml` 打印 `len(s)`、`<img>`、`<math>`、`<table>`、`footnote-ref`、`h1/h2` —— 一分钟就能定「几篇几章、公式量级、脚注体系、图表数量」。
5. 读 nav.xhtml 拿目录树（篇→章→节），确定 md 文件怎么切。

## 公式：不要反推，直接取注解

pandoc 出的 EPUB，每个 `<math>` 都带原文：

```python
<math display="block" …><semantics><mrow>…</mrow>
  <annotation encoding="application/x-tex">\n\\pi = p q - C (q)\\qquad\\text{(1.1)}\n</annotation>
</semantics></math>
```

取 `annotation[@encoding="application/x-tex"]` 的 text、strip 换行，就是原始 LaTeX——**保真度 100%，不需要 texmath 反推 MathML**。`display="block"` → `$$…$$`，否则 `$…$`。

## 解析代码的四个必踩点

1. **命名空间**：XHTML `{http://www.w3.org/1999/xhtml}`、MathML `{http://www.w3.org/1998/Math/MathML}`。用 `lname(e) = e.tag.rsplit('}',1)[-1]` 取本地名——直接 `tag.replace(NS,'')` 对 MathML 元素无效，`if tag=='math'` 永远不成立，公式会掉进 `itertext()` 变成「π=pq−C(q)(1.1) \pi = …」这种双份垃圾。
2. **`inline()` 顶部先拦 math**：`if lname(el)=='math': return '$'+tex+'$'`（block 返回空串），否则递归进 `<semantics>` 会把 annotation 的 TeX 当正文吐出来。
3. **脚注反链要跳过**：`<a class="footnote-back">↩︎</a>`，不跳过每条脚注结尾都挂一个残符。
4. **脚注里的行间公式必须改成行内**：脚注定义要单行，用一个 `flat()` 渲染器把 block math 也输出成 `$…$`。漏了这条，公式会整条消失（实测 10 条脚注、15 个公式，`$$` 总数比对能立刻发现）。

## 结构映射

- 章 `h2` / 节 `h3` / 小节 `h4`；篇页是独立 `h1` 小文件。按**文件内最小标题层级**归一（章=`#`、节=`##`、小节=`###`），这样篇页、章文件、答案区各自都从 `#` 起。
- 前置里「前言 + 第11版的新变化 + 配套内容 + 致谢」通常是 4 个 xhtml，合并成一个 `前言.md`。
- 文件命名 `NN-章节名.md`（两位数序号保排序），去掉 `\ / : * ? " < > |`。

## 特殊块（例题 / 定义 / 最优化原则）

用户要求：上下各一条 `---`，标题加粗。

- **例题的边界读原文定，不是「到下一个标题」**：本书 119 个例题，几乎都以「请回答:」或「问题:」收尾（后面可能跟 `1.` `2.` 小问和公式），再往下就是正文讨论。按「到下一个标题」划，会把整节讨论吞进例题框（实测 83 个例题受影响）。
- 定义块 = `**定义**` + 术语段（`**术语** 定义正文`）+ 紧跟的公式与续句（以 `的 / 式中 / 这里 / 其中 / 表示 / 即 …` 开头），之后的评述性段落留在框外。
- 相邻两个特殊块之间的「首尾两条 `---`」会被压成一条（既闭合又开启），所以**按 `---` 行数奇偶判断成对是错的**；正确探针是：每个特殊标题上方必须有一条 `---`，每个块往下扫到第一条 `---`/标题前必须闭合。

## 图注 ≠ 图题（用户明确纠正过一次）

- **图题**＝图片的编号与题目，md 里是整行加粗 `**图 3.3 在 x−y 坐标系中有无限条无差异曲线**`，**保持加粗，不要改成引用块**。
- **图注**＝图片下方那段解释文字（说明图中曲线/点/阴影/面板 a、b 在讲什么），用户要求写成 Markdown 引用块 `> …`。
- 上游 `build.py` 里两者来自不同字段，输出形态也不同：`cap` → `**…**`（或 `*…*` 面板标签），`note` → `*…*`（斜体）。所以**斜体段**里有一部分天然就是图注；但只有 30 余处有 `note`，多数图注是以**普通段落**跟在图题后面的，没有标记。
- 判定只能人工：导出候选（`![…]` + 可选图题之后的第一段及其后一段）连同上下文 → 逐条读 → 写成 `NNN Y/N` 清单 → 脚本按清单执行。实测 142 条候选里 126 条是图注、16 条是正文（正文那条接着上一个论点，比如「如果无差异曲线是凸的…」）。
- **别用规则代替判读**：按「紧跟图题就当图注」会把正文引出段也吞进引用块（本案例第 3 章「曲线 U₁ 表示所有能使个人得到相同效用的组合…」后面直接接 `**定义**`，那是正文）。
- **容器分支的坑**：例题/定义块若整段原样搬运，内部的图注就不会走判定 → 实测漏转 16 条（全在例题框里）。渲染必须收敛成一个 `render(i)` 逐块函数，容器只负责加 `---` 和标题；验收时数 `^> ` 行数是否等于清单里 Y 的条数。

## 图打断正文（本方向最常见的一类语义错误）

源 EPUB 里，图 + 图题 + 图注 会把一段话切成「前段（无句末标点）」+「后段（以『的 / 而 / 相对价格』这类续句开头）」。要求是「图片不切断原文」，做法：

- 探针：段落末尾无 `。！？` 且**紧接**一个纯图段落 → 候选；再往下跳过图题（`**图x.y …**`）与图注短段，看第一段正文是不是续句。
- 处理：两段合并，**图 + 图题 + 图注整体移到合并段之后**（图上移会让图跑到前文引用之外）。
- 面板标签 `*(a) …*`、以 `\qquad\text{(x.y)}` 结尾的公式块、带 `[^n]` 的完整句，全是假候选——过滤掉能少 80% 噪音。
- **判「源缺」前必须回查 OCR 页数据**：`book.md` 断在半句 ≠ 源缺。实测把第13章「…另一方面,在给定的预算约束下(直线 $C$)，」判成源缺写进说明，被用户当场否掉（「你没有审查章节原文吧？原文是被图片切断的」）——续文是**下一页的第一个正文块**「个人的需求是 $(x_1',y_1')$。结果……」：图13.4 + 图题 + 图注整个插在中间，build 的跨页合并接不上，于是在 book.md 里看起来就是断句。合并后读得通（「…在给定的预算约束下(直线 C)，个人的需求是 (x₁′,y₁′)。」）。
- 真正的源缺要在版面数据里核出来才算数：第14章 p420 最后一块就止于「…多元价格政策总会导致更多的」，p421 直接从图14.5 开始，图注与例14.5 之间**没有任何正文块** → 这才是缺字，列进说明、不补。
- 回查方法：`pages/pages_X.json` 每页只有 `blocks / notes / header`，`blocks[i]['txt']` 已是拼好的整段文本，判「这块在不在」看它就够；要看**原始 span**（常被 build 截断或合并）则读 `raw/*.json`，结构是 `pdf_info[i].preproc_blocks[j].blocks[k].lines[l].spans[m].content` —— 只遍历 `lines[l]['content']` 会静默拿到空串，误以为该页没内容（本会话在这上面空跑了两轮）。页序按下标对齐 `pages` 里的 `pi`，raw 里没有 `page_no`。
- 说明文件里这两类必须分开写：「被图切断、已合并」与「版面本身缺字」；用户会逐条核，混为一谈等于否认自己没读原文。

## 机械保真核对（每轮改完必跑）

正文字符级比对：逐章把源 XHTML 与 md 都「剥掉公式」后比 CJK 字符多重集。

- 源侧：递归遍历，遇到 `math` 子树**整棵跳过**；md 侧：先删 `$$…$$` 再删 `$…$`。
- **两侧必须用同一口径**。只剥一侧时，`\text{中文}` 会造成「源有 2 个『和』、md 没有」这类假警报（第一版就据此误报 4 章丢字）。
- 真差异只剩三类，逐条查证即可：`\text{…}` 里的中文、OCR 网格表把行标题每行重复（去重后差十几个字）、md 侧把一处行间公式改成行内。
- 公式侧另做一次**序列比对**：按文档顺序取源 annotation 与 md 的 `$$`/`$` 内容，归一空白后 difflib；差异只能是「拆块/合块」，出现整条缺失才是真丢。

## 表格

收益矩阵/博弈矩阵这类表，源 HTML 常把行标题（`参与人1(妻子)`、`年轻人1`、`嫌疑人1`）在每一行重复一遍（OCR 网格效应）。md 里应去重成「表头一行 + 行列」，否则每张表都长得像三行同名列。

## 并行审读：批量大小与超时

- **subagent 单次 600 秒硬超时**，超时不返回 summary，但**已经改的文件落在盘上**——不能当成「没做」，也不能采信「已完成」的自述，一律自己复核（重跑字符比对 + 读 diff）。
- 实测吞吐：一个 agent 8–16 个小文件（≈20–40 K 字）能跑完；一整个「第1篇 + 第2章」（第2章 90 K 字、1131 个公式）就超时。**按篇幅切，不按篇切**：3–5 个文件或 ~5 万字符以内一批。
- 派活时写死三条：只改分配到的 md；临时脚本一律写 `/tmp/<task>/`（实测有 agent 往项目目录写 `check.py` 覆盖了旧管线文件）；语义判断必须读源 XHTML 上下文，禁止正则批量替换。
- 收工核对顺序：字符级保真 → 公式/图/表/标题计数 → 脚注 refs==defs → 特殊块闭合 → 抽读 2–3 章。

## 从加工后的 md 重新出 EPUB

```bash
pandoc 书名.md -o 书名.epub --mathml --toc --toc-depth=3 --epub-chapter-level=2 \
  --css=style.css --resource-path=. \
  --metadata title="…" --metadata author="…" --metadata lang=zh-CN --metadata publisher="…"
```

- 图片按 `![](images/<hash>.jpg)` 引用，`--resource-path` 指到 md 所在目录，pandoc 会把 199 张图全部内嵌。
- 验收四条：`grep -c 'Could not convert TeX math'` 必须 0；解包数 `text/*.xhtml`（≈54）、`media/`（199）、`<blockquote`（=图注数）、`<math`（=源公式数）。
- `--metadata` 全中文时先 `> /tmp/pan.log 2>&1` 再看尾部，别用 `| head` 截断——报错在最后几行。
- 生成后**抽读一个 xhtml** 确认渲染顺序：`<p><img></p>` → `<p><strong>图 x.y …</strong></p>` → `<blockquote>`（图注）→ 正文。这一步能立刻看出图注有没有挂错位置。

## 交付

`md/` 下放 `README.md`（带锚点的章节目录 + 格式约定 + 保真核对表）与 `说明.txt`（做法、保真数字、审读改动、**源数据缺陷清单**）。打包用 `python zipfile`（环境里不一定有 `zip` 命令），同时留一份到 `/tmp/` 供 Telegram 下载。
